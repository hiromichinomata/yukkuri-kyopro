## 6.1 高度な DP

**霊夢**: [05.md](05.md) までで DP はたくさんやった。黄色では何が増えるの？

**魔理沙**: **遷移が線形** なら **行列のべき乗**、**Convex Hull Trick（CHT）** で DP を高速化するパターンが増える。黄色では「DP の式を立てたあと、計算が重い」ときに **定数倍を log に落とす** 発想が増える。

**霊夢**: 線形漸化って、前の項の線形結合で次が決まるやつ？

**魔理沙**: その通り。フィボナッチや、タイルの敷き詰め数などが典型だ。ステップ数 n が 10^18 級だと、ループ DP は無理。**状態を k 個に圧縮して行列にする** と、O(k³ log n) で済む。

### 行列のべき乗（線形漸化）

`dp[k] = sum(c[j] * dp[k-j])` のような式は、状態をベクトルにして **遷移行列 T** を作り、`T^n` で k ステップ進める。

#### イメージ / 手順

1. 直近 k 個の `dp` を成分にした列ベクトル **v** を用意する  
2. 1 ステップ進める行列 **T** を係数から組み立てる（例: フィボなら 2×2）  
3. 答えは **v の n ステップ後** → `T^n × v` の必要成分  
4. `mat_pow(T, n)` は **二分累乗**（[02.md](02.md) の累乗と同型）

#### いつ使うか

| キーワード | 候補 |
|------------|------|
| 第 n 項、n ステップ後、10^18 回遷移 | 行列のべき乗 |
| 線形漸化、前 k 項の和で次 | 同上 |
| タイル・経路数が指数級の n | 状態次元を小さく保てるか確認 |
| 遷移が min/max で非線形 | CHT / 別 DP（下記） |

#### 計算量

| 処理 | 目安 |
|------|------|
| 行列 1 回の積 | O(k³)（k = 状態次元） |
| n ステップ | O(k³ log n) |
| フィボナッチ（k=2） | O(log n) |

#### つまずき

- **初期状態と n の対応**: `T^n` を `n-1` 回か `n` 回か、0 項の定義でズレやすい  
- **mod の位置**: 積のたびに `% mod`（オーバーフロー対策）  
- **状態次元 k**: k が大きいと k³ が重い。問題ごとに k を最小化する  
- **非線形遷移** を無理に行列化しない（min/max DP は CHT 側）

→ [solutions/python/06/matrix_pow/](../solutions/python/06/matrix_pow/) / [solutions/go/06/matrix_pow/](../solutions/go/06/matrix_pow/)

```python
def mat_mul(A, B, mod):
    n, m, p = len(A), len(B), len(B[0])
    C = [[0] * p for _ in range(n)]
    for i in range(n):
        for k in range(m):
            if A[i][k] == 0:
                continue
            for j in range(p):
                C[i][j] = (C[i][j] + A[i][k] * B[k][j]) % mod
    return C

def mat_pow(M, e, mod):
    n = len(M)
    res = [[1 if i == j else 0 for j in range(n)] for i in range(n)]
    while e:
        if e & 1:
            res = mat_mul(res, M, mod)
        M = mat_mul(M, M, mod)
        e >>= 1
    return res
```

```go
const mod = 1_000_000_007

func matMul(A, B [][]int) [][]int {
	n, m, p := len(A), len(B), len(B[0])
	C := make([][]int, n)
	for i := range C {
		C[i] = make([]int, p)
	}
	for i := 0; i < n; i++ {
		for k := 0; k < m; k++ {
			if A[i][k] == 0 {
				continue
			}
			for j := 0; j < p; j++ {
				C[i][j] = (C[i][j] + A[i][k]*B[k][j]) % mod
			}
		}
	}
	return C
}

func matPow(M [][]int, e int) [][]int {
	n := len(M)
	res := make([][]int, n)
	for i := 0; i < n; i++ {
		res[i] = make([]int, n)
		res[i][i] = 1
	}
	for e > 0 {
		if e&1 == 1 {
			res = matMul(res, M)
		}
		M = matMul(M, M)
		e >>= 1
	}
	return res
}

func fib(n int) int {
	if n == 0 {
		return 0
	}
	T := [][]int{{1, 1}, {1, 0}}
	Tn := matPow(T, n-1)
	return Tn[0][0]
}
```

### Convex Hull Trick（入門）

**魔理沙**: DP が `dp[i] = min_j (dp[j] + cost(j, i))` で、`cost` が **傾きが単調** なら、deque で直線群の下包絡を維持して O(N) になる。

**霊夢**: 直線の束の「下側の折れ線」ってこと？

**魔理沙**: 各 j が `y = m*x + b` の直線を表すと、各 i で **最小値を取る j** を探す DP だ。傾き m が単調なら、古い直線は二度と最小にならないので deque で捨てられる。

#### イメージ / 手順

1. 各候補 j を直線 `(m, b)` に変換（`cost(j,i)` の形から m, b を読む）  
2. 直線は **傾きの降順** に追加し、クエリ x は **昇順** に投げる（この向きのとき deque の先頭から捨てられる）  
3. 新しい直線を入れるとき、**交点の順序** がおかしい後ろを pop（`bad` 判定）  
4. クエリ x（= i）で deque 先頭を評価

#### いつ使うか

| キーワード | 候補 |
|------------|------|
| `min_j (dp[j] + a[j]*x + b[j])`、傾き単調 | CHT（deque） |
| 凸コスト、区間 min | CHT または Li Chao |
| 傾きが単調でない | Li Chao 木、セグ木 |
| n, k が 10^18 | 行列べき乗の方を先に疑う |

#### 計算量

| 手法 | 目安 |
|------|------|
| ナイーブ DP | O(N²) |
| CHT（単調傾き） | O(N) |
| Li Chao | O(N log V) 程度 |

#### つまずき

- **傾きの向きとクエリの向き** を取り違える（下のコードは「傾き降順に追加・x 昇順にクエリ」専用。逆なら符号を反転して合わせる）  
- **min か max か** で deque の pop 条件が反転する  
- **x の定義**（0-index / 1-index）で直線の傾き・切片が変わる  
- 傾きが単調でないのに CHT だけ使って WA  
- `bad` の式は整数除算の丸めに注意（浮動小数は避ける）

→ [solutions/python/06/cht/](../solutions/python/06/cht/) / [solutions/go/06/cht/](../solutions/go/06/cht/)

```python
from collections import deque

def cht_min(lines):
    """y = m*x + b の下包絡（最小値）を作る。

    前提: lines は傾き m の **降順**（単調減少）、クエリ x は **昇順**。
    同じ傾きの直線は切片 b が小さい方だけ残す。
    """
    dq = deque()

    def bad(l1, l2, l3):
        # l1, l3 の交点が l1, l2 の交点より左（以下）なら l2 は最小にならない
        return (l3[1] - l1[1]) * (l1[0] - l2[0]) <= (l2[1] - l1[1]) * (l1[0] - l3[0])

    for ln in lines:
        if dq and dq[-1][0] == ln[0]:
            if dq[-1][1] <= ln[1]:
                continue
            dq.pop()
        while len(dq) >= 2 and bad(dq[-2], dq[-1], ln):
            dq.pop()
        dq.append(ln)
    return dq

def query(dq, x):
    """x は前回のクエリ以上であること（先頭の直線を捨てていくため）"""
    while len(dq) >= 2:
        m1, b1 = dq[0]
        m2, b2 = dq[1]
        if m1 * x + b1 < m2 * x + b2:
            break
        dq.popleft()
    m, b = dq[0]
    return m * x + b
```

**霊夢**: 傾きが単調じゃないと？

**魔理沙**: 別の CHT や Li Chao 木（セグ木）を使う。黄色では **単調傾き** の型を見抜くところまででよい。

```go
type line struct{ m, b int }

func (l line) eval(x int) int { return l.m*x + l.b }

// chtMin は y = m*x + b の下包絡（最小値）を作る。
// 前提: lines は傾き m の降順、クエリ x は昇順。
func chtMin(lines []line) []line {
	dq := []line{}
	bad := func(l1, l2, l3 line) bool {
		// l1, l3 の交点が l1, l2 の交点より左（以下）なら l2 は最小にならない
		return (l3.b-l1.b)*(l1.m-l2.m) <= (l2.b-l1.b)*(l1.m-l3.m)
	}
	for _, ln := range lines {
		if len(dq) > 0 && dq[len(dq)-1].m == ln.m {
			if dq[len(dq)-1].b <= ln.b {
				continue
			}
			dq = dq[:len(dq)-1]
		}
		for len(dq) >= 2 && bad(dq[len(dq)-2], dq[len(dq)-1], ln) {
			dq = dq[:len(dq)-1]
		}
		dq = append(dq, ln)
	}
	return dq
}

// query は x が前回以上であることを前提に、先頭の直線を捨てながら最小値を返す。
func query(dq *[]line, x int) int {
	for len(*dq) >= 2 && (*dq)[0].eval(x) >= (*dq)[1].eval(x) {
		*dq = (*dq)[1:]
	}
	return (*dq)[0].eval(x)
}
```

## 6.2 木の重心分解・LCA

**霊夢**: 木の「真ん中」って、重心？

**魔理沙**: **重心** は、どの部分木を切っても残りのサイズが n/2 以下になる頂点だ。**重心分解** は、重心で木を分割し、パスクエリを O(log n) 段で処理する技法だ。

**霊夢**: LCA は「最近共通の祖先」だよね。黄色ではどっちが先？

**魔理沙**: **LCA を書ける** のが先。**重心分解** は「パス上・距離 d 以内」の集計に効く。どちらも [05.md](05.md) の DFS・木の基礎の上に乗る。

### 重心分解のイメージ / 手順

1. 部分木サイズを DFS で求め、**重心**（切っても各片 ≤ n/2）を 1 つ取る  
2. その重心を根に見立て、全頂点までの距離などを集計  
3. 重心を除いた各連結成分に **再帰**（深さ O(log n)）  
4. 「距離 d 以内に〜」系のクエリで、重心を跨ぐ経路をまとめて数える

### いつ使うか

| キーワード | 候補 |
|------------|------|
| 木、2 頂点のパス・距離 | LCA |
| パス上の和・最大（静的） | LCA + 前計算、または HLD（[07.md](07.md)） |
| 距離 k 以内、部分木、根からの距離 | 重心分解 |
| 動的 link/cut | リンクカット木（橙色） |

### 計算量

| 技法 | 前処理 | クエリ |
|------|--------|--------|
| LCA（ダブリング） | O(N log N) | O(log N) |
| 重心分解（典型） | 構築 O(N log N) | 問題による |

### つまずき

- **LOG** は「2^LOG > N」になるように N から計算する（`n.bit_length()`）。固定値にすると深い木で祖先が足りない  
- LCA で **深い方を先に上げる**  
- 重心分解で **除去した重心を二重カウント**  
- 無向木で `parent` の向きを DFS 前に固定する

### LCA（ダブリング）

→ [solutions/python/06/lca/](../solutions/python/06/lca/) / [solutions/go/06/lca/](../solutions/go/06/lca/)

```python
import sys

sys.setrecursionlimit(10**7)

def dfs(v, p, depth, up, g, LOG):
    up[v][0] = p
    for i in range(1, LOG):
        up[v][i] = up[up[v][i - 1]][i - 1] if up[v][i - 1] != -1 else -1
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs(to, v, depth, up, g, LOG)

def lca(a, b, depth, up, LOG):
    if depth[a] < depth[b]:
        a, b = b, a
    d = depth[a] - depth[b]
    for i in range(LOG):  # 深い方を、深さの差だけ上げる
        if d >> i & 1:
            a = up[a][i]
    if a == b:
        return a
    for i in range(LOG - 1, -1, -1):  # 祖先が分かれる直前まで一緒に上げる
        if up[a][i] != up[b][i]:
            a = up[a][i]
            b = up[b][i]
    return up[a][0]

def build_lca(g, root=0):
    n = len(g)
    LOG = max(1, n.bit_length())  # 2^LOG > n なので、深さの差（< n）を表せる
    up = [[-1] * LOG for _ in range(n)]
    depth = [0] * n
    dfs(root, -1, depth, up, g, LOG)
    return depth, up, LOG
```

```go
func dfs(v, p int, depth []int, up [][]int, g [][]int, LOG int) {
	up[v][0] = p
	for i := 1; i < LOG; i++ {
		if up[v][i-1] != -1 {
			up[v][i] = up[up[v][i-1]][i-1]
		} else {
			up[v][i] = -1
		}
	}
	for _, to := range g[v] {
		if to == p {
			continue
		}
		depth[to] = depth[v] + 1
		dfs(to, v, depth, up, g, LOG)
	}
}

func lca(a, b int, depth []int, up [][]int, LOG int) int {
	if depth[a] < depth[b] {
		a, b = b, a
	}
	d := depth[a] - depth[b]
	for i := 0; i < LOG; i++ { // 深い方を、深さの差だけ上げる
		if d>>i&1 == 1 {
			a = up[a][i]
		}
	}
	if a == b {
		return a
	}
	for i := LOG - 1; i >= 0; i-- { // 祖先が分かれる直前まで一緒に上げる
		if up[a][i] != up[b][i] {
			a = up[a][i]
			b = up[b][i]
		}
	}
	return up[a][0]
}

func buildLCA(g [][]int, root int) ([]int, [][]int, int) {
	n := len(g)
	LOG := 1
	for 1<<LOG <= n { // 2^LOG > n なので、深さの差（< n）を表せる
		LOG++
	}
	up := make([][]int, n)
	for i := range up {
		up[i] = make([]int, LOG)
	}
	depth := make([]int, n)
	dfs(root, -1, depth, up, g, LOG)
	return depth, up, LOG
}
```

**霊夢**: パス上の和や最大値は？

**魔理沙**: 重心分解 + データ構造、または **HLD（重軽分解）**（[07.md](07.md) で詳しくする）。黄色では **LCA が書ける** ことが先だ。

**霊夢**: `up[v][0] = -1` で根の親は？

**魔理沙**: 根の親を -1 にしておくと、「上に上がりすぎ」判定が簡単になる。ダブリングの初期化で `up[v][i] = -1` を埋めておくのも同じ理由だ。

## 6.3 平方分割

**霊夢**: クエリがたくさん来る配列問題、全部セグ木？

**魔理沙**: **平方分割** や **Mo's algorithm** で、オフラインクエリをまとめて処理する。区間 `[l,r]` のクエリを、**左端の動きが O(√N)** になるよう並べ替える。

**霊夢**: オンラインじゃダメなの？

**魔理沙**: Mo は **クエリの順番を自分で決められる** 前提。区間の add/remove が O(1)（または軽い log）なら、並べ替えで総移動量を抑えられる。セグ木で毎クエリ O(log N) でもよいが、オフラインでまとめられるなら Mo が勝つことがある。

### 平方分割のイメージ

配列を **√N 個ずつのブロック** に分け、ブロック単位の集計 + 端のブルートフォース。セグ木より実装が軽いことがある。

### Mo's algorithm のイメージ / 手順

1. ブロック幅 `B ≈ √N` を決める  
2. クエリを `(ブロック番号, 右端 r, 左端 l, 元の順番)` でソート（奇数ブロックは r 降順で **ジグザグ**）  
3. 現在区間 `[cur_l, cur_r)` を、次のクエリに合わせて **add/remove** で伸縮  
4. 各クエリの答えを記録して、元の順に戻す

### いつ使うか

| キーワード | 候補 |
|------------|------|
| 区間クエリが大量、オフライン可 | Mo / 平方分割 |
| 区間の種類数・出現回数・xor 和 | Mo（add/remove が軽いとき） |
| 区間の min/max、和の更新もある | セグ木・フェニック |
| クエリ順が固定（オンライン） | セグ木 |

### 計算量

| 手法 | 目安 |
|------|------|
| Mo（add/remove O(1)） | O((N+Q)√N) |
| ブロック平方分割 | O(N√N) 前処理 + クエリによる |

### つまずき

- **区間が `[l,r]` 閉区間か `[l,r)` か** で add/remove のループがズレる  
- 右端・左端の伸縮 **4 本の while** の順序をテンプレ通りに  
- 奇数ブロックの **r 降順** を忘れると遅くなる  
- distinct カウントで `cnt[x]==0` のときだけ増減

### Mo's algorithm（入門）

→ [solutions/python/06/mo/](../solutions/python/06/mo/) / [solutions/go/06/mo/](../solutions/go/06/mo/)

```python
def mo_order(queries, n, block):
    ordered = []
    for idx, (l, r) in enumerate(queries):
        block_id = l // block
        ordered.append((block_id, r if block_id % 2 else -r, l, r, idx))
    ordered.sort()
    return ordered

def mo_count_distinct(a, queries):
    n = len(a)
    block = int(n**0.5) + 1
    order = mo_order(queries, n, block)
    cnt = {}
    cur_l, cur_r = 0, 0
    distinct = 0
    ans = [0] * len(queries)

    def add(i):
        nonlocal distinct
        x = a[i]
        cnt[x] = cnt.get(x, 0) + 1
        if cnt[x] == 1:
            distinct += 1

    def remove(i):
        nonlocal distinct
        x = a[i]
        cnt[x] -= 1
        if cnt[x] == 0:
            distinct -= 1

    for _, _, l, r, idx in order:
        while cur_r <= r:
            add(cur_r)
            cur_r += 1
        while cur_r - 1 > r:
            cur_r -= 1
            remove(cur_r)
        while cur_l > l:
            cur_l -= 1
            add(cur_l)
        while cur_l < l:
            remove(cur_l)
            cur_l += 1
        ans[idx] = distinct
    return ans
```

**魔理沙**: 計算量はだいたい **O((N+Q)√N)**。オフラインで区間の種類数・頻度などに使う。

```go
func moCountDistinct(a []int, queries [][2]int) []int {
	n := len(a)
	block := int(math.Sqrt(float64(n))) + 1
	type item struct{ bid, r, l, idx int }
	items := make([]item, len(queries))
	for i, q := range queries {
		bid := q[0] / block
		r := q[1]
		if bid%2 == 1 {
			r = -r
		}
		items[i] = item{bid, r, q[0], i}
	}
	sort.Slice(items, func(i, j int) bool {
		if items[i].bid != items[j].bid {
			return items[i].bid < items[j].bid
		}
		return items[i].r < items[j].r
	})
	cnt := map[int]int{}
	curL, curR, distinct := 0, 0, 0
	ans := make([]int, len(queries))
	add := func(i int) {
		x := a[i]
		cnt[x]++
		if cnt[x] == 1 {
			distinct++
		}
	}
	remove := func(i int) {
		x := a[i]
		cnt[x]--
		if cnt[x] == 0 {
			distinct--
		}
	}
	for _, it := range items {
		l, r := it.l, queries[it.idx][1]
		for curR <= r {
			add(curR)
			curR++
		}
		for curR-1 > r {
			curR--
			remove(curR)
		}
		for curL > l {
			curL--
			add(curL)
		}
		for curL < l {
			remove(curL)
			curL++
		}
		ans[it.idx] = distinct
	}
	return ans
}
```

## 6.4 FFT・NTT（入門）

**霊夢**: 畳み込みって、多項式の掛け算？

**魔理沙**: 配列 `a`, `b` の畳み込み `c` は `c[k] = sum_i a[i]*b[k-i]`。ナイーブは O(N²)。**NTT** は mod 上で O(N log N) だ。競プロでは **998244353** と原根 3 が定番。

**霊夢**: なんで 998244353 なの？

**魔理沙**: `2^23 × 119 × 1` の形で、長さ n が 2 の冪の NTT に向いた **素数** だ。原根 3 で単位根が作れる。問題の mod が違うときは、CRT で別 mod の結果を合成する話になる（橙色以降）。

### 畳み込みのイメージ / 手順

1. 長さを **2 の冪** にパディング（畳み込み結果の長さまで）  
2. 両配列に **NTT**（順変換）  
3. 同じ位置の係数を **掛け合わせる**  
4. **逆 NTT**（逆変換）で係数列に戻す  
5. 必要な長さだけ切り出す

### いつ使うか

| キーワード | 候補 |
|------------|------|
| 畳み込み、多項式の積、係数列 | NTT / FFT |
| 組み合わせ数列の生成関数 | NTT |
| mod が 998244353 または NTT 向き素数 | NTT |
| 実数・浮動小数が必要 | FFT（誤差注意） |

### 計算量

| 手法 | 目安 |
|------|------|
| ナイーブ畳み込み | O(N²) |
| NTT / FFT | O(N log N) |

### つまずき

- 長さが **2 の冪でない** まま NTT する  
- 逆変換後に **1/n を掛け忘れ**（mod では逆元）  
- `invert=True` のとき **原根の逆** を使う  
- mod が NTT 非対応なのにそのまま NTT する

### NTT（入門・非再帰）

→ [solutions/python/06/ntt/](../solutions/python/06/ntt/) / [solutions/go/06/ntt/](../solutions/go/06/ntt/)

```python
MOD = 998244353
G = 3

def ntt(a, invert=False):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]
    length = 2
    while length <= n:
        w = pow(G, (MOD - 1) // length, MOD)
        if invert:
            w = pow(w, MOD - 2, MOD)
        half = length // 2
        for i in range(0, n, length):
            wn = 1  # w^j を順に掛けていく
            for j in range(half):
                u = a[i + j]
                v = a[i + j + half] * wn % MOD
                a[i + j] = (u + v) % MOD
                a[i + j + half] = (u - v) % MOD
                wn = wn * w % MOD
        length <<= 1
    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD
    return a

def convolution(a, b):
    n1, n2 = len(a), len(b)
    n = 1
    while n < n1 + n2 - 1:
        n <<= 1
    fa = a + [0] * (n - n1)
    fb = b + [0] * (n - n2)
    fa = ntt(fa)
    fb = ntt(fb)
    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD
    return ntt(fa, invert=True)[: n1 + n2 - 1]
```

## 6.5 最大流・最小費用流（応用）

**霊夢**: [05.md](05.md) の最大流、まだ入門だったよね？

**魔理沙**: 黄色では **Dinic** や **最小費用流** が実戦投入される。**マッチング → フロー** の還元を覚えろ。

**霊夢**: [05.md](05.md) の Ford-Fulkerson から何が変わるの？

**魔理沙**: **Dinic** は BFS で **level グラフ** を作り、DFS で **ブロッキングフロー** を一気に流す。辺の数が多いグラフでも実用的になりやすい。最小費用流は「1 単位流すたびのコスト最小」で、マッチングの **重み付き** 版にも使える。

### フロー還元のイメージ / 手順

1. 問題を **s から t へ流す** 形に言い換える  
2. 制約を **容量** に落とす（頂点容量は in/out 分割）  
3. `max_flow(s,t)` が答え、またはその値で二分  
4. 最小費用なら **費用付き辺** + ポテンシャル（または SPFA）

| 問題 | 還元のイメージ |
|------|----------------|
| 二部マッチング | s→左 容量1、左→右 容量1、右→t 容量1 |
| 頂点容量 | 頂点 v を v_in → v_out に分割、辺は v_out へ |
| 最小カット | 最大流 = 最小カット（弱・強対偶） |
| 最小費用流 | 費用付き辺で流量を送る |

### いつ使うか

| キーワード | 候補 |
|------------|------|
| マッチング、割当、選び方 | フロー |
| 最大流、容量、パイプ | Dinic |
| コスト最小、費用 | 最小費用流 |
| 頂点あたり 1 回まで | 頂点分割 + 容量 1 |

### 計算量

| 手法 | 目安 |
|------|------|
| Dinic（一般） | O(V²E) 程度（実用上はもっと速いことが多い） |
| 最小費用流 | 実装による（Dijkstra + ポテンシャルが定番） |

### つまずき

- **逆向き辺**（残量）の `rev` インデックスを間違える  
- 頂点容量を **分割せず** 辺だけに容量を付ける  
- `level[s] < 0` で終了するのに DFS を回し続ける  
- 最小費用流で **負サイクル** とポテンシャルの初期化

```go
type edge struct{ to, cap, rev int }

type Dinic struct {
	n int
	g [][]edge
}

func (d *Dinic) AddEdge(fr, to, cap int) {
	d.g[fr] = append(d.g[fr], edge{to, cap, len(d.g[to])})
	d.g[to] = append(d.g[to], edge{fr, 0, len(d.g[fr]) - 1})
}

func (d *Dinic) bfs(s, t int, level []int) bool {
	for i := range level {
		level[i] = -1
	}
	level[s] = 0
	q := []int{s}
	for head := 0; head < len(q); head++ {
		v := q[head]
		for _, e := range d.g[v] {
			if e.cap > 0 && level[e.to] < 0 {
				level[e.to] = level[v] + 1
				q = append(q, e.to)
			}
		}
	}
	return level[t] >= 0
}

func (d *Dinic) dfs(v, t, f int, level, iter []int) int {
	if v == t {
		return f
	}
	for i := iter[v]; i < len(d.g[v]); i++ {
		iter[v] = i
		e := d.g[v][i]
		if e.cap > 0 && level[v] < level[e.to] {
			df := d.dfs(e.to, t, min(f, e.cap), level, iter)
			if df > 0 {
				d.g[v][i].cap -= df
				d.g[e.to][e.rev].cap += df
				return df
			}
		}
	}
	return 0
}

func (d *Dinic) MaxFlow(s, t int) int {
	flow := 0
	level := make([]int, d.n)
	for d.bfs(s, t, level) {
		iter := make([]int, d.n)
		for {
			f := d.dfs(s, t, 1<<30, level, iter)
			if f == 0 {
				break
			}
			flow += f
		}
	}
	return flow
}
```

## 6.6 文字列：サフィックス配列・自動機

**霊夢**: サフィックス配列って、全部の後ろの並びをソートした感じ？

**魔理沙**: **辞書順にサフィックスを並べた配列 SA** と、**LCP（最長共通接頭辞）** の組で、部分文字列・繰り返しを扱う。

**霊夢**: 全部の後ろをソートするって、重くない？

**魔理沙**: 素朴に O(N² log N) だが、**倍々で rank を更新** すれば O(N log² N) や O(N log N) まで落とせる。黄色では簡易構築 + **用途の理解** が先だ。

### サフィックス配列のイメージ / 手順

1. 各開始位置 `i` を **サフィックス** `s[i:]` とみなす  
2. 辞書順に並べた順序が **SA**  
3. 隣接サフィックスの **LCP** 配列で「共通接頭辞の長さ」が分かる  
4. 部分文字列の出現回数・最長繰り返しなどに還元

### いつ使うか

| キーワード | 候補 |
|------------|------|
| 部分文字列、繰り返し、周期 | SA + LCP |
| 辞書順 k 番目のサフィックス | SA |
| 複数パターンの同時マッチ | Aho-Corasick |
| 1 パターンのマッチ | KMP（[05.md](05.md)） |

### 計算量

| 構築 | 目安 |
|------|------|
| 簡易 SA（本節） | O(N log² N) |
| SA-IS 等 | O(N) |

### つまずき

- 文字列末尾に **`$` などの番兵** を付けないと LCP が崩れることがある  
- `rank[i+k]` が範囲外のとき **-1** 扱いを忘れる  
- SA だけ作って **LCP を使わない**（問題によっては LCP が本丸）

### サフィックス配列（簡易構築 O(N log² N)）

```python
def suffix_array(s):
    n = len(s)
    sa = list(range(n))
    rank = [ord(c) for c in s]
    k = 1
    while k < n:
        sa.sort(key=lambda i: (rank[i], rank[i + k] if i + k < n else -1))
        new_rank = [0] * n
        new_rank[sa[0]] = 0
        for i in range(1, n):
            a = (rank[sa[i]], rank[sa[i] + k] if sa[i] + k < n else -1)
            b = (rank[sa[i - 1]], rank[sa[i - 1] + k] if sa[i - 1] + k < n else -1)
            new_rank[sa[i]] = new_rank[sa[i - 1]] + (a != b)  # ソート済みなので a != b なら a > b
        rank = new_rank
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1
    return sa
```

```go
func suffixArray(s string) []int {
	n := len(s)
	sa := make([]int, n)
	for i := range sa {
		sa[i] = i
	}
	rank := make([]int, n)
	for i, c := range s {
		rank[i] = int(c)
	}
	for k := 1; k < n; k <<= 1 {
		sort.Slice(sa, func(i, j int) bool {
			ri, rj := rank[sa[i]], rank[sa[j]]
			if ri != rj {
				return ri < rj
			}
			ai, aj := -1, -1
			if sa[i]+k < n {
				ai = rank[sa[i]+k]
			}
			if sa[j]+k < n {
				aj = rank[sa[j]+k]
			}
			return ai < aj
		})
		newRank := make([]int, n)
		newRank[sa[0]] = 0
		for i := 1; i < n; i++ {
			prev, cur := sa[i-1], sa[i]
			a1, a2 := rank[prev], rank[cur]
			b1, b2 := -1, -1
			if prev+k < n {
				b1 = rank[prev+k]
			}
			if cur+k < n {
				b2 = rank[cur+k]
			}
			less := a1 < a2 || (a1 == a2 && b1 < b2)
			newRank[cur] = newRank[prev]
			if less {
				newRank[cur]++
			}
		}
		rank = newRank
		if rank[sa[n-1]] == n-1 {
			break
		}
	}
	return sa
}
```

### Aho-Corasick（複数パターン）

**魔理沙**: 辞書の複数文字列を同時にマッチする **オートマトン**。トライ木 + **失敗リンク（failure link）** で、ミスマッチ時も別パターンへ飛べる。

**霊夢**: KMP の「失敗時に戻る先」を木版にした感じ？

**魔理沙**: そのイメージでよい。構築は `add` で辞書を挿入 → `build` で BFS → `search` で 1 パス走査。

#### いつ使うか

| キーワード | 候補 |
|------------|------|
| 複数キーワード、辞書、禁止語 | Aho-Corasick |
| 出現位置の列挙 | AC + 終端マーク |
| パターン 1 個 | KMP / Z |

→ [solutions/python/06/aho_corasick/](../solutions/python/06/aho_corasick/) / [solutions/go/06/aho_corasick/](../solutions/go/06/aho_corasick/)

```python
from collections import deque

class AhoCorasick:
    def __init__(self) -> None:
        self.next = [{}]
        self.fail = [0]
        self.out = [[]]  # そのノードで終わるパターン番号（失敗リンク先の分も含む）
        self.words = []

    def add(self, s: str) -> None:
        node = 0
        for ch in s:
            if ch not in self.next[node]:
                self.next[node][ch] = len(self.next)
                self.next.append({})
                self.fail.append(0)
                self.out.append([])
            node = self.next[node][ch]
        self.out[node].append(len(self.words))
        self.words.append(s)

    def build(self) -> None:
        q = deque(self.next[0].values())
        while q:
            v = q.popleft()
            for ch, nxt in self.next[v].items():
                f = self.fail[v]
                while f and ch not in self.next[f]:
                    f = self.fail[f]
                self.fail[nxt] = self.next[f].get(ch, 0)
                # 失敗リンク先で終わるパターンも、ここで終わっている
                self.out[nxt] = self.out[nxt] + self.out[self.fail[nxt]]
                q.append(nxt)

    def search(self, text: str) -> list:
        """(終了位置, パターン) のリストを返す"""
        node = 0
        hits = []
        for i, ch in enumerate(text):
            while node and ch not in self.next[node]:
                node = self.fail[node]
            node = self.next[node].get(ch, 0)
            for k in self.out[node]:
                hits.append((i, self.words[k]))
        return hits
```

## 6.7 組み合わせ論（応用）

**霊夢**: 包除原理、聞いたことある！

**魔理沙**: 「少なくとも 1 個」より **「ちょうど k 個」** が欲しいとき、包含関係で足したり引いたりする。

**霊夢**: 集合の和を「被り付き」で数えるやつだよね。

**魔理沙**: 条件 A₁…A_m について、**少なくとも 1 個を満たす** 個数は、空集合から始めて、1 個選ぶと足し、2 個選ぶと引き…と交互にする。競プロでは **「ちょうど k 個」** や **coprime の個数** に直すことが多い。

### 包除原理のイメージ / 手順

1. 条件を集合（または bit）で表す  
2. 各部分集合 S について **|∩_{i∈S} A_i|** を数える（単調なら式で高速化も可）  
3. |S| が奇数なら引く、偶数なら足す（「ちょうど」版は別の係数）  
4. 答えを mod で整える

### いつ使うか

| キーワード | 候補 |
|------------|------|
| 少なくとも / ちょうど k 個の条件 | 包除原理 |
| 互いに素、coprime | 包除（素因数で割る） |
| 回転・反転で同一 | Burnside |
| 木の全域木の個数 | 行列ツリー定理 |

### 計算量

| m 条件 | 部分集合走査 |
|--------|----------------|
| m ≤ 20 前後 | O(2^m × 各カウント) |

### つまずき

- **「少なくとも」と「ちょうど」** で符号が逆  
- 倍数のカウントで **lcm を取り忘れ**  
- 2^m が重いのに単調性で高速化できるのを見逃す

### 包除原理

### Burnside の補題（入門）

**魔理沙**: **回転・反転で一致するものを同一** とみなす数え上げ。置換 g の **固定点個数** を数え、群のサイズで割って平均する。

#### agc021_a（桁の貪欲）

→ [solutions/python/06/agc021_a/](../solutions/python/06/agc021_a/) / [solutions/go/06/agc021_a/](../solutions/go/06/agc021_a/)

**問題（要約）**: N 以下の正の整数の桁和の最大値を求める（N は最大 10^16）。 問題文は [AtCoder](https://atcoder.jp/contests/agc021/tasks/agc021_a) で読むこと。

**霊夢**: N 以下を全部調べるのは無理だね。

**魔理沙**: 桁和を大きくするには **下の桁を 9 にしたい**。N のある桁を 1 減らせば、それより下は自由に 9 にできる（それでも N 以下）。だから候補は「N そのもの」と「i 桁目を 1 減らして下を全部 9」の高々 17 個。全部の桁和を比べて最大を取る。

```python
import sys

def main() -> None:
    s = sys.stdin.readline().strip()
    best = sum(map(int, s))  # N そのもの
    for i, ch in enumerate(s):
        if ch == "0":
            continue
        # i 桁目を 1 減らし、それより下を全部 9 にした数は N 以下
        cand = sum(map(int, s[:i])) + int(ch) - 1 + 9 * (len(s) - i - 1)
        best = max(best, cand)
    print(best)

if __name__ == "__main__":
    main()
```

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	in := bufio.NewReader(os.Stdin)
	out := bufio.NewWriter(os.Stdout)
	defer out.Flush()

	var s string
	fmt.Fscan(in, &s)
	best, upper := 0, 0 // upper: i 桁目より上の桁の和
	for _, ch := range s {
		best += int(ch - '0') // N そのもの
	}
	for i := 0; i < len(s); i++ {
		d := int(s[i] - '0')
		if d > 0 {
			// i 桁目を 1 減らし、それより下を全部 9 にした数は N 以下
			if cand := upper + d - 1 + 9*(len(s)-i-1); cand > best {
				best = cand
			}
		}
		upper += d
	}
	fmt.Fprintln(out, best)
}
```

#### agc023_a（累積和 + 同じ値を数える）

→ [solutions/python/06/agc023_a/](../solutions/python/06/agc023_a/) / [solutions/go/06/agc023_a/](../solutions/go/06/agc023_a/)

**問題（要約）**: 整数列の連続部分列のうち、和が 0 になるものの個数を求める。 問題文は [AtCoder](https://atcoder.jp/contests/agc023/tasks/agc023_a) で読むこと。

**霊夢**: 区間の和は累積和の差だよね。

**魔理沙**: そうだ。区間 (l, r] の和が 0 ⇔ **累積和 S[l] と S[r] が等しい**。だから累積和を順に作りながら、同じ値がこれまで何回出たかを辞書で数えて足せばいい。区間の問題を **「同じ値のペアを数える」** に言い換えるのは頻出の型だ。

```python
import sys
from collections import Counter

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))
    # 区間 (l, r] の和が 0 ⇔ 累積和 S[l] == S[r]
    cnt = Counter([0])  # S[0] = 0
    s = 0
    ans = 0
    for x in a:
        s += x
        ans += cnt[s]  # これまでに同じ累積和が出た回数だけ、和 0 の区間が増える
        cnt[s] += 1
    print(ans)

if __name__ == "__main__":
    main()
```

