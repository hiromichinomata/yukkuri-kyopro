## 1.1 標準入力・出力

**霊夢**: [00.md](00.md) で A+B はできた。でも問題文、1 行じゃないこともあるんでしょ？

**魔理沙**: その通り。灰色では **読み方のパターン** を体に覚えるのが仕事だ。AtCoder はだいたい次のどれかだ。

| パターン | 入力のイメージ | よくある問題 |
|----------|----------------|--------------|
| 1 行 1 個 | `5` | 整数 1 つ |
| 1 行 複数 | `3 1 4` | スペース区切り |
| 2 行目以降に N 行 | `3` のあと 3 行 | 配列・文字列 |

### いつ使うか

| 問題文のヒント | 読み方 |
|----------------|--------|
| 「1 行に整数が 1 つ」 | `int(input())` または `readline` 1 回 |
| 「スペース区切りで複数」 | `map(int, line.split())` |
| 「続く N 行に …」 | 先に `n`、あと `n` 回 `readline` |
| 行数が不定・余白が多い | `sys.stdin.read().split()`（[00.md](00.md) の一括読み） |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 1 行目だけ読んで止まる | 2 行目以降の `n` 行を読んでいない |
| 全部 0 や空 | `split()` 忘れ、型変換忘れ |
| サンプル OK・本番 WA | **余計な出力**、改行の有無、1-indexed / 0-indexed の取り違え |

**霊夢**: Python ではどう読むの？

**魔理沙**: 基本は 3 つだ。`input()` 1 行、`split()` で分割、`int()` で数にする。

**霊夢**: `input()` と `readline()`、どっち？

**魔理沙**: 競プロでは **`input = sys.stdin.readline`** を先に書いて `int(input())` する形が多い。遅い問題では `readline` の方が速いことがある。1 ファイル内では **混ぜない** ようにしろ。

#### 1 行・複数整数（Python）

```python
import sys

def main() -> None:
    line = sys.stdin.readline()
    a, b, c = map(int, line.split())
    print(a + b + c)

if __name__ == "__main__":
    main()
```

#### 1 行・複数整数（Go）

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	in := bufio.NewReader(os.Stdin)
	var a, b, c int
	fmt.Fscan(in, &a, &b, &c)
	fmt.Println(a + b + c)
}
```

**霊夢**: `map(int, ...)` って何？

**魔理沙**: 文字列のリストを、まとめて整数に変換する書き方だ。競プロでは毎日出会う。

#### 先に個数 N が来る（Python）

→ [solutions/python/01/io_n_lines/main.py](../solutions/python/01/io_n_lines/main.py)

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    xs = [int(input()) for _ in range(n)]
    print(sum(xs))

if __name__ == "__main__":
    main()
```

#### 先に個数 N が来る（Go）

→ [solutions/go/01/io_n_lines/main.go](../solutions/go/01/io_n_lines/main.go)

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	in := bufio.NewReader(os.Stdin)
	out := bufio.NewWriter(os.Stdout)
	defer out.Flush()

	var n int
	fmt.Fscan(in, &n)
	sum := 0
	for i := 0; i < n; i++ {
		var x int
		fmt.Fscan(in, &x)
		sum += x
	}
	fmt.Fprintln(out, sum)
}
```

**入力例**:

```text
3
10
20
30
```

**出力**: `60`

**霊夢**: 出力は `print` だけ？ 改行は？

**魔理沙**: `print(x)` は **末尾に改行が 1 つ** 付くのが AtCoder の想定だ。余計な文字列を足すと WA になる。

```python
# OK
print(42)

# WA になりがち
print("答えは", 42)
```

## 1.2 四則演算・条件分岐・ループ

**霊夢**: `if` と `for`、競プロでもそのまま使えるの？

**魔理沙**: 使える。灰色の A 問題は **条件分岐 1 段** と **ループ 0〜1 段** が多い。剰余 `%` も早めに慣えろ。「偶数か」「割り切れるか」は超頻出だ。

### いつ使うか

| キーワード | 書き方の例 |
|------------|------------|
| 最大・最小・比較 | `if` / `max` / `min` |
| 1 から N まで足す・数える | `for i in range(1, n + 1)` |
| 偶数・奇数・倍数 | `% 2`, `% k == 0` |
| Yes / No | 条件を満たすかだけ見て、文字列は問題文どおり |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 境界で WA | `n=0`, `n=1` を試していない |
| 無限ループ | `range(n)` と `range(1, n+1)` の取り違え |
| 負の剰余 | Python は `-1 % 3 == 2` など、文面どおりの条件式を使う |

**霊夢**: `range(1, n + 1)` の `+ 1`、毎回不安なんだけど。

**魔理沙**: 「1 から n まで inclusive」なら **終端は n+1 未満** だ。紙に `n=3` と書いて `1,2,3` が出るか確認する癖をつけろ。

#### 条件分岐（Python）

```python
x = int(input())
if x % 2 == 0:
    print("even")
else:
    print("odd")
```

#### 条件分岐（Go）

```go
var x int
fmt.Fscan(in, &x)
if x%2 == 0 {
    fmt.Println("even")
} else {
    fmt.Println("odd")
}
```

#### for ループで 1 から N（Python）

```python
n = int(input())
s = 0
for i in range(1, n + 1):
    s += i
print(s)
```

#### for ループ（Go）

```go
var n int
fmt.Fscan(in, &n)
s := 0
for i := 1; i <= n; i++ {
    s += i
}
fmt.Println(s)
```

## 1.3 配列・リスト・文字列の基礎

**霊夢**: 配列って、競プロだと何に使うの？

**魔理沙**: 「N 個の数を並べて扱う」ときの入れ物だ。Python では **リスト**、Go では **スライス** と呼ぶ。

### いつ使うか

| 問題の型 | 使うもの |
|----------|----------|
| N 個の整数 | リスト / スライス |
| 文字 1 行 | `str`、`strip()` |
| 先頭・末尾だけ見る | `xs[0]`, `xs[-1]` |
| 部分を切り出す | スライス `xs[l:r]`（茶色で本格化） |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| RE（実行時エラー） | `xs[n]` のように **範囲外**（有効は `0`〜`n-1`） |
| 長さが 1 足りない | `n` 行読むのに `n-1` 回ループ |
| 文字と数の混同 | `input()` が文字列のまま比較している |

**霊夢**: `xs[-1]` は便利だけど、空リストだと？

**魔理沙**: 空なら RE だ。問題文で **N ≥ 1** と言われていれば安心、と書いてあるかも確認しろ。

#### リストの読み方（Python）

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    xs = list(map(int, input().split()))
    print(xs[0], xs[-1], len(xs))

if __name__ == "__main__":
    main()
```

- `xs[0]` … 先頭  
- `xs[-1]` … 末尾  
- `len(xs)` … 長さ（添字は `0` から `n-1`）

#### スライス（Go）

```go
xs := make([]int, n)
for i := 0; i < n; i++ {
    fmt.Fscan(in, &xs[i])
}
fmt.Println(xs[0], xs[n-1], len(xs))
```

#### 文字列（Python）

→ [solutions/python/01/abc081_a/](../solutions/python/01/abc081_a/) / [solutions/go/01/abc081_a/](../solutions/go/01/abc081_a/)

`0` を除いた長さを数える（abc081_a 相当）。

```python
s = input().strip()
t = s.replace("0", "")
print(len(t))
```

```go
var s string
fmt.Fscan(in, &s)
cnt := 0
for _, ch := range s {
    if ch != '0' {
        cnt++
    }
}
fmt.Println(cnt)
```

**霊夢**: `replace` だけで解けちゃうの？

**魔理沙**: 灰色では **言語の標準機能で足りる** ことも多い。茶色以降は自分でループする場面が増える。

#### スライスで部分列（Python）

```python
s = "abcdef"
print(s[1:4])   # "bcd"  添字 1 以上 4 未満
print(s[::-1])  # 反転（たまに使う）
```

## 1.4 全探索（バイト力）

**霊夢**: アルゴリズムって言うと難しそう……

**魔理沙**: 灰色の「全探索」は **力任せで全部試す** だ。N が小さい（例: 100 以下）とき、二重ループで十分なことが多い。

**霊夢**: 二重ループって？

**魔理沙**: ループの中にもう 1 個ループを入れる。組み合わせやペアを調べるとき使う。

### いつ使うか（全探索）

| 問題文のヒント | 方針 |
|----------------|------|
| N ≤ 100（または 200）で「全部試せ」 | 二重・三重ループで OK |
| 「ペア」「組み合わせ」「どれか 2 つ」 | `i` と `j>i` の二重ループ |
| 「並べ替えてから」が出る | 茶色 [02.md](02.md) のソートへ（力任せより速い型あり） |
| N ≥ 10^5 で二重ループ | **別手法**（ソート+二分、累積和など）を検討 |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| TLE | N が大きいのに二重ループのまま |
| 同じペアを二重カウント | `j` を `i+1` からにしていない |
| 見落とし | `break` の位置で外側ループが止まらない |

**霊夢**: 「全部試す」って言葉、出たらとりあえずループ？

**魔理沙**: **制約が小さいときだけ** だ。制約を読んでから「10^4 回以内か」を数えろ。ダメなら別の章の技法を探す。

#### ペアの和が K になるか（Python）

→ [solutions/python/01/brute_force_pair/](../solutions/python/01/brute_force_pair/) / [solutions/go/01/brute_force_pair/](../solutions/go/01/brute_force_pair/)

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n, k = map(int, input().split())
    xs = list(map(int, input().split()))
    ok = False
    for i in range(n):
        for j in range(i + 1, n):
            if xs[i] + xs[j] == k:
                ok = True
                break
        if ok:
            break
    print("Yes" if ok else "No")

if __name__ == "__main__":
    main()
```

```go
ok := false
for i := 0; i < n; i++ {
    for j := i + 1; j < n; j++ {
        if xs[i]+xs[j] == k {
            ok = true
            break
        }
    }
    if ok {
        break
    }
}
if ok {
    fmt.Println("Yes")
} else {
    fmt.Println("No")
}
```

**霊夢**: `i + 1` から始めるのはなぜ？

**魔理沙**: 同じペアを二回数えないためだ。`(i,j)` と `(j,i)` を別に見ない。

#### 全探索の見積もり

| N の目安 | 二重ループ | 感覚 |
|----------|------------|------|
| ≤ 100 | 〜10^4 | 余裕 |
| ≤ 1,000 | 〜10^6 | ギリギリ |
| ≤ 10^5 | 〜10^10 | 無理（別アルゴリズムへ） |

### 計算量

- 二重ループ: **O(N²)**（N=10^3 なら約 10^6 操作でギリギリの問題もある）  
- 三重ループ: **O(N³)**（N=200 程度までが目安）  
- 全探索でも **定数と定数倍** は効く。Python は Go より遅いので、同じ O(N²) でも Python だけ TLE になりやすい  

**魔理沙**: 制約を読んで「何回ループするか」をざっくり数える癖をつけろ。TLE はだいたいここで起きる。

## 1.5 関数・スコープ・デバッグ

**霊夢**: 1 ファイルに全部書くの？ 長くならない？

**魔理沙**: 灰色では短いままでもいいが、**読みやすくするために関数に分ける** のは早めにやるとよい。

### いつ使うか

| 状況 | 関数に分ける例 |
|------|----------------|
| GCD・判定・1 ステップの更新 | `gcd(a,b)`, `ok(x)` |
| 同じ処理を 2 回以上書きそう | 共通化 |
| シミュレーションの 1 手 | `step(state)`（後の Part でも使う） |

### つまずき（デバッグ）

| 症状 | まず疑うこと |
|------|----------------|
| WA | 出力形式、サンプル以外の境界 |
| RE | 添字、ゼロ除算、再帰深さ（Python） |
| TLE | ループ回数（1.4 の表に戻る） |
| ローカルだけおかしい | 入力ファイルの改行・全角スペース |

**霊夢**: `debug` を stderr に出すの、なんで？

**魔理沙**: ジャッジは **標準出力だけ** を答えと比較する。デバッグを stdout に出すと WA になる。stderr なら提出時に消せば影響しない（それでも提出前に消すのが安全だ）。

#### 関数に分ける（Python）

→ [solutions/python/01/gcd_fn/](../solutions/python/01/gcd_fn/) / [solutions/go/01/gcd_fn/](../solutions/go/01/gcd_fn/)

```python
def gcd(a: int, b: int) -> int:
    while b:
        a, b = b, a % b
    return a

def main() -> None:
    a, b = map(int, input().split())
    print(gcd(a, b))

if __name__ == "__main__":
    main()
```

```go
func gcd(a, b int) int {
    for b != 0 {
        a, b = b, a%b
    }
    return a
}
```

**霊夢**: バグったときどうするの？

**魔理沙**: ローカルでは **print デバッグ** で十分だ。提出直前に消す。

```python
import sys

def debug(*args):
    print(*args, file=sys.stderr)

def main() -> None:
    n = int(input())
    debug("n =", n)  # 提出前に削除
    print(n * 2)
```

| 症状 | よくある原因 |
|------|----------------|
| WA | 出力形式、境界（0, 1, 最大） |
| RE | 添字はみ出し、ゼロ除算、再帰深さ |
| TLE | ループ回数過多 |

## 1.6 模擬（シミュレーション）

**霊夢**: シミュレーションって、何をするの？

**魔理沙**: 問題文のルールどおりに **状態を更新していく** ことだ。「カードを引く」「時刻を進める」など、while / for で 1 ステップずつ再現する。

### いつ使うか

| 問題文のヒント | 方針 |
|----------------|------|
| 「1 日ずつ」「1 手ずつ」「時刻 t で …」 | `for` / `while` で 1 ステップ更新 |
| ルールが文章で長い | 変数で **状態**（残りカード、位置、スコア）を明示 |
| 「最適に操作」かつ N が小さい | 全探索・DP（abc088_b）。N が大きいなら別技法 |

### つまずき（シミュレーション）

| 落とし穴 | 対策 |
|----------|------|
| ルールの読み違え | 紙に **初期状態 → 1 手後 → 終了条件** を 3 行で書く |
| 先手・後手の交代忘れ | `turn ^= 1` や `turn = 1 - turn` など **1 か所** にまとめる |
| コピーと参照 | Python でリストを代入すると参照が共有されることがある。必要なら `xs.copy()` |
| 「貪欲に取る」≠ 問題の最適 | 問題文が **最適戦略** を求めているか確認（abc088_b は最適が必要） |
| `pop(0)` で TLE | N が大きいときは **deque** やインデックス管理（茶色以降） |

**霊夢**: while の中でリストから先頭を抜くと遅いって、今は気にしなくていい？

**魔理沙**: 灰色・N≤100 なら気にしなくていい。まず **正しく動く** シミュレーションを書け。速さは制約を見てから直せばいい。

### 🖐️ ハンズオン: 先頭からカードを引く（abc088_b 相当）

→ [solutions/python/01/abc088_b/](../solutions/python/01/abc088_b/) / [solutions/go/01/abc088_b/](../solutions/go/01/abc088_b/)

**ルール（要約）**: 長さ N の数列。先手・後手が交互に、**左端か右端** のカードを 1 枚取る。合計が大きい方が勝ち。最適に取ったときの先手の合計を出力する（典型は B 問題）。

**霊夢**: 最適って、全部試すの？

**魔理沙**: abc088_b は N が小さいので全探索や DP もあるが、灰色では **「貪欲に大きい方を取る」シミュレーション** の練習として、まずはルールをコードに落とすことが大事だ。本リポジトリでは **シンプル版**（交互に左端だけ取る例）も置いてある。本番は AtCoder で問題文を読んで実装しろ。

#### 交互に左端を取る（練習・Python）

→ [solutions/python/01/simulate_left_only/](../solutions/python/01/simulate_left_only/)

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    xs = list(map(int, input().split()))
    t = 0  # 先手の合計
    turn = 0
    while xs:
        t += xs.pop(0)
        turn ^= 1
    print(t)

if __name__ == "__main__":
    main()
```

**魔理沙**: 本番の abc088_b は左右の選択が要る。次の [茶色 Part](02.md) 前に、AtCoder で本題を解いてみろ。

#### abc088_b（提出用・再帰的メモ化の簡易版）

本リポジトリの [abc088_b](../solutions/python/01/abc088_b/) は、区間 `[l,r]` で先手が最適に取ったときの得点差を **メモ化再帰** で求める定番実装だ（N ≤ 100 程度なら通る）。

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def f(l: int, r: int) -> int:
    if l == r:
        return a[l]
    return max(a[l] - f(l + 1, r), a[r] - f(l, r - 1))
```

**霊夢**: 難しく見える……

**魔理沙**: 灰色では「while で 1 ステップずつ」でもよい。まずは **動くシミュレーション** を書く経験を積め。

## 1.7 数学の基礎

**霊夢**: 数学苦手なんだけど……

**魔理沙**: 灰色で出るのは **最大公約数（GCD）**、**倍数・剰余**、**偶奇（パリティ）** くらいだ。テンプレを覚えろ。

### いつ使うか

| キーワード | 技法 |
|------------|------|
| 両方で割り切れる・同じ周期 | GCD / LCM（LCM は茶色以降でも可） |
| 3 の倍数・5 の倍数 | `%` |
| 奇数個・偶奇が同じ | 個数の `% 2` や XOR（入門） |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| GCD が 1 にならない | `while b:` の更新順、`a,b` の入れ替えミス |
| 倍数判定の漏れ | `0` が倍数として許されるか問題文を確認 |
| XOR を使いすぎ | 灰色では **カウントで十分** なことが多い |

**霊夢**: GCD、証明しなくていいの？

**魔理沙**: 灰色では **ユークリッドの互除法のコードを信じて使う** でよい。なぜ動くかは後の Part や数学の記事で足りる。

#### GCD（ユークリッドの互除法）

→ [solutions/python/01/gcd_fn/](../solutions/python/01/gcd_fn/)（1.5 と共通）

```python
def gcd(a: int, b: int) -> int:
    while b:
        a, b = b, a % b
    return a
```

```go
func gcd(a, b int) int {
    for b != 0 {
        a, b = b, a%b
    }
    return a
}
```

#### 倍数・剰余

```python
n = int(input())
if n % 3 == 0 and n % 5 == 0:
    print("FizzBuzz")
elif n % 3 == 0:
    print("Fizz")
elif n % 5 == 0:
    print("Buzz")
else:
    print(n)
```

#### パリティ（_XOR の入門）

2 つの数が同じ偶奇なら `(a ^ b) % 2 == 0` のように書ける。灰色では「奇数個か？」のカウントで十分なことが多い。

```python
xs = list(map(int, input().split()))
odd = sum(x % 2 for x in xs)
print(odd % 2)  # 奇数個なら 1
```
