## 2.1 ソートとカスタム比較

**霊夢**: [01.md](01.md) まででループは慣れた。茶色になると何が増えるの？

**魔理沙**: まず **ソート** だ。並べ替えたあとに貪欲、二分、累積和と組み合わせる。茶色の B〜C では「ソートしてから何かする」が定番だぜ。

### いつ使うか

| 問題文のヒント | ソートの軸 |
|----------------|------------|
| 「最小のコスト順」「安い順に」 | 値の昇順 |
| 「終了が早い順」「締切」 | 第 2 要素（終了時刻）昇順 → 2.2 の貪欲 |
| 「辞書順で最小」 | 文字列そのまま、またはタプル |
| 「元の index が欲しい」 | `enumerate` してから `key` でソート |

### 計算量

- ソート: **O(N log N)**（N=10^5 でも普通は OK）  
- ソート後に 1 回走査: +O(N)  

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 期待と違う順序 | `reverse=True` の有無、`key` の指定ミス |
| ペアの第 1 要素で並べたつもり | `key=lambda x: x[1]` を忘れている |
| Go でソートしても変わらない | `sort.Slice` の **比較関数の向き**（`<` と `>`） |

**霊夢**: Python でソートするには？

**魔理沙**: リストの `sort` か、組み込みの `sorted` だ。

**霊夢**: `sort` と `sorted`、どっち使えばいい？

**魔理沙**: **元のリストを書き換えてよい** なら `xs.sort()`。**別のリストが欲しい** ときは `sorted(xs)`。競プロではどちらでもよいが、1 問題内で混ぜないようにしろ。

#### 昇順・降順（Python）

```python
xs = [3, 1, 4, 1]
xs.sort()                 # 昇順（元のリストを書き換え）
print(xs)                 # [1, 1, 3, 4]

ys = sorted(xs, reverse=True)  # 降順（新しいリスト）
```

#### 昇順・降順（Go）

→ [solutions/go/02/sort_pairs/](../solutions/go/02/sort_pairs/)

```go
import "sort"

xs := []int{3, 1, 4, 1}
sort.Ints(xs)  // 昇順

sort.Slice(xs, func(i, j int) bool {
    return xs[i] > xs[j]  // 降順
})
```

#### ペアを第 2 要素でソート（Python）

→ [solutions/python/02/sort_pairs/](../solutions/python/02/sort_pairs/)

```python
pairs = [(1, 3), (2, 1), (4, 2)]
pairs.sort(key=lambda x: x[1])   # 第 2 要素で昇順
print(pairs)  # [(2, 1), (4, 2), (1, 3)]
```

```python
# インデックス付きでソート（元の順番が欲しいとき）
items = [("b", 2), ("a", 1)]
items.sort(key=lambda t: t[1])
```

#### ペアのソート（Go）

```go
type pair struct{ a, b int }

ps := []pair{{1, 3}, {2, 1}, {4, 2}}
sort.Slice(ps, func(i, j int) bool {
    return ps[i].b < ps[j].b
})
```

**霊夢**: `key` って何？

**魔理沙**: 「どの値を基準に並べるか」を渡す関数だ。競プロでは **終了時刻**、**コスト**、**頻度** などで並べる。

## 2.2 bit 全探索・順列全探索

**霊夢**: [01.md](01.md) の全探索は二重ループだったよね。「どれを選ぶか」が N 個ぶんあるときは、ループを N 重にするの？

**魔理沙**: N が変わるたびにループの数は変えられない。そこで **bit 全探索** を使う。N 個のものそれぞれを「選ぶ / 選ばない」の 2 択にすると、組み合わせは **2^N 通り**。これを 0 〜 2^N − 1 の整数に対応させて、1 重ループで全部試す。

**霊夢**: 整数に対応させる？

**魔理沙**: 整数を 2 進数で書いたとき、**i ビット目が 1 なら i 番目を選ぶ** と決める。N=3 なら次の 8 通りだ。

| mask（10 進） | 2 進 | 選ぶもの |
|---------------|------|----------|
| 0 | 000 | なし |
| 1 | 001 | 0 番 |
| 2 | 010 | 1 番 |
| 3 | 011 | 0 番・1 番 |
| 4 | 100 | 2 番 |
| 5 | 101 | 0 番・2 番 |
| 6 | 110 | 1 番・2 番 |
| 7 | 111 | 全部 |

### bit 全探索の手順

1. `mask` を 0 から 2^N − 1 まで回す（`1 << N` が 2^N）  
2. 各 `i` について `mask >> i & 1` が 1 なら i 番目を「選んだ」とする  
3. 選んだものについて条件（和が K か、など）を調べる  
4. 条件を満たす mask を数える、または最大・最小を取る

### 順列全探索

**霊夢**: 「選ぶ / 選ばない」じゃなくて、「どの順番で回るか」を全部試したいときは？

**魔理沙**: それは **順列全探索** だ。N 個の並べ方は **N! 通り**。Python は `itertools.permutations` が全順列を出してくれる。Go には標準関数がないので、辞書順で次の並びを作る **nextPermutation** を自分で書く。

| | bit 全探索 | 順列全探索 |
|---|------------|------------|
| 試すもの | 各要素を選ぶ / 選ばない | 並べる順番 |
| 通り数 | 2^N | N! |
| N の上限の目安 | 〜20（2^20 ≒ 10^6） | 〜8〜10（10! ≒ 3.6×10^6） |
| Python | `for mask in range(1 << n)` | `itertools.permutations` |
| Go | `for mask := 0; mask < 1<<n; mask++` | 自作の `nextPermutation` |

### いつ使うか

| 問題文のヒント | 方針 |
|----------------|------|
| N ≤ 20 程度で「いくつか選ぶ」「部分集合」 | bit 全探索 |
| 「スイッチの ON/OFF」「参加する / しない」 | bit 全探索 |
| N ≤ 8〜10 で「順番」「回る順」「並べ替え」 | 順列全探索 |
| N ≥ 25 で部分集合 | 2^N が大きすぎる。DP（[03.md](03.md)）や半分全列挙（[07.md](07.md)）を検討 |

### 計算量

- bit 全探索: **O(2^N × N)**（N=20 で約 2×10^7）  
- 順列全探索: **O(N! × N)**（N=8 で約 3×10^5、N=10 で約 3.6×10^7）  
- [01.md](01.md) の 1.4 の表どおり、**N ≤ 20 を見たら bit 全探索を疑う** のが定石だ

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 1 通り足りない | `range(1 << n)` ではなく `range((1 << n) - 1)` にしている |
| 演算子の優先順位で誤動作 | Go で `mask>>i&1 == 1` は `(mask>>i)&1` の意味になる。迷ったら括弧を付ける |
| Go の順列が一部しか出ない | `nextPermutation` の前に **昇順ソート** していない |
| TLE | N=12 で順列全探索（12! ≒ 4.8×10^8） |

#### 和が K になる選び方を数える（bit 全探索）

→ [solutions/python/02/bit_search/](../solutions/python/02/bit_search/) / [solutions/go/02/bit_search/](../solutions/go/02/bit_search/)

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    count = 0
    for mask in range(1 << n):  # 0 〜 2^n - 1 の全部分集合
        s = 0
        for i in range(n):
            if mask >> i & 1:  # i ビット目が 1 なら a[i] を選ぶ
                s += a[i]
        if s == k:
            count += 1
    print(count)

if __name__ == "__main__":
    main()
```

#### 全都市を回る最短距離（順列全探索）

→ [solutions/python/02/permutation_search/](../solutions/python/02/permutation_search/) / [solutions/go/02/permutation_search/](../solutions/go/02/permutation_search/)

```python
import sys
from itertools import permutations

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    d = [list(map(int, input().split())) for _ in range(n)]
    best = 10**18
    # 都市 0 から出発し、残りの都市を回る順番をすべて試す
    for order in permutations(range(1, n)):
        cost = 0
        cur = 0
        for nxt in order:
            cost += d[cur][nxt]
            cur = nxt
        cost += d[cur][0]  # 都市 0 に戻る
        best = min(best, cost)
    print(best)

if __name__ == "__main__":
    main()
```

```go
// nextPermutation は p を辞書順で次の順列に並べ替える。最後の順列なら false を返す。
func nextPermutation(p []int) bool {
	i := len(p) - 2
	for i >= 0 && p[i] >= p[i+1] {
		i--
	}
	if i < 0 {
		return false
	}
	j := len(p) - 1
	for p[j] <= p[i] {
		j--
	}
	p[i], p[j] = p[j], p[i]
	for l, r := i+1, len(p)-1; l < r; l, r = l+1, r-1 {
		p[l], p[r] = p[r], p[l]
	}
	return true
}

// main の中（d は n×n の距離行列）
order := make([]int, 0, n-1)
for i := 1; i < n; i++ {
	order = append(order, i) // 昇順から始めると全順列を辿れる
}
best := 1 << 60
for {
	cost, cur := 0, 0
	for _, nxt := range order {
		cost += d[cur][nxt]
		cur = nxt
	}
	cost += d[cur][0] // 都市 0 に戻る
	if cost < best {
		best = cost
	}
	if !nextPermutation(order) {
		break
	}
}
fmt.Fprintln(out, best)
```

**霊夢**: 都市 0 を固定してるのはなぜ？

**魔理沙**: 巡回はどこから始めても同じ一周だから、出発点を固定すれば (N−1)! 通りで済む。**同じものを数えない工夫** は全探索でも効くぜ。

**推奨問題**: [abc128_c](https://atcoder.jp/contests/abc128/tasks/abc128_c)（bit 全探索、[解答](../solutions/python/02/abc128_c/)）、[abc167_c](https://atcoder.jp/contests/abc167/tasks/abc167_c)（bit 全探索 + 最小化、[解答](../solutions/python/02/abc167_c/)）、[abc145_c](https://atcoder.jp/contests/abc145/tasks/abc145_c)（順列全探索、[解答](../solutions/python/02/abc145_c/)）、[abc150_c](https://atcoder.jp/contests/abc150/tasks/abc150_c)（順列の番号、[解答](../solutions/python/02/abc150_c/)）

## 2.3 貪欲法（入門）

**霊夢**: 貪欲って、目の前で一番良さそうなのを選び続けるやつ？

**魔理沙**: その通り。証明は問題ごとだが、茶色までは **「ソートしてから順に取る」** パターンを覚えれば十分なことが多い。

### いつ使うか

| 問題の型 | 典型の貪欲 |
|----------|------------|
| 重ならない区間を最大個数 | **終了時刻が早い順** にソートして取る |
| コインでちょうど払う（この問題設定） | 大きい額面から |
| 「各要素を少しだけ変えて、並びを整えられるか」 | 左から見て、後ろが楽になる方を選ぶ（abc136_c） |

### 証明のイメージ（区間スケジューリング）

**霊夢**: なんで終了が早い順なの？ 開始が早い順じゃダメ？

**魔理沙**: 直感だけ言う。**早く終わる区間を選ぶと、あとに残る候補が一番多い** からだ。形式的には次の置き換え（交換論法）で説明できる。

1. 最適解のどれか 1 つを取り、そこに含まれる区間のうち **終了が最も早い** ものを `A` とする  
2. もし最適解が `A` を使っていなければ、`A` より遅く終わる区間 `B` と入れ替えてもまだ重ならない組が作れる（`A` の終了が早いので）  
3. よって「終了が最も早い区間を含む最適解」が存在する → 貪欲の 1 手目として `A` を選んでよい  
4. 残りも同じ議論を繰り返す  

**霊夢**: コインの大きい順は、いつも正しいの？

**魔理沙**: **一般のコイン額面では正しくない** 例がある（古典的な反例問題）。ただし AtCoder で「500, 100, 50…」と教科書的に出る設定では、問題文が **その貪欲でよい** と言っているか、証明済みの設定だ。迷ったら **小さい入力で総当たり** と比べる。

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 区間が 1 つ足りない | 半開区間 `[l,r)` と閉区間 `[l,r]` の **重なり判定** が違う |
| コインで WA | 額面が昇順でない、貪欲が最適でない設定なのに貪欲した |
| abc136_c で WA | 「下げられるなら下げる」と「下げると左より低くなる」の条件の順番 |

### 計算量

- ソート + 1 パス: **O(N log N)**  

### 区間スケジューリング（終了時刻が早い順）

**問題の型**: 区間 `[l, r)` がたくさん。重ならないように最大何個選べるか。

**魔理沙**: **終了時刻 `r` の昇順** にソートし、取れるものから貪欲に取る。

→ [solutions/python/02/greedy_intervals/](../solutions/python/02/greedy_intervals/) / [solutions/go/02/greedy_intervals/](../solutions/go/02/greedy_intervals/)

**入力例**:

```text
3
1 3
2 4
3 5
```

**Python**:

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    intervals = []
    for _ in range(n):
        l, r = map(int, input().split())
        intervals.append((l, r))
    intervals.sort(key=lambda x: x[1])  # 終了時刻でソート

    last = -10**18
    cnt = 0
    for l, r in intervals:
        if l >= last:  # 前の区間と重ならない（半開区間なら l >= last でよい例）
            cnt += 1
            last = r
    print(cnt)

if __name__ == "__main__":
    main()
```

**Go**:

```go
sort.Slice(intervals, func(i, j int) bool {
    return intervals[i].end < intervals[j].end
})
last := -1 << 60
cnt := 0
for _, iv := range intervals {
    if iv.start >= last {
        cnt++
        last = iv.end
    }
}
fmt.Println(cnt)
```

### 🖐️ abc136_c（左から貪欲）

→ [solutions/python/02/abc136_c/](../solutions/python/02/abc136_c/) / [solutions/go/02/abc136_c/](../solutions/go/02/abc136_c/)

**問題（要約）**: N 個のマスの高さが並んでいる。各マスについて「高さを 1 下げる」か「何もしない」を 1 回選ぶ。左から右へ **広義単調増加**（同じか増える）にできるか判定する（ABC C）。

> 💡 **ヒント**: 左から順に決めるとき、今のマスは「下げる」と「そのまま」のどちらにしておくと、右のマスが楽になる？
>
> ここで一度手を止めて、5〜10 分考えてみよう。この先は方針の説明とコードだ。

**霊夢**: 2^N 通り試すのは無理だよね……

**魔理沙**: 左から見て、**下げられるなら下げる** のが得だ。いまのマスを低くしておくほど、右のマスにとって条件がゆるくなるからな。下げると左より低くなる場合だけ、そのままにする。それでも左より低いなら No だ。

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    h = list(map(int, input().split()))
    prev = 0  # 直前のマスの（操作後の）高さ
    for x in h:
        if x - 1 >= prev:  # 下げても大丈夫なら下げる（後ろが楽になる）
            prev = x - 1
        elif x >= prev:  # 下げられないならそのまま
            prev = x
        else:
            print("No")
            return
    print("Yes")

if __name__ == "__main__":
    main()
```

**霊夢**: 「今を低くするほど後ろが楽」って、区間スケジューリングの「早く終わるほど後ろが楽」と似てるね。

**魔理沙**: そうだ。貪欲の正しさは **「この選び方をしても、後の選択肢が減らない」** で説明できることが多い。

## 2.4 二次元グリッド

**霊夢**: 迷路とか、マス目の問題も多いよね？

**魔理沙**: グリッドは **2 次元配列** で持つ。`H` 行 `W` 列、`grid[i][j]` は `i` 行目 `j` 列目（0-indexed）が競プロの約束だ。

### いつ使うか

| 問題文のヒント | 方針 |
|----------------|------|
| H×W のマス、迷路、地図 | `grid[i][j]` |
| 上下左右・4 近傍 | `di`, `dj` の配列 + 範囲チェック |
| 最短歩数・到達可能 | BFS（本節は予告、[03.md](03.md) で本格化） |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 行と列の取り違え | `(i,j)` と `(y,x)`、問題文の「縦 H・横 W」を再確認 |
| 範囲外 RE | `0 <= ni < H` を **両方** チェックしてから `grid[ni][nj]` |
| `#` と `.` の意味 | 問題文の記号定義どおり（壁と通路が逆の問題もある） |

**霊夢**: `grid[i][j]` の `i` が上から下？

**魔理沙**: 入力の **1 行目が `i=0`** になるのが一般的だ。問題文に「上から i 行目」とあれば、その通りに読む。

#### グリッドの読み方（Python）

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    h, w = map(int, input().split())
    grid = [list(input().strip()) for _ in range(h)]
    print(grid[0][0], grid[h - 1][w - 1])

if __name__ == "__main__":
    main()
```

#### 4 方向への移動

```python
# 上, 下, 左, 右

si, sj = 1, 0
for k in range(4):
    ni, nj = si + di[k], sj + dj[k]
    if 0 <= ni < H and 0 <= nj < W and grid[ni][nj] != "#":
        print("ok", ni, nj)
```

```go
di := []int{-1, 1, 0, 0}
dj := []int{0, 0, -1, 1}
ni, nj := si+di[k], sj+dj[k]
if 0 <= ni && ni < H && 0 <= nj && nj < W && grid[ni][nj] != '#' {
    // 移動可能
}
```

**霊夢**: `#` は壁？

**魔理沙**: 問題文の記号に従え。`.` は通れる、`#` は壁、という問題が多い。

#### グリッド上の BFS（おまけ）

茶色の C では **幅優先探索** が出始める。緑 Part で本格化するが、ここではイメージだけ。

```python
from collections import deque

def bfs(grid, si, sj):
    h, w = len(grid), len(grid[0])
    dist = [[-1] * w for _ in range(h)]
    dist[si][sj] = 0
    q = deque([(si, sj)])
    while q:
        i, j = q.popleft()
        for di, dj in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            ni, nj = i + di, j + dj
            if 0 <= ni < h and 0 <= nj < w and grid[ni][nj] != "#" and dist[ni][nj] == -1:
                dist[ni][nj] = dist[i][j] + 1
                q.append((ni, nj))
    return dist
```

## 2.5 累積和・差分（1 次元）

**霊夢**: 区間の和、毎回ループしたら遅くない？

**魔理沙**: **累積和** を作れば、区間 `[l, r]` の和を O(1) で求められる。茶色の C で超頻出だ。

### いつ使うか（累積和・差分）

| 問題文のヒント | 技法 |
|----------------|------|
| 区間 `[L,R]` の和を **何度も** 聞かれる | 累積和（前処理 O(N)、各クエリ O(1)） |
| 区間に +v を **何度も** 足す、最後に配列が欲しい | 差分配列 → 最後に 1 回累積和 |
| 固定長 k の部分列の和 | 累積和で `cum[r]-cum[l-1]`、またはスライディング |
| N, Q が 10^5 で「各クエリで区間和」 | 素朴な二重ループは TLE → 累積和 |

**霊夢**: 1-indexed の `cum[l-1]`、毎回ドキドキする……

**魔理沙**: **1-indexed で統一** するか、0-indexed で `cum[r+1]-cum[l]` に統一するか、どちらか一方をテンプレートに固定しろ。紙に `l=1,r=3` の小例で値を書いて確認する。

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 区間和が 1 ずれる | off-by-one（`cum[r]-cum[l-1]` の `l` が 1-indexed か） |
| 差分の結果がおかしい | `diff[r+1] -= v` の `+1` 忘れ、最後の累積和を取っていない |
| 累積和なのに TLE | クエリごとに `for` で区間を足している |

### 計算量

| 処理 | 目安 |
|------|------|
| 累積和の構築 | O(N) |
| 区間和 1 回 | O(1) |
| Q 回の区間和クエリ | O(N + Q) |
| 差分で区間加算 1 回 | O(1)、最後に O(N) で復元 |

#### 累積和（Python）

→ [solutions/python/02/prefix_sum/](../solutions/python/02/prefix_sum/) / [solutions/go/02/prefix_sum/](../solutions/go/02/prefix_sum/)

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))  # 1-indexed にする
    # cum[i] = a[1] + ... + a[i]
    cum = [0] * (n + 1)
    for i in range(1, n + 1):
        cum[i] = cum[i - 1] + a[i]

    for _ in range(q):
        l, r = map(int, input().split())
        print(cum[r] - cum[l - 1])  # 区間 [l, r] の和

if __name__ == "__main__":
    main()
```

**入力例**:

```text
5 3
1 2 3 4 5
1 3
2 4
5 5
```

**出力**:

```text
6
9
5
```

#### 累積和（Go）

```go
cum := make([]int, n+1)
for i := 1; i <= n; i++ {
    cum[i] = cum[i-1] + a[i]
}
// [l, r] の和
ans := cum[r] - cum[l-1]
```

#### 差分配列（区間に一括 +1）

**魔理沙**: 「区間 `[l,r]` に +v」を何度もやるとき、差分配列 `diff` で O(1) に記録し、最後に累積和で戻す。

→ [solutions/python/02/diff_array/](../solutions/python/02/diff_array/) / [solutions/go/02/diff_array/](../solutions/go/02/diff_array/)

```python
n = 5
diff = [0] * (n + 2)

def add_range(l: int, r: int, v: int) -> None:
    diff[l] += v
    diff[r + 1] -= v

add_range(1, 3, 10)  # 1..3 に +10
add_range(2, 5, 5)   # 2..5 に +5

a = [0] * (n + 1)
for i in range(1, n + 1):
    a[i] = a[i - 1] + diff[i]
print(a[1:])  # 最終配列
```

```go
diff := make([]int, n+2)
addRange := func(l, r, v int) {
    diff[l] += v
    diff[r+1] -= v
}
```

**霊夢**: 差分って、茶色で毎回使うの？

**魔理沙**: C 問題の「区間更新」で出る。累積和とセットで覚えろ。

## 2.6 集合・辞書・カウンタ

**霊夢**: 同じ数が何回出たか、ってどう数える？

**魔理沙**: **辞書 / カウンタ** を使う。Python は `collections.Counter` が便利だ。

### いつ使うか

| キーワード | 構造 |
|------------|------|
| 何回出現 / 最頻値 | `Counter` / `map` |
| 種類数 / 重複を除いた個数 | `set` |
| 値ごとに index をまとめる | `defaultdict(list)` |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| KeyError | 存在しないキーに `dict[k]`（`get` や `in` を使う） |
| 種類数が 1 多い | 空要素を数えている |
| Go で順序が欲しい | `map` は順不同 → ソートしてから出力 |

**霊夢**: `Counter` と手書き辞書、どっち？

**魔理沙**: 競プロでは **短い方** でよい。読みやすさ重視なら `Counter`、依存を避けたいなら `freq[x] = freq.get(x,0)+1` でも同じだ。

#### 頻度カウント（Python）

→ [solutions/python/02/counter_freq/](../solutions/python/02/counter_freq/) / [solutions/go/02/counter_freq/](../solutions/go/02/counter_freq/)

```python
from collections import Counter

xs = [1, 2, 2, 3, 3, 3]
cnt = Counter(xs)
print(cnt[2])        # 2
print(cnt.most_common(2))  # [(3, 3), (2, 2)]
```

```python
# 手動で辞書
freq = {}
for x in xs:
    freq[x] = freq.get(x, 0) + 1
```

#### 頻度カウント（Go）

```go

    freq[x]++
}
```

#### 集合で重複除去

```python

print(len(s))  # 3
```

```go
seen := map[int]struct{}{}

    seen[x] = struct{}{}
}
```

**魔理沙**: 「種類数」「出現回数が K 以上」はカウンタ、`defaultdict` で集約する問題も多い。

## 2.7 文字列処理

**霊夢**: 文字列、競プロだと何が出るの？

**魔理沙**: **辞書順**、**先頭・末尾**、**1 文字ずつシフト**、**部分列** の確認だ。茶色では全探索やソートと組み合わせる。

### いつ使うか

| 問題の型 | 方針 |
|----------|------|
| 辞書順で最小 / 最大の文字列 | 比較 `<` またはソート |
| シフト・ROT | `ord` と `% 26`（abc146_b） |
| 部分文字列の有無（短い） | `in` や全探索 |
| 長い文字列 × 多クエリ | 後の Part（ハッシュ、Z など） |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| シフトで文字化け | 大文字 / 小文字の範囲、`Z` の次を `A` にする `% 26` |
| 辞書順 WA | 数値を文字列として比較している（`"10" < "2"` など） |
| 末尾の改行 | `strip()` の有無で長さが変わる |

#### 辞書順の比較

```python
s = "abc"
t = "abcd"
print(s < t)  # True（先頭から比較）
```

#### 辞書順で小さい方を出力（abc152_b）

→ [solutions/python/02/abc152_b/](../solutions/python/02/abc152_b/) / [solutions/go/02/abc152_b/](../solutions/go/02/abc152_b/)

1 桁の整数 `a`, `b` について、「数字 `a` を `b` 個並べた文字列」と「数字 `b` を `a` 個並べた文字列」の **辞書順で小さい方** を出力する。

```python
import sys

def main() -> None:
    a, b = map(int, sys.stdin.readline().split())
    s = str(a) * b  # 数字 a を b 個
    t = str(b) * a  # 数字 b を a 個
    print(min(s, t))  # 文字列の min は辞書順で比べる

if __name__ == "__main__":
    main()
```

**霊夢**: 数として比べたら `444` より `3333` の方が大きいのに、`3333` が答えなんだ。

**魔理沙**: そこが **数値の比較と辞書順の違い** だ。辞書順は先頭の文字から比べるので、長さは関係ない。

#### 1 文字シフト（abc146_b）

→ [solutions/python/02/abc146_b/](../solutions/python/02/abc146_b/) / [solutions/go/02/abc146_b/](../solutions/go/02/abc146_b/)

大文字だけの文字列 `S` の各文字を `N` 文字後ろにずらす（`Z` の次は `A`）。

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    s = input().strip()
    ans = []
    for ch in s:
        c = (ord(ch) - ord("A") + n) % 26  # Z の次は A
        ans.append(chr(ord("A") + c))
    print("".join(ans))

if __name__ == "__main__":
    main()
```

```go
shift := func(ch byte, n int) byte {
    c := (int(ch-'A') + n) % 26 // Z の次は A
    return byte('A' + c)
}
```

## 2.8 座標圧縮（入門）

**霊夢**: 座標が 10 億とかで、配列に入らないって言うやつ？

**魔理沙**: **座標圧縮** は「値が大きいが、種類数は少ない」ときに、小さな番号に置き換える技法だ。ソートして重複除去し、**元の値 → 圧縮後の index** の写像を作る。

### いつ使うか

| 制約の見方 | 圧縮するか |
|------------|------------|
| 値 ≤ 10^9 だが **種類数 ≤ N（N≤10^5）** | ◎ 配列の添字に使う |
| 値そのものが 0〜N | 圧縮不要、そのまま添字 |
| 座標上のイベントを木で管理 | 圧縮してから Fenwick / セグ木（水色以降） |

### つまずき

| 症状 | 原因の例 |
|------|----------|
| index がずれる | `bisect_left` と `bisect_right` の違い（同値の扱い） |
| 重複を除き忘れ | `sorted(set(...))` を忘れて同じ値が複数 index になる |
| 元の値が必要 | 圧縮後だけ保持し、答え出力で元の座標が要る場合は **別配列** で保持 |

### 計算量

- 集める + ソート + 一意化: **O(N log N)**  
- 各値の圧縮: **O(log N)**（二分探索）または辞書で O(1)  

**霊夢**: 茶色の時点で、毎回 bisect まで要る？

**魔理沙**: まずは **手順を紙に書ける** ことが目標だ。本番では [solutions/python/02/compress_coords/](../solutions/python/02/compress_coords/) のテンプレートをコピーして使えばいい。

#### 手順

1. 使う値を集める  
2. ソートして重複を除く  
3. `bisect` や辞書で index を得る  

→ [solutions/python/02/compress_coords/](../solutions/python/02/compress_coords/) / [solutions/go/02/compress_coords/](../solutions/go/02/compress_coords/)

**Python**:

```python
import bisect

values = [10**9, 5, 10**9, 7, 5]
uniq = sorted(set(values))  # [5, 7, 10**9]

def compress(x: int) -> int:
    return bisect.bisect_left(uniq, x)  # 0-indexed の座標

print([compress(v) for v in values])  # [2, 0, 2, 1, 0]
```

**Go**:

```go
uniq := []int{5, 7, 1_000_000_000} // sorted unique
idx := sort.SearchInts(uniq, x)
```

**霊夢**: 何のためにつかうの？

**魔理沙**: 例えば「座標軸上のイベント」を Fenwick 木やセグ木で扱うとき、添字が小さくなる。水色以降で本番になるが、茶色では **「値が大きいが N は小さい」** と見たら思い出せ。
