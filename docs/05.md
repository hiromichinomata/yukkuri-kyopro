## 5.1 最小全域木・クラスカル

**霊夢**: [04.md](04.md) で DSU はやった。最小全域木って何？

**魔理沙**: **MST（最小全域木）** は、無向連結グラフで **すべての頂点をつなぎ、辺の重み和が最小** になる木のことだ。**クラスカル法** は辺を軽い順に見て、**閉路を作らなければ採用** する。採用判定は DSU の `unite` だけだ。

### イメージ

重い辺は後回しにして、軽い辺から「橋」を張る。2 本目で同じ 2 成分をつなごうとすると **閉路** になるのでスキップする。

| 手順 | 内容 |
|------|------|
| 1 | 辺を重み昇順にソート |
| 2 | 各辺 `(u,v,w)` で `unite(u,v)` が成功したら採用 |
| 3 | 採用辺の `w` を足す。`n-1` 本取れたら終了 |

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| すべての頂点を連結、重み和最小 | MST・クラスカル |
| 辺を削除して連結に | 逆は最大全域木等（応用） |
| 有向・流量 | フロー（5.4） |

### 計算量

| 処理 | 目安 |
|------|------|
| ソート + DSU | O(E log E) |

→ [solutions/python/05/kruskal/](../solutions/python/05/kruskal/) / [solutions/go/05/kruskal/](../solutions/go/05/kruskal/)（[04.md](04.md) の DSU を発展）

```python
def kruskal(n, edges):
    edges.sort(key=lambda e: e[2])
    dsu = DSU(n)
    total = 0
    used = 0
    for u, v, w in edges:
        if dsu.unite(u, v):
            total += w
            used += 1
            if used == n - 1:
                break
    return total
```

```go
func kruskal(n int, edges [][3]int, dsu *DSU) int {
    sort.Slice(edges, func(i, j int) bool { return edges[i][2] < edges[j][2] })
    total, used := 0, 0
    for _, e := range edges {
        if dsu.Unite(e[0], e[1]) {
            total += e[2]
            used++
            if used == n-1 {
                break
            }
        }
    }
    return total
}
```

**霊夢**: Prim 法は？

**魔理沙**: 頂点から **最小辺で広げる** 方法もある。密グラフでは Prim + ヒープが有利なこともあるが、競プロでは **クラスカル + DSU** がコピペしやすい。[04.md](04.md) の DSU テンプレをそのまま持ってこい。

## 5.2 最長共通部分列・最長増加部分列（応用）

**霊夢**: LIS、緑のときは O(N²) だったよね？

**魔理沙**: [03.md](03.md) の DP 版は N ≤ 2000 程度まで。**青色では LIS を O(N log N)** にするのが定番だ。`tails[i]` = 「長さ i+1 の LIS の末尾の最小値」 を `bisect` で更新する。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 最長増加部分列、LIS | tails + 二分 |
| 2 文字列、共通部分列 | LCS（O(NM) DP） |
| 転倒数、逆順対 | Fenwick + 座標圧縮 |

### 計算量

| 問題 | 目安 |
|------|------|
| LIS 長さ | O(N log N) |
| LCS 長さ | O(NM) |

### つまずき

- **LIS**: `bisect_left` で「x 以上の最小位置」— 厳密増加なら `left`、非減なら `right` など問題で変える。  
- **LCS**: DP 表は `(n+1)×(m+1)`、答えは `dp[n][m]`。

#### LIS（O(N log N)）

→ [solutions/python/05/lis_fast/](../solutions/python/05/lis_fast/) / [solutions/go/05/lis_fast/](../solutions/go/05/lis_fast/)

```python
import bisect

def lis_length(a):
    tails = []
    for x in a:
        i = bisect.bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)
```

```go
func lowerBound(a []int, x int) int {
    lo, hi := 0, len(a)
    for lo < hi {
        mid := (lo + hi) / 2
        if a[mid] < x {
            lo = mid + 1
        } else {
            hi = mid
        }
    }
    return lo
}

func lisLength(a []int) int {
    tails := []int{}
    for _, x := range a {
        i := lowerBound(tails, x)
        if i == len(tails) {
            tails = append(tails, x)
        } else {
            tails[i] = x
        }
    }
    return len(tails)
}
```

#### LCS（O(NM)）

→ [solutions/python/05/lcs/](../solutions/python/05/lcs/) / [solutions/go/05/lcs/](../solutions/go/05/lcs/)

```python
def lcs(s, t):
    n, m = len(s), len(t)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        for j in range(m):
            if s[i] == t[j]:
                dp[i + 1][j + 1] = dp[i][j] + 1
            else:
                dp[i + 1][j + 1] = max(dp[i + 1][j], dp[i][j + 1])
    return dp[n][m]
```

```go
func lcs(s, t string) int {
    n, m := len(s), len(t)
    dp := make([][]int, n+1)
    for i := range dp {
        dp[i] = make([]int, m+1)
    }
    for i := 0; i < n; i++ {
        for j := 0; j < m; j++ {
            if s[i] == t[j] {
                dp[i+1][j+1] = dp[i][j] + 1
            } else if dp[i+1][j] > dp[i][j+1] {
                dp[i+1][j+1] = dp[i+1][j]
            } else {
                dp[i+1][j+1] = dp[i][j+1]
            }
        }
    }
    return dp[n][m]
}
```

**魔理沙**: ARC B〜C では **LIS の長さ** や **LCS 風 DP** が、座標圧縮やセグ木（[04.md](04.md) 4.5）とセットで出る。復元が要るなら `dp` から親を辿る。

## 5.3 セグメントツリー（応用）— lazy propagation

**霊夢**: [04.md](04.md) のセグ木は、一点更新だけだった。

**魔理沙**: **区間に +v、区間和を聞く** には **遅延セグメントツリー（lazy propagation）** を使う。各ノードに **まだ子に降ろしていない加算値 `lazy`** を持たせ、必要なとき `_push` で子へ伝播する。

### 手順のイメージ

1. 区間がノード区間に **完全包含** → そのノードの `lazy` と `seg` を更新して return  
2. そうでなければ **push** してから左右の子を再帰  
3. クエリ前にも push して、古い lazy を残さない  

| 操作 | 内容 |
|------|------|
| `range_add(l, r, v)` | `[l,r)` に v を加える |
| `range_sum(l, r)` | `[l,r)` の和 |

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 区間に一律 +v、区間和 | lazy セグ木 |
| 区間の最大・最小 | lazy + max/min |
| 一点だけ更新 | 普通のセグ木 / Fenwick（[04.md](04.md)） |

### 計算量

| 操作 | 目安 |
|------|------|
| 区間加算・区間和 | O(log N) |

→ [solutions/python/05/segtree_lazy/](../solutions/python/05/segtree_lazy/) / [solutions/go/05/segtree_lazy/](../solutions/go/05/segtree_lazy/)

```python
class LazySegTree:
    """区間加算・区間和（サイズは 2 の冪）"""

    def __init__(self, data: list) -> None:
        n = 1
        while n < len(data):
            n <<= 1
        self.n = n
        self.seg = [0] * (2 * n)
        self.lazy = [0] * (2 * n)
        for i, v in enumerate(data):
            self.seg[n + i] = v
        for i in range(n - 1, 0, -1):  # 内部ノードも初期値から作る
            self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]

    def _apply(self, i: int, l: int, r: int, x: int) -> None:
        self.seg[i] += x * (r - l)
        self.lazy[i] += x

    def _push(self, i: int, l: int, r: int) -> None:
        if self.lazy[i] == 0 or i >= self.n:
            return
        m = (l + r) // 2
        x = self.lazy[i]
        self._apply(2 * i, l, m, x)
        self._apply(2 * i + 1, m, r, x)
        self.lazy[i] = 0

    def _pull(self, i: int) -> None:
        self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]

    def range_add(self, ql: int, qr: int, x: int, i: int = 1, l: int = 0, r: int | None = None) -> None:
        if r is None:
            r = self.n
        if qr <= l or r <= ql:
            return
        if ql <= l and r <= qr:
            self._apply(i, l, r, x)
            return
        self._push(i, l, r)
        m = (l + r) // 2
        self.range_add(ql, qr, x, 2 * i, l, m)
        self.range_add(ql, qr, x, 2 * i + 1, m, r)
        self._pull(i)

    def range_sum(self, ql: int, qr: int, i: int = 1, l: int = 0, r: int | None = None) -> int:
        if r is None:
            r = self.n
        if qr <= l or r <= ql:
            return 0
        if ql <= l and r <= qr:
            return self.seg[i]
        self._push(i, l, r)
        m = (l + r) // 2
        return self.range_sum(ql, qr, 2 * i, l, m) + self.range_sum(ql, qr, 2 * i + 1, m, r)
```

**霊夢**: 実装、長い……

**魔理沙**: テンプレを [solutions/](../solutions/python/05/segtree_lazy/) から持ち、問題に合わせて `max` や `min` に変える。ABC F / ARC C で差がつく。区間が **半開 `[l,r)`** か **閉 `[l,r]`** かはテンプレごとに固定し、コピペ後に取り違えないこと。

### つまずき

- **push 忘れ**: 子へ降りる直前に lazy を子へ落とす（`_push`）。  
- **初期値の内部ノード**: 葉に初期値を置いたら、親も `seg[2i] + seg[2i+1]` で作っておく。忘れると初期値が 0 以外のとき区間和がずれる。  
- **区間の長さ**: `seg[i] += lazy * (r - l)`（半開区間の幅）を忘れると WA。  
- **再帰の引数 `node, l, r`**: テンプレのまま使う。中身だけ `sum` → `max` に差し替え。

## 5.4 フロー入門・二部マッチング

**霊夢**: 最大流って、ネットワークの流れ？

**魔理沙**: 有向グラフで **源点 s から吸点 t へ、各辺の容量を超えずに送れる流量の最大** を求める。残り容量に **逆辺** を張るのがポイントで、増加路を何度か見つけて流を足す。

### イメージ

1. BFS で `s` から `t` へ残容量 > 0 の経路を探す（増加路）  
2. 経路上の最小残容量だけ流す  
3. 正方向の容量を減らし、逆方向の容量を増やす  
4. 増加路がなくなるまで繰り返す  

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 最大流、容量、源点・吸点 | Ford-Fulkerson / Dinic |
| マッチング、割当 | s-源・t-吸に還元 |
| 最小カット | 最大流 = 最小カット |

### 計算量

| 手法 | 目安 |
|------|------|
| Ford-Fulkerson（BFS） | O(VE^2) 程度（入門） |
| Dinic | O(V^2 E) など（本番向け） |

[04.md](04.md) の二分グラフ・マッチング入門から、ここで **容量** を扱えるようになる。

#### 増加路 BFS（入門）

→ [solutions/python/05/max_flow/](../solutions/python/05/max_flow/) / [solutions/go/05/max_flow/](../solutions/go/05/max_flow/)

```python
from collections import deque

def max_flow(cap, s, t, n):
    flow = 0
    while True:
        parent = [-1] * n
        parent[s] = s
        q = deque([s])
        while q:
            v = q.popleft()
            for to in range(n):
                if parent[to] == -1 and cap[v][to] > 0:
                    parent[to] = v
                    q.append(to)
        if parent[t] == -1:
            break
        # 増加路のボトルネック
        f = 10**18
        v = t
        while v != s:
            f = min(f, cap[parent[v]][v])
            v = parent[v]
        v = t
        while v != s:
            u = parent[v]
            cap[u][v] -= f
            cap[v][u] += f
            v = u
        flow += f
    return flow
```

```go
func maxFlow(cap [][]int, s, t, n int) int {
    flow := 0
    for {
        parent := make([]int, n)
        for i := range parent {
            parent[i] = -1
        }
        parent[s] = s
        q := []int{s}
        for head := 0; head < len(q); head++ {
            v := q[head]
            for to := 0; to < n; to++ {
                if parent[to] == -1 && cap[v][to] > 0 {
                    parent[to] = v
                    q = append(q, to)
                }
            }
        }
        if parent[t] == -1 {
            break
        }
        f := 1 << 60
        v := t
        for v != s {
            if cap[parent[v]][v] < f {
                f = cap[parent[v]][v]
            }
            v = parent[v]
        }
        v = t
        for v != s {
            u := parent[v]
            cap[u][v] -= f
            cap[v][u] += f
            v = u
        }
        flow += f
    }
    return flow
}
```

**最小カット**: 最大流 = 最小カット（s 側と t 側を分ける辺容量の和の最小）。「割り当て」「マッチング」に還元される問題が多い。

**霊夢**: 逆辺 `cap[v][u] += f` って、なんで必要？

**魔理沙**: 一度流した流を **やり直す** 余地を残すためだ。後から別経路と組み合わせて最適になる。

### 二部マッチング（最大流の特別な形）

**霊夢**: [04.md](04.md) の 4.8 で「左右でペアを作る問題はフローで」って言ってたよね。

**魔理沙**: **二部マッチング** は、左の頂点集合と右の頂点集合があり、辺で結ばれた左右をペアにする。**1 つの頂点は 1 回までしか使えない** とき、最大何組作れるかを求める問題だ。

**霊夢**: どうやってフローにするの？

**魔理沙**: 源点 s → 左の各頂点（容量 1）、左 → 右（元の辺、容量 1）、右の各頂点 → 吸点 t（容量 1）と張る。この **最大流 = 最大マッチング数** だ。容量がすべて 1 なので、上の BFS 版をそのまま使ってもいいが、もっと短く書ける **増加路 DFS**（Kuhn 法）が定番だ。

1. 左の頂点 u を順に見る  
2. u から行ける右の頂点 v を試す。v が空いていれば組む  
3. v がもう誰か（u'）と組んでいたら、u' を **別の右頂点に付け替えられないか** を再帰で試す。できれば v を u に譲ってもらう  
4. 付け替えの連鎖が成功したらマッチングが 1 増える（これがフローの「増加路」）

| キーワード | 候補 |
|------------|------|
| 「人と仕事を 1 対 1 で割り当てる」「最大何組」 | 二部マッチング |
| 二分グラフ（[04.md](04.md) 4.8）でペア作り | 二部マッチング |
| 割り当てにコストがある | 最小費用流（[06.md](06.md) 6.5） |

計算量: 増加路 DFS は **O(VE)**。V, E が 10^4 程度までが目安（それ以上は Dinic などの高速なフロー）。

→ [solutions/python/05/bipartite_matching/](../solutions/python/05/bipartite_matching/) / [solutions/go/05/bipartite_matching/](../solutions/go/05/bipartite_matching/)

```python
def max_matching(n_left: int, n_right: int, g: list) -> int:
    """二部グラフの最大マッチング（増加路 DFS、O(V E)）。g[u] は左 u から行ける右の頂点"""
    match_r = [-1] * n_right  # 右 v の相手（左の番号）、いなければ -1

    def try_kuhn(u: int, seen: list) -> bool:
        for v in g[u]:
            if seen[v]:
                continue
            seen[v] = True
            # v が空いている、または v の今の相手を別の右頂点に移せるなら u と組める
            if match_r[v] == -1 or try_kuhn(match_r[v], seen):
                match_r[v] = u
                return True
        return False

    result = 0
    for u in range(n_left):
        if try_kuhn(u, [False] * n_right):
            result += 1
    return result
```

```go
// maxMatching は二部グラフの最大マッチングを増加路 DFS で求める（O(VE)）。
// g[u] は左 u から行ける右の頂点。
func maxMatching(nLeft, nRight int, g [][]int) int {
	matchR := make([]int, nRight) // 右 v の相手（左の番号）、いなければ -1
	for i := range matchR {
		matchR[i] = -1
	}
	var seen []bool
	var try func(u int) bool
	try = func(u int) bool {
		for _, v := range g[u] {
			if seen[v] {
				continue
			}
			seen[v] = true
			// v が空いている、または v の今の相手を別の右頂点に移せるなら u と組める
			if matchR[v] == -1 || try(matchR[v]) {
				matchR[v] = u
				return true
			}
		}
		return false
	}
	result := 0
	for u := 0; u < nLeft; u++ {
		seen = make([]bool, nRight)
		if try(u) {
			result++
		}
	}
	return result
}
```

**霊夢**: `seen` を毎回作り直すのはなぜ？

**魔理沙**: 1 回の増加路探索の中で、同じ右頂点を 2 回試さないためのものだからだ。左の頂点ごとに新しい探索なので、リセットする。

## 5.5 ゲーム理論・Nim

**霊夢**: 先手必勝って、どう判定するの？

**魔理沙**: まず **Nim** を覚えろ。複数の山から任意個取れるゲームでは、各山の石数の **xor（ニム和）** が 0 なら **後手必勝**、そうでなければ **先手必勝** だ。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 石を取る、xor、先手後手 | Nim |
| 複数ゲームを同時に、合体 | Grundy 数の xor |
| グラフ上のゲーム | Grundy（難しめ） |

### 計算量

| 処理 | 目安 |
|------|------|
| Nim 判定 | O(山の個数) |

```python
def nim_xor(piles):
    x = 0
    for p in piles:
        x ^= p
    return "first" if x != 0 else "second"
```

```go
func nimXor(piles []int) string {
    x := 0
    for _, p := range piles {
        x ^= p
    }
    if x != 0 {
        return "first"
    }
    return "second"
}
```

#### Grundy 数（入門）

→ [solutions/python/05/grundy/](../solutions/python/05/grundy/) / [solutions/go/05/grundy/](../solutions/go/05/grundy/)

複数ゲームの合体は、各ゲームの Grundy 数を xor。 mex（最小非負整数不在）で定義する。

```python
def mex(s):
    m = 0
    while m in s:
        m += 1
    return m
```

**魔理沙**: ARC C では「ゲームを分解して xor」パターンが出る。完全把握は難しいが、**xor 思い出し** で方針が立つ。

## 5.6 文字列：ローリングハッシュ・KMP・Z アルゴリズム

**霊夢**: パターンマッチ、毎回 strcmp するの？

**魔理沙**: ナイーブだと O(NM)。**KMP** は失敗関数 `next`（いわゆる π 配列）を前計算し、テキストを 1 回走査して **O(N+M)** にする。**Z アルゴリズム** は「各位置からの最長共通接頭辞」を O(N) で出す。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|

| 手法 | 目安 |

| KMP | O(N+M) |

#### KMP

→ [solutions/python/05/kmp/](../solutions/python/05/kmp/) / [solutions/go/05/kmp/](../solutions/go/05/kmp/)

```python
def build_next(p):
    m = len(p)
    next_arr = [0] * m
    j = 0
    for i in range(1, m):
        while j > 0 and p[i] != p[j]:
            j = next_arr[j - 1]
        if p[i] == p[j]:
            j += 1
            next_arr[i] = j
    return next_arr

def kmp_search(text, pat):
    next_arr = build_next(pat)
    j = 0
    pos = []
    for i in range(len(text)):
        while j > 0 and text[i] != pat[j]:
            j = next_arr[j - 1]
        if text[i] == pat[j]:
            j += 1
        if j == len(pat):
            pos.append(i - len(pat) + 1)
            j = next_arr[j - 1]
    return pos
```

#### Z アルゴリズム

→ [solutions/python/05/z_algorithm/](../solutions/python/05/z_algorithm/) / [solutions/go/05/z_algorithm/](../solutions/go/05/z_algorithm/)

`Z[i]` = S と S[i:] の最長共通接頭辞長。構築 O(N)。

```python
def z_algorithm(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i <= r:
            z[i] = min(r - i + 1, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] - 1 > r:
            l, r = i, i + z[i] - 1
    return z
```

### ローリングハッシュ（部分文字列を O(1) で比較）

**霊夢**: 「s の区間 [l1, r1) と [l2, r2) が同じ文字列か」を何回も聞かれたら？

**魔理沙**: 毎回 1 文字ずつ比べると O(長さ) かかる。**ローリングハッシュ** は文字列を「BASE 進数の数」とみなして mod を取った値（ハッシュ）を前計算し、**どの部分文字列のハッシュも O(1)** で出す。ハッシュが等しければ（ほぼ確実に）同じ文字列だ。

**霊夢**: 部分文字列のハッシュがすぐ出るのはなぜ？

**魔理沙**: 累積和と同じ発想だ。`h[i]` を「先頭 i 文字のハッシュ」とすると、`s[l:r]` のハッシュは `h[r] − h[l] × BASE^(r−l)` になる。先頭 l 文字ぶんの値を、桁をそろえて引くイメージだ。

| 方針 | 理由 |
|------|------|
| mod は **2^61 − 1** | 大きい素数なので衝突しにくい。掛け算は 128 ビットで計算する |
| BASE は **実行のたびにランダム** | 固定値だと、衝突するように作られたテストで落ちることがある |
| 衝突の確率 | 比較 1 回あたり約 長さ / 2^61。10^6 回比べても実質 0 |

| キーワード | 候補 |
|------------|------|
| 部分文字列が等しいかを大量に判定 | ローリングハッシュ |
| 最長の繰り返し部分、回文判定（逆向きのハッシュと比較） | ローリングハッシュ + 二分探索 |
| パターン 1 個の出現位置を確実に | KMP / Z（衝突なし） |

→ [solutions/python/05/rolling_hash/](../solutions/python/05/rolling_hash/) / [solutions/go/05/rolling_hash/](../solutions/go/05/rolling_hash/)

```python
import random

MOD = (1 << 61) - 1
BASE = random.randrange(10**5, MOD - 1)  # 基数はランダムに選ぶ（狙い撃ちの衝突を防ぐ）

class RollingHash:
    def __init__(self, s: str) -> None:
        n = len(s)
        self.h = [0] * (n + 1)  # h[i] = s[0:i] のハッシュ
        self.pw = [1] * (n + 1)  # pw[i] = BASE^i
        for i, ch in enumerate(s):
            self.h[i + 1] = (self.h[i] * BASE + ord(ch)) % MOD
            self.pw[i + 1] = self.pw[i] * BASE % MOD

    def get(self, l: int, r: int) -> int:
        """s[l:r] のハッシュを O(1) で返す"""
        return (self.h[r] - self.h[l] * self.pw[r - l]) % MOD
```

```go
const hashMod = (1 << 61) - 1

// mulMod は a*b mod (2^61-1) を 128 ビットの積で計算する。
func mulMod(a, b uint64) uint64 {
	hi, lo := bits.Mul64(a, b)
	// 積 = hi*2^64 + lo。2^61 ≡ 1 なので、上位と下位 61 ビットを足せばよい
	res := (hi<<3 | lo>>61) + (lo & hashMod)
	if res >= hashMod {
		res -= hashMod
	}
	return res
}

type rollingHash struct {
	h, pw []uint64
}

func newRollingHash(s string, base uint64) *rollingHash {
	n := len(s)
	rh := &rollingHash{h: make([]uint64, n+1), pw: make([]uint64, n+1)}
	rh.pw[0] = 1
	for i := 0; i < n; i++ {
		rh.h[i+1] = (mulMod(rh.h[i], base) + uint64(s[i])) % hashMod
		rh.pw[i+1] = mulMod(rh.pw[i], base)
	}
	return rh
}

// get は s[l:r] のハッシュを O(1) で返す。
func (rh *rollingHash) get(l, r int) uint64 {
	return (rh.h[r] + hashMod - mulMod(rh.h[l], rh.pw[r-l])) % hashMod
}
```

**霊夢**: Go だけ `bits.Mul64` を使うのはなぜ？

**魔理沙**: 2^61 未満の数どうしの積は最大 2^122 で、64 ビットに収まらないからだ。Python は整数に上限がないので、そのまま掛けて mod を取れる。

## 5.7 座標幾何（入門）

**霊夢**: 凸包って、ゴムで囲んだ形？

**魔理沙**: 点集合を **凸な最小の多角形** で包むものだ。まず **CCW（外積の符号）** で向きを判定し、**Andrew の monotone chain** で凸包を O(N log N) で求める。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 凸包、包含、ゴム | monotone chain |
| 線分が交わるか | CCW の符号組 |
| 多角形の面積 | 靴ひも公式（別） |

### つまずき

- **CCW = 0**: 3 点が一直線。凸包では `<= 0` で pop するか問題次第。  
- **overflow**: 座標が大きいとき `int64`（Go）や Python のまま整数で。  
- **重複点**: `sorted(set(points))` で除く。

#### CCW

→ [solutions/python/05/ccw/](../solutions/python/05/ccw/) / [solutions/go/05/ccw/](../solutions/go/05/ccw/)

```python
def ccw(a, b, c):
    # >0: 反時計, <0: 時計, =0: 一直線
    return (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])
```

```go
func ccw(a, b, c [2]int) int {
    return (b[0]-a[0])*(c[1]-a[1]) - (b[1]-a[1])*(c[0]-a[0])
}
```

#### 凸包（Andrew の monotone chain）

→ [solutions/python/05/convex_hull/](../solutions/python/05/convex_hull/) / [solutions/go/05/convex_hull/](../solutions/go/05/convex_hull/)

```python
def convex_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points
    lower = []
    for p in points:
        while len(lower) >= 2 and ccw(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)
    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and ccw(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)
    return lower[:-1] + upper[:-1]
```

**魔理沙**: 線分交差は CCW の符号の組み合わせで判定する。ARC C の幾何は **実装ミス（整数 overflow）** に注意。Go は `int64` を使え。

## 5.8 確率・期待値 DP

**霊夢**: 確率 DP って、遷移に確率を掛けるの？

**魔理沙**: 状態 `dp[i]` を **確率** または **期待値** として、遷移先へ **確率で重み付け** して更新する。mod 問題では [04.md](04.md) の **逆元** で分数を扱う。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 確率、期待値、ランダム操作 | 確率 DP |
| mod 998244353 | 逆元で分数 |
| 浮動小数 OK | `float`（誤差注意） |

### つまずき

- **確率の和が 1** になる初期条件（`dp[0]=1` など）  
- **期待値**: `E = 1 + 平均(次状態の E)` の式を立てる  
- **mod**: 割りは逆元、足し算は mod のまま

```python
# 例: サイコロでちょうど n に到達する確率（表が 1..6）
def prob_reach(n, max_face=6):
    dp = [0.0] * (n + 1)
    dp[0] = 1.0
    for i in range(n):
        for f in range(1, max_face + 1):
            if i + f <= n:
                dp[i + f] += dp[i] / max_face
    return dp[n]
```

## 5.9 構築・考察入門

**霊夢**: ARC を見たら「条件を満たす数列を 1 つ出力せよ」って問題があったよ。アルゴリズムの名前がわからない……

**魔理沙**: それが **構築問題** だ。ARC・AGC では、知っているアルゴリズムを当てはめるより **自分で規則を見つける** 問題が多い。名前のある技法の代わりに、**考え方の型** を持っておく。

### 考察の型

| 型 | やること |
|----|----------|
| **小さいケースの実験** | N = 1, 2, 3, … を手や全探索で解き、答えの規則を見る |
| **不変量** | 操作をしても変わらない量（和の偶奇、xor、個数の差など）を探す。不変量が違えば「不可能」と言える |
| **必要条件から攻める** | 「少なくともこれは必要」を集め、それが十分かを確かめる |
| **極端な形を作る** | ソート済み、交互、全部同じ、など単純な形から作れないか考える |
| **逆から考える** | 最後の状態から操作を逆に辿る |

**霊夢**: 実験ってプログラムでやるの？

**魔理沙**: そうだ。**N が小さいときの全探索** を書いて、答えや「条件を満たす例」を並べて眺める。ここで [02.md](02.md) の 2.2 の順列全探索や bit 全探索が活きる。規則が見えたら、それを一般の N で作る構築を書き、**全探索の結果と突き合わせて** 確かめる。

### 例題: 隣の差がすべて異なる順列

**霊夢**: 「1〜N の順列で、隣り合う 2 つの差の絶対値がすべて異なるものを 1 つ出力せよ」だと？

**魔理沙**: 差は N−1 個あって、取りうる値は 1〜N−1 の N−1 種類しかない。つまり **差がちょうど 1, 2, …, N−1 を 1 回ずつ** 使う必要がある（必要条件）。差 N−1 は 1 と N が隣のときしか作れないので、1 と N を並べる。次に差 N−2 を作るには……と考えると、**1, N, 2, N−1, 3, …** と左右から交互に取る形が出てくる。差は N−1, N−2, …, 1 になる。

1. 必要条件「差は 1〜N−1 を 1 回ずつ」を見つける  
2. 一番大きい差から作る、という極端な形から攻める  
3. 構築を書いたら、**小さい N で全部確かめる**（下の `is_valid`）

→ [solutions/python/05/construction/](../solutions/python/05/construction/) / [solutions/go/05/construction/](../solutions/go/05/construction/)

```python
import sys
from itertools import permutations

def is_valid(p: list) -> bool:
    """隣り合う差の絶対値がすべて異なるか"""
    diffs = [abs(p[i + 1] - p[i]) for i in range(len(p) - 1)]
    return len(set(diffs)) == len(diffs)

def construct(n: int) -> list:
    """1, n, 2, n-1, 3, ... と左右から交互に取ると、差が n-1, n-2, ..., 1 になる"""
    res = []
    lo, hi = 1, n
    while lo <= hi:
        res.append(lo)
        if lo != hi:
            res.append(hi)
        lo += 1
        hi -= 1
    return res

def experiment(max_n: int) -> None:
    """小さい n で全探索し、条件を満たす順列の例と個数を見る（考察用）"""
    for n in range(1, max_n + 1):
        ok = [p for p in permutations(range(1, n + 1)) if is_valid(list(p))]
        print(f"n={n}: {len(ok)} 個, 例 {list(ok[0])}", file=sys.stderr)
```

```go
// isValid は隣り合う差の絶対値がすべて異なるかを返す。
func isValid(p []int) bool {
	seen := map[int]bool{}
	for i := 0; i+1 < len(p); i++ {
		d := p[i+1] - p[i]
		if d < 0 {
			d = -d
		}
		if seen[d] {
			return false
		}
		seen[d] = true
	}
	return true
}

// construct は 1, n, 2, n-1, ... と左右から交互に取る。差は n-1, n-2, ..., 1 になる。
func construct(n int) []int {
	res := []int{}
	for lo, hi := 1, n; lo <= hi; lo, hi = lo+1, hi-1 {
		res = append(res, lo)
		if lo != hi {
			res = append(res, hi)
		}
	}
	return res
}
```

### 例題: 不変量で「不可能」を示す

**霊夢**: 「できない」ときに -1 を出す問題は？

**魔理沙**: 不変量の出番だ。例えば「整数の列で、隣り合う 2 つを選んで両方に +1 する操作を好きなだけ行う。全部を 0 にできるか（最初は負の数もある）」なら、操作で **偶数番目の和 − 奇数番目の和** は変わらない（片方ずつ +1 されるから）。最初にこの値が 0 でなければ、絶対に全部 0 にはできない。
