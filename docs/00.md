## 0.2 競技プログラミングと AtCoder

**霊夢**: AtCoder ってサイトで、コンテストに出るの？

**魔理沙**: だ。主に次の 3 種類がある。

| コンテスト | 略称 | だいたいの難易度 | 本書での位置づけ |
|------------|------|------------------|------------------|
| AtCoder Beginner Contest | ABC | 初心者〜中級 | 灰色〜水色の主戦場 |
| AtCoder Regular Contest | ARC | 中級〜上級 | 緑〜橙色の橋渡し |
| AtCoder Grand Contest | AGC | 上級〜最上級 | 水色〜赤色 |

**霊夢**: レーティングの「色」って何？

**魔理沙**: 成績に応じて数値と色が付く。だいたい次の対応だ。

| 色 | レーティング目安 |
|----|------------------|
| 灰色 | 〜400 |
| 茶色 | 400〜800 |
| 緑 | 800〜1200 |
| 水色 | 1200〜1600 |
| 青 | 1600〜2000 |
| 黄 | 2000〜2400 |
| 橙 | 2400〜2800 |
| 赤 | 2800〜 |

### 1 問の流れ（提出と判定）

**霊夢**: 問題文を読んで、プログラムを書いて、送るだけ？

**魔理沙**: 流れはこうだ。

1. **問題文**を読む（入力形式・制約・出力）  
2. **ローカル**でサンプルケースを試す  
3. 言語を選んで **提出**  
4. ジャッジが複数ケースで実行し、**AC**（正解）か **WA**（不正解）などが返る  

**霊夢**: AC って何？

**魔理沙**: Accepted の略で「正解」だ。ほかによく見るのは次のとおり。

| 結果 | 意味 |
|------|------|
| AC | 正解 |
| WA | 出力が違う |
| TLE | 時間制限オーバー |
| MLE | メモリ制限オーバー |
| RE | 実行時エラー（例外・セグフォなど） |
| CE | コンパイルエラー |

### 入出力の約束（AtCoder 形式）

**魔理沙**: 競プロではだいたい **標準入力 → 計算 → 標準出力** だ。ファイル入出力や対話形式は問題ごとに文面で指定される。

**霊夢**: 例えば「2 つの整数を足して出力」だと？

**魔理沙**: 入力が次のとき、

```text
3 5
```

出力は `8` だ。余計な文字（`答え: 8` など）は **WA** になるから注意。

**霊夢**: じゃあ最初に書くプログラム、イメージできる？

**魔理沙**: 後で Python / Go のテンプレを載せる。まずは「読んで、計算して、1 行で出す」だけ覚えろ。

### つまずき（問題文の読み落とし）

| よくある誤解 | 正しい読み方 |
|--------------|--------------|
| サンプルだけ見て提出 | **制約**（N の上限、値の範囲）を必ず読む |
| 「整数」とだけ思う | 負の数・0・最大値が許されるか確認 |
| 出力に説明文を足す | 問題が指定した **形式だけ**（余計な空白・ラベルは WA） |
| AC したら終わり | 同じ問題を **別の入力**（境界）でもローカルで試す |

**霊夢**: 制約って、何のためにあるの？

**魔理沙**: 「このアルゴリズムで間に合うか」を見るためだ。Part 0 では深追いしなくていいが、**N が 10^5 なのに二重ループ** は後の Part で TLE になる、とだけ頭に入れておけ。

### 学習のコツ（コンテスト前）

1. 過去の **ABC A** を 1 問、解説を見ずに 20 分 → ダメなら解説 → **もう一度手で書く**  
2. WA のときは「サンプルは通るか」「出力の末尾改行」を先に疑う  
3. 言語は **1 つに決めて** 慣れる（もう一方は Part が進んでから見比べでよい）

### ローカルで「A + B」を試す（ハンズオン）

**霊夢**: 環境、できたか試したい！

```go
	fmt.Println(a + b)

```

## 0.4 言語選びと共通ルール（Python / Go）

**霊夢**: Python と Go、どっちを選べばいいの？

**魔理沙**: ざっくりこうだ。

| | Python | Go |
|---|--------|-----|
| 書きやすさ | ◎ 文法が短い | ○ 型がある |
| 実行速度 | △ 遅め（TLE に注意） | ◎ 速い |
| 競プロでの人気 | 高い | 高い |
| 本書 | 🐍 両方載せる | 🐹 両方載せる |

**霊夢**: 初心者は Python の方がやさしそう。

**魔理沙**: 最初は Python だけでもいい。遅いと感じたら Go を並べて読むとよい。本書は **同じ問題を両言語で見比べる** 前提だ。

### いつ使うか（テンプレの選び方）

| 状況 | Python | Go |
|------|--------|-----|
| 最初の 1 ヶ月・書く量を減らしたい | ◎ 基本テンプレから | 後回しでよい |
| N, Q が 10^5 級で TLE が出る | `readline` 版を確認 | ◎ `bufio` 版に寄せる |
| 深い DFS・再帰 | `setrecursionlimit` 版 | スタック版 or ループへ切替を検討 |
| 入力が 1 ブロックだけ | `read().split()` 版 | `Fscan` 連続でよい |

**霊夢**: 毎回どれをコピーすればいいの？

**魔理沙**: 迷ったら **基本テンプレ 1 種類** をエディタのスニペットに登録しろ。問題を読んでから「再帰」「一括読み」に差し替える、で十分だ。

### つまずき（テンプレ運用）

- `pass` のまま提出して CE …… **main の中身を書き忘れ**  
- デバッグ `print` を残して WA（稀）や遅延 …… 提出前に削除  
- Python で `input()` と `readline()` を混ぜて読み順が崩れる …… **どちらか一方** に統一  
- Go で `Scan` だけ使って TLE …… 本書の **`bufio` 版** に切り替え  

### 提出用テンプレート（コピーの起点）

**魔理沙**: 以降の Part でも使う骨組みだ。まずは **丸ごとコピーして、問題ごとに編集** しろ。

#### Python：基本テンプレート

```python
import sys

# よく使う定数
INF = 10**18
MOD = 998244353

def main() -> None:
    input = sys.stdin.readline
    # 例: 1 行に n
    # n = int(input())
    # 例: 1 行に n 個の整数
    # xs = list(map(int, input().split()))
    pass

if __name__ == "__main__":
    main()
```

#### Python：再帰が深い問題用（DFS など）

**魔理沙**: Python は再帰の深さにデフォルト上限がある。木の DFS などでは先に上げる。

```python
import sys

sys.setrecursionlimit(10**7)  # 問題に応じて調整

def dfs(v: int) -> None:
    ...

def main() -> None:
    ...

if __name__ == "__main__":
    main()
```

**霊夢**: `10**7` って、大きすぎない？

**魔理沙**: 制約とスタックオーバーフローのバランスで決める。まずは `10**6` 〜 `10**7` で試し、RE なら見直す、で十分だ。

#### Python：複数行をまとめて読む

```python
import sys

def main() -> None:
    data = sys.stdin.read().split()
    # data[0], data[1], ... が文字列
    # 整数にする例:
    # it = iter(data)
    # n = int(next(it))
    # xs = [int(next(it)) for _ in range(n)]
    pass

if __name__ == "__main__":
    main()
```

#### Go：基本テンプレート

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

const (
	inf int64 = 1 << 60
	mod int = 998244353
)

func main() {
	in := bufio.NewReader(os.Stdin)
	out := bufio.NewWriter(os.Stdout)
	defer out.Flush()

	// 例: var n int
	// fmt.Fscan(in, &n)
	// 例: xs := make([]int, n); for i := range xs { fmt.Fscan(in, &xs[i]) }
}
```

#### Go：1 行を読む・スペース区切り

```go
package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

func readInts(in *bufio.Reader, n int) []int {
	line, _ := in.ReadString('\n')
	fields := strings.Fields(strings.TrimSpace(line))
	xs := make([]int, n)
	for i := 0; i < n; i++ {
		xs[i], _ = strconv.Atoi(fields[i])
	}
	return xs
}

func main() {
	in := bufio.NewReader(os.Stdin)
	_ = readInts(in, 3) // 例: 3 整数 on one line
}
```

**霊夢**: `bufio` って、何のため？

**魔理沙**: 入出力を速くするためだ。Go は `fmt.Scan` だけだと遅くて TLE になることがある。本書の Go 例は基本 `bufio.Reader` / `Writer` を使う。

#### Go：再帰（DFS）

**魔理沙**: Go は Python みたいな `setrecursionlimit` はない。深い再帰はスタックオーバーフローに注意し、必要なら **明示スタック** や **メモ化 + ループ** に切り替える。

```go
func dfs(v int, g [][]int, seen []bool) {
	seen[v] = true
	for _, to := range g[v] {
		if !seen[to] {
			dfs(to, g, seen)
		}
	}
}
```

```python
def add_mod(a: int, b: int, mod: int = MOD) -> int:
```

### よくあるミス（提出前チェック）

**霊夢**: WA ばっかりになりそう……

**魔理沙**: 提出前に次を見る癖をつけろ。

| チェック | 内容 |
|----------|------|
| 出力形式 | 余計な文字・空白・改行すぎ |
| 末尾改行 | 問題によっては不要な `\n` も WA の原因 |
| 型 | Python で int は大丈夫、Go は `int` / `int64` の取り違え |
| オーバーフロー | Go は意識、Python は多倍長だが TLE は別問題 |
| 境界 | `n=0`, `n=1`, 最大値 |

```python
# Python: デバッグ（提出前に削除）
def debug(*args, **kwargs):

```

```go
// Go: デバッグ（提出前に削除）
func debug(args ...interface{}) {
	fmt.Fprintln(os.Stderr, args...)
}
```
