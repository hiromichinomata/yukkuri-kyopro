## 3.1 深さ優先探索・幅優先探索

**霊夢**: [02.md](02.md) でグリッドは読めるようになった。でも「最短の歩数」って、全探索じゃなくていいの？

**魔理沙**: いい質問だ。マス目で **1 マスずつ移動・全辺の重みが同じ** なら **BFS（幅優先探索）** が正解だ。はじめてそのマスに着いたときの距離が、自動的に最短になる。

### BFS のイメージ

BFS は「**波紋が広がる**」イメージだ。

1. スタートを距離 0 にする  
2. キューにスタートを入れる  
3. キューから 1 マス取り出し、その隣接マスへ距離 +1 で広げる  
4. まだ訪れていないマスだけキューに入れる  

`dist[i][j] == -1` を「未訪問」にすると、二重に入れるバグを防げる。

| 手法 | 向いていること | 使う構造 | 計算量の目安 |
|------|----------------|----------|--------------|
| **BFS** | 最短歩数、層ごとの処理 | キュー（`deque`） | O(HW) グリッド |
| **DFS** | 連結成分、経路の存在、バックトラック | 再帰 or スタック | O(HW) グリッド |

**霊夢**: DFS は最短には使えないの？

**魔理沙**: 重みのないグラフでも、DFS は **深く進んでから戻る** ので、最初に見つけた経路が最短とは限らない。ただし **「つながっているか」「何マスあるか（連結成分のサイズ）」** には DFS が手軽で強い。

### 問題文で BFS / DFS を疑うキーワード

| キーワード | 候補 |
|------------|------|
| 最短、最小手数、最小操作回数 | BFS |
| 連結、成分、島の数、到達可能 | DFS / BFS |
| 迷路、4 方向、8 方向 | BFS or DFS |
| 全パターン試す、組み合わせ | DFS + バックトラック（[01.md](01.md) の全探索と組み合わせ） |

#### グリッド BFS（Python）

→ [solutions/python/03/grid_bfs/](../solutions/python/03/grid_bfs/) / [solutions/go/03/grid_bfs/](../solutions/go/03/grid_bfs/)

```python
from collections import deque
import sys

def bfs(grid, si, sj):
    h, w = len(grid), len(grid[0])
    dist = [[-1] * w for _ in range(h)]
    dist[si][sj] = 0
    q = deque([(si, sj)])
    di = (-1, 1, 0, 0)
    dj = (0, 0, -1, 1)
    while q:
        i, j = q.popleft()
        for k in range(4):
            ni, nj = i + di[k], j + dj[k]
            if 0 <= ni < h and 0 <= nj < w and grid[ni][nj] != "#" and dist[ni][nj] == -1:
                dist[ni][nj] = dist[i][j] + 1
                q.append((ni, nj))
    return dist
```

```go
dist := make([][]int, h)
for i := range dist {
    dist[i] = make([]int, w)
    for j := range dist[i] {
        dist[i][j] = -1
    }
}
type pos struct{ i, j int }
q := []pos{{si, sj}}
dist[si][sj] = 0
di := []int{-1, 1, 0, 0}
dj := []int{0, 0, -1, 1}
for head := 0; head < len(q); head++ {
    p := q[head]
    for k := 0; k < 4; k++ {
        ni, nj := p.i+di[k], p.j+dj[k]
        if 0 <= ni && ni < h && 0 <= nj && nj < w &&
            grid[ni][nj] != '#' && dist[ni][nj] == -1 {
            dist[ni][nj] = dist[p.i][p.j] + 1
            q = append(q, pos{ni, nj})
        }
    }
}
```

#### DFS で連結成分のサイズ

「`.` の連結ブロックに何マスあるか」は DFS で 1 回の深掘りで数えられる。

→ [solutions/python/03/grid_dfs/](../solutions/python/03/grid_dfs/) / [solutions/go/03/grid_dfs/](../solutions/go/03/grid_dfs/)

```python
import sys

sys.setrecursionlimit(10**7)

def dfs(i, j, grid, seen):
    h, w = len(grid), len(grid[0])
    seen[i][j] = True
    size = 1
    for di, dj in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        ni, nj = i + di, j + dj
        if 0 <= ni < h and 0 <= nj < w and not seen[ni][nj] and grid[ni][nj] == ".":
            size += dfs(ni, nj, grid, seen)
    return size
```

```go
func dfsGrid(i, j int, grid [][]byte, seen [][]bool) int {
    h, w := len(grid), len(grid[0])
    seen[i][j] = true
    size := 1
    di := []int{-1, 1, 0, 0}
    dj := []int{0, 0, -1, 1}
    for k := 0; k < 4; k++ {
        ni, nj := i+di[k], j+dj[k]
        if 0 <= ni && ni < h && 0 <= nj && nj < w &&
            !seen[ni][nj] && grid[ni][nj] == '.' {
            size += dfsGrid(ni, nj, grid, seen)
        }
    }
    return size
}
```

**霊夢**: 再帰、深いと RE しない？

**魔理沙**: マス数が大きいと再帰深度も増える。[00.md](00.md) の `setrecursionlimit` を上げるか、**明示スタック** で DFS を書く（水色以降で詳しくする）。緑では「BFS = キュー」「DFS = 再帰 or スタック」の対応だけ押さえれば十分だ。

## 3.2 二分探索

**霊夢**: ソート済みの配列から、○以上の最小値を探す……二分って、半分に割るやつ？

**魔理沙**: その通り。緑では **2 種類** を分けて覚える。

| 種類 | 何を探すか | 前提 |
|------|------------|------|
| **配列の二分** | ソート済み配列の位置 | 配列が昇順 |
| **答えの二分** | 整数 `x` の最大/最小 | `check(x)` が単調（偽→偽→…→真→真 など） |

### 配列の二分（lower_bound）

「`x` **以上** の最小の要素の位置」がよく出る。Python なら `bisect.bisect_left`、自前なら **(ng, ok) パターン** で書く。

- `ng`: 常に条件を満たさない側（例: -1）  
- `ok`: 常に満たす側の候補（例: len(a)）  
- ループ終了後の `ok` が答え  

**霊夢**: `bisect_left` と `bisect_right` の違いは？

**魔理沙**: 同じ値が並ぶとき、`left` は **左端**、`right` は **右端の次** だ。例: `[1,3,3,5]` で 3 を探すと `left=1`, `right=3` になる。

#### lower_bound 相当（Python）

→ [solutions/python/03/lower_bound/](../solutions/python/03/lower_bound/) / [solutions/go/03/lower_bound/](../solutions/go/03/lower_bound/)

```python
import bisect

a = [1, 3, 3, 5, 7]
i = bisect.bisect_left(a, 4)  # 4 以上の最小位置 → 3（値 5）
```

```python
def lower_bound(a, x):
    ng, ok = -1, len(a)
    while ok - ng > 1:
        mid = (ok + ng) // 2
        if a[mid] >= x:
            ok = mid
        else:
            ng = mid
    return ok
```

```go
func lowerBound(a []int, x int) int {
    ng, ok := -1, len(a)
    for ok-ng > 1 {
        mid := (ok + ng) / 2
        if a[mid] >= x {
            ok = mid
        } else {
            ng = mid
        }
    }
    return ok
}
```

### 答えの二分

「`x` 以下なら可能」が単調なら、**最大の可能な x** を探せる。典型は **最小の最大値**・**最大の最小値** 問題。

手順:

1. `check(x)` を書く（x で制約を満たすか）  
2. 探索範囲 `[lo, hi]` を決める（広めでよい）  
3. `ng, ok` で最大 `x` を取る（[solutions/python/03/binary_search_answer/](../solutions/python/03/binary_search_answer/) 参照）  

**霊夢**: `mid = (ok + ng) // 2` と `// 2` の違い、またややこしい……

**魔理沙**: **最大値を探す** ときは `mid = (ok + ng + 1) // 2` にして無限ループを避ける。テンプレを [solutions/](../solutions/python/03/binary_search_answer/) からコピーして、中身の `check` だけ差し替えるのが安全だ。

```python
def check(x: int) -> bool:
    ...

def max_ok(lo: int, hi: int) -> int:
    ng, ok = lo - 1, hi
    while ok - ng > 1:
        mid = (ok + ng + 1) // 2
        if check(mid):
            ok = mid
        else:
            ng = mid
    return ok
```

```go
ok, ng := hi, lo-1
for ok-ng > 1 {
    mid := (ok + ng + 1) / 2
    if check(mid) {
        ok = mid
    } else {
        ng = mid
    }
}
```

## 3.3 スタック・キュー・deque

**霊夢**: BFS はキューって言ってたよね。スタックは何に使うの？

**魔理沙**: **キュー（FIFO）** は「先に入れたものから処理」、**スタック（LIFO）** は「後に入れたものから処理」だ。データ構造の **使い分け** が緑のポイントになる。

| 構造 | 性質 | 競プロでの典型 |
|------|------|----------------|
| キュー | 先入れ先出し | BFS、トポロジカルソート |
| スタック | 後入れ先出し | 括弧の対応、DFS、単調スタック |
| deque | 両端 O(1) | スライディングウィンドウ、BFS |

### 括弧の対応（スタック）

アルゴリズム:

1. 開き括弧 `(` `[` `{` → push  
2. 閉じ括弧 → スタック top とペアか確認 → pop  
3. 最後にスタックが空なら合法  

→ [solutions/python/03/stack_brackets/](../solutions/python/03/stack_brackets/) / [solutions/go/03/stack_brackets/](../solutions/go/03/stack_brackets/)

```python
def valid_parentheses(s: str) -> bool:
    st = []
    pair = {")": "(", "]": "[", "}": "{"}
    for ch in s:
        if ch in "([{":
            st.append(ch)
        elif ch in ")]}":
            if not st or st[-1] != pair[ch]:
                return False
            st.pop()
        else:
            return False
    return len(st) == 0
```

```go
st := []byte{}
pair := map[byte]byte{')': '(', ']': '[', '}': '{'}
for i := 0; i < len(s); i++ {
    ch := s[i]
    if ch == '(' || ch == '[' || ch == '{' {
        st = append(st, ch)
    } else if ch == ')' || ch == ']' || ch == '}' {
        if len(st) == 0 || st[len(st)-1] != pair[ch] {
            return false
        }
        st = st[:len(st)-1]
    } else {
        return false
    }
}
return len(st) == 0
```

### スライディングウィンドウ（deque）

「長さ `k` の連続部分列」について、**毎ステップで 1 要素入れ 1 要素出す** と O(N) で済む。二重ループだと O(Nk) になる。

→ [solutions/python/03/deque_window/](../solutions/python/03/deque_window/) / [solutions/go/03/deque_window/](../solutions/go/03/deque_window/)

```python
from collections import deque

def max_sum_k(xs, k):
    q = deque()
    s = 0
    ans = -10**18
    for i, x in enumerate(xs):
        s += x
        q.append(i)
        if len(q) > k:
            s -= xs[q.popleft()]
        if i >= k - 1:
            ans = max(ans, s)
    return ans
```

```go
func maxSumK(xs []int, k int) int {
    s, ans := 0, -1<<60
    left := 0
    for right, x := range xs {
        s += x
        if right-left+1 > k {
            s -= xs[left]
            left++
        }
        if right-left+1 == k && s > ans {
            ans = s
        }
    }
    return ans
}
```

**霊夢**: [02.md](02.md) の累積和と何が違う？

**魔理沙**: 累積和は **区間和を O(1)** で取るのが得意。ウィンドウは **長さ固定で右端だけ動かす** ときに向く。問題が「長さ k の最大和」ならどちらも使えるが、**条件が複雑（例: 種類数 ≤ 2）** なら deque + 辞書のウィンドウが出やすい。

## 3.4 動的計画法（入門）

**霊夢**: DP って、何をメモするの？ 再帰と何が違うの？

**魔理沙**: **同じ部分問題を何度も解かない** のが DP だ。再帰でもメモ化すれば DP になる。緑では **表（配列）に状態を書く** 書き方を覚える。

### DP を立てる 3 ステップ

1. **状態**: `dp[i]` や `dp[i][j]` が何を表すか（例: 「i 番目まで見たときの最良値」）  
2. **遷移**: 小さい問題から大きい問題へ（ループの順序）  
3. **初期値**: 空・0 マス・重さ 0 など  

| 名前 | 状態の例 | 遷移の意味 | 計算量 |
|------|----------|------------|--------|
| 01 ナップサック | `dp[c]` = 重さ c 以下の最大価値 | 品 i を入れる / 入れない | O(N·W) |
| LIS | `dp[i]` = 末尾 i の LIS 長 | j < i かつ a[j] < a[i] | O(N²) |
| 経路数 | `dp[i][j]` = マス (i,j) への経路数 | 上・左から来る | O(HW) |

### 01 ナップサック — なぜ逆順か

同一品を **2 回使ってしまう** のを防ぐため、`c` を **大きい方から** 更新する（1 次元圧縮 DP）。

→ [solutions/python/03/knapsack/](../solutions/python/03/knapsack/) / [solutions/go/03/knapsack/](../solutions/go/03/knapsack/)

```python
def knapsack(weights, values, cap):
    n = len(weights)
    dp = [0] * (cap + 1)
    for i in range(n):
        w, v = weights[i], values[i]
        for c in range(cap, w - 1, -1):  # 逆順が重要
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]
```

```go
dp := make([]int, cap+1)
for i := 0; i < n; i++ {
    w, v := weights[i], values[i]
    for c := cap; c >= w; c-- {
        if dp[c-w]+v > dp[c] {
            dp[c] = dp[c-w] + v
        }
    }
}
```

### LIS（最長増加部分列）

「strictly increasing」の長さ。O(N²) は緑の上限で十分。水色以降で **O(N log N)**（ patience sorting ）に速くできる。

→ [solutions/python/03/lis/](../solutions/python/03/lis/) / [solutions/go/03/lis/](../solutions/go/03/lis/)

```python
def lis(a):
    n = len(a)
    dp = [1] * n
    for i in range(n):
        for j in range(i):
            if a[j] < a[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)
```

```go
func lis(a []int) int {
    n := len(a)
    dp := make([]int, n)
    for i := 0; i < n; i++ {
        dp[i] = 1
    }
    for i := 0; i < n; i++ {
        for j := 0; j < i; j++ {
            if a[j] < a[i] && dp[j]+1 > dp[i] {
                dp[i] = dp[j] + 1
            }
        }
    }
    ans := 0
    for _, v := range dp {
        if v > ans {
            ans = v
        }
    }
    return ans
}
```

### 経路数（右・下のみ）

障害物マスは `dp=0`。到達不能なら 0、スタートが障害物なら 0。

→ [solutions/python/03/dp_paths/](../solutions/python/03/dp_paths/) / [solutions/go/03/dp_paths/](../solutions/go/03/dp_paths/)

```python
def paths(h, w, blocked):
    dp = [[0] * w for _ in range(h)]
    dp[0][0] = 0 if blocked[0][0] else 1
    for i in range(h):
        for j in range(w):
            if blocked[i][j]:
                dp[i][j] = 0
                continue
            if i:
                dp[i][j] += dp[i - 1][j]
            if j:
                dp[i][j] += dp[i][j - 1]
    return dp[h - 1][w - 1]
```

```go
dp := make([][]int, h)
for i := range dp {
    dp[i] = make([]int, w)
}
if !blocked[0][0] {
    dp[0][0] = 1
}
for i := 0; i < h; i++ {
    for j := 0; j < w; j++ {
        if blocked[i][j] {
            dp[i][j] = 0
            continue
        }
        if i > 0 {
            dp[i][j] += dp[i-1][j]
        }
        if j > 0 {
            dp[i][j] += dp[i][j-1]
        }
    }
}
```

### 🖐️ abc137_d 相当（スケジュール DP）

→ [solutions/python/03/abc137_d/](../solutions/python/03/abc137_d/) / [solutions/go/03/abc137_d/](../solutions/go/03/abc137_d/)

**霊夢**: DP か貪欲か、どう見分ける？

**魔理沙**: **「前の選択が後の選択を制限する」** ときは DP を疑う。単純に「いま一番おいしい」を取れるなら貪欲（[02.md](02.md)）。締切・容量・回数制限が絡むと DP になりやすい。

## 3.5 グラフの基礎

**霊夢**: グラフって、線でつながった点？

**魔理沙**: **頂点（ノード）** と **辺** の集合だ。競プロではほぼ **隣接リスト** で持つ。頂点数 N、辺数 M なら **O(N + M)** で走査できる。

### 隣接リスト vs 隣接行列

| 表現 | 空間 | 辺 (u,v) の有無 |
|------|------|-----------------|
| 隣接リスト | O(N + M) | 隣接リストを走査 |
| 隣接行列 | O(N²) | O(1) だが N が大きいと使えない |

N ≤ 10⁵ 級ではリスト一択に近い。

#### 無向・有向

- **無向**: `g[u].append(v)` と `g[v].append(u)`  
- **有向**: `g[u].append(v)` のみ（一方通行）  

問題文の「双方向」「一方通行」を読み違えると WA になる。

→ [solutions/python/03/graph_adj_list/](../solutions/python/03/graph_adj_list/) / [solutions/go/03/graph_adj_list/](../solutions/go/03/graph_adj_list/)

```python
n, m = 5, 4
g = [[] for _ in range(n)]
edges = [(0, 1), (0, 2), (1, 3), (2, 4)]
for u, v in edges:
    g[u].append(v)
    g[v].append(u)  # 無向
```

```go
g := make([][]int, n)
for _, e := range edges {
    u, v := e[0], e[1]
    g[u] = append(g[u], v)
    g[v] = append(g[v], u)
}
```

### 木（tree）の DFS

木は **辺が N-1 本の連結グラフ**。DFS で `parent` と `depth` を付けると、「LCA」「部分木」の準備になる（黄色で本格化）。

→ [solutions/python/03/tree_dfs/](../solutions/python/03/tree_dfs/) / [solutions/go/03/tree_dfs/](../solutions/go/03/tree_dfs/)

```python
import sys

sys.setrecursionlimit(10**7)

def dfs(v, parent, g, depth):
    depth[v] = depth[parent] + 1 if parent != -1 else 0
    for to in g[v]:
        if to == parent:
            continue
        dfs(to, v, g, depth)
```

```go
func dfs(v, parent int, g [][]int, depth []int) {
    if parent == -1 {
        depth[v] = 0
    } else {
        depth[v] = depth[parent] + 1
    }
    for _, to := range g[v] {
        if to == parent {
            continue
        }
        dfs(to, v, g, depth)
    }
}
```

**霊夢**: グラフとグリッド、同じ？

**魔理沙**: グリッドも **各マスを頂点、隣接を辺** とみなせばグラフだ。BFS/DFS のコードはほぼ同じ。座標 `(i,j)` を頂点番号 `i*w+j` に直す問題もある。

## 3.6 トポロジカルソート

**霊夢**: 依存関係があるタスクの順番……先に A を終わらないと B できない、みたいな？

**魔理沙**: それを辺 `A → B`（A のあと B）で表す。**有向閉路がない（DAG）** ときだけ、線形順序に並べられる。それが **トポロジカルソート** だ。

### Kahn 法（入次数）

1. 各頂点の **入次数**（入ってくる辺の数）を数える  
2. 入次数 0 の頂点をキューへ  
3. キューから取り出し、答えに追加、出辺で隣の入次数を 1 減らす  
4. 新たに 0 になった頂点をキューへ  
5. 最後に答えの長さが N でなければ **閉路あり**（ソート不可）  

→ [solutions/python/03/topological_sort/](../solutions/python/03/topological_sort/) / [solutions/go/03/topological_sort/](../solutions/go/03/topological_sort/)

```python
from collections import deque

def topological_sort(n, g, indeg):
    q = deque([i for i in range(n) if indeg[i] == 0])
    order = []
    while q:
        v = q.popleft()
        order.append(v)
        for to in g[v]:
            indeg[to] -= 1
            if indeg[to] == 0:
                q.append(to)
    return order if len(order) == n else []
```

```go
q := []int{}
for i := 0; i < n; i++ {
    if indeg[i] == 0 {
        q = append(q, i)
    }
}
order := []int{}
for head := 0; head < len(q); head++ {
    v := q[head]
    order = append(order, v)
    for _, to := range g[v] {
        indeg[to]--
        if indeg[to] == 0 {
            q = append(q, to)
        }
    }
}
// len(order) != n なら閉路あり
```

**霊夢**: 順序が複数あるときは？

**魔理沙**: 「どれでもよい」問題が多い。指定があるなら **優先度付きキュー** で辞書順最小などを取る。緑では Kahn 法までで十分だ。

## 3.7 組み合わせの基礎

**霊夢**: nCr とか、mod で余りを取るやつ？ なんで組み合わせが出てくるの？

**魔理沙**: **順列・組み合わせを全部列挙** すると階乗で爆発する。式で数えるとき **nCr** が効く。例: N 個から K 個選ぶ方法は C(N,K)。

### パスカルの三角形

漸化式: C(i,j) = C(i-1,j-1) + C(i-1,j)。mod 素数なら各ステップで `% MOD` する。

→ [solutions/python/03/ncr/](../solutions/python/03/ncr/) / [solutions/go/03/ncr/](../solutions/go/03/ncr/)

```python
MOD = 998244353

def build_nCr(n, mod=MOD):
    c = [[0] * (n + 1) for _ in range(n + 1)]
    c[0][0] = 1
    for i in range(1, n + 1):
        c[i][0] = c[i][i] = 1
        for j in range(1, i):
            c[i][j] = (c[i - 1][j - 1] + c[i - 1][j]) % mod
    return c
```

```go
const mod = 998244353

func buildNCR(n int) [][]int {
    c := make([][]int, n+1)
    for i := 0; i <= n; i++ {
        c[i] = make([]int, n+1)
    }
    c[0][0] = 1
    for i := 1; i <= n; i++ {
        c[i][0], c[i][i] = 1, 1
        for j := 1; j < i; j++ {
            c[i][j] = (c[i-1][j-1] + c[i-1][j]) % mod
        }
    }
    return c
}
```

### 逆元（フェルマの小定理）

mod が素数 `p` のとき、`a^(-1) ≡ a^(p-2) (mod p)`。割り算 `a/b` は `a * inv(b) % p` にする。

```python
def mod_pow(a, e, mod=MOD):
    res = 1
    while e:
        if e & 1:
            res = res * a % mod
        a = a * a % mod
        e >>= 1
    return res

def mod_inv(a, mod=MOD):
    return mod_pow(a, mod - 2, mod)
```

```go
func modPow(a, e, mod int) int {
    res := 1
    a %= mod
    for e > 0 {
        if e&1 == 1 {
            res = res * a % mod
        }
        a = a * a % mod
        e >>= 1
    }
    return res
}

func modInv(a, mod int) int {
    return modPow(a, mod-2, mod)
}
```

**霊夢**: 水色でまた出てくる？

**魔理沙**: [04.md](04.md) で **階乗テーブル + 逆元テーブル** から O(1) で nCr を取る。緑ではパスカルか、小さい N 用の表まででよい。

## 3.8 優先度付きキュー（ダイクストラ入門）

**霊夢**: ヒープって、最小値がすぐ取れるやつ？ BFS と何が違う？

**魔理沙**: BFS は **辺の重みが全部 1** のときの最短。辺に **非負のコスト** があると **ダイクストラ** だ。毎回「いま一番距離が短い頂点」から広げる **貪欲** が正しい（非負が前提）。

### ダイクストラの流れ

1. `dist[start] = 0`、他は INF  
2. ヒープに `(0, start)` を入れる  
3. 最小の `(d, v)` を pop。すでに古い距離なら skip  
4. 隣接 `to` について `d + cost` で緩和（短くなったら push）  

計算量: O((N + M) log N) 程度（ヒープ実装）。

→ [solutions/python/03/dijkstra/](../solutions/python/03/dijkstra/) / [solutions/go/03/dijkstra/](../solutions/go/03/dijkstra/)

```python
import heapq

def dijkstra(g, start, n):
    INF = 10**18
    dist = [INF] * n
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, v = heapq.heappop(pq)
        if d > dist[v]:
            continue
        for to, cost in g[v]:
            nd = d + cost
            if nd < dist[to]:
                dist[to] = nd
                heapq.heappush(pq, (nd, to))
    return dist
```

```go
import (
    "container/heap"
)

type edge struct{ to, cost int }
type item struct{ d, v int }
type pq []item

func (h pq) Len() int            { return len(h) }
func (h pq) Less(i, j int) bool  { return h[i].d < h[j].d }
func (h pq) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *pq) Push(x interface{})  { *h = append(*h, x.(item)) }
func (h *pq) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func dijkstra(g [][]edge, start, n int) []int {
    const INF = int(1e18)
    dist := make([]int, n)
    for i := range dist {
        dist[i] = INF
    }
    dist[start] = 0
    h := &pq{}
    heap.Init(h)
    heap.Push(h, item{0, start})
    for h.Len() > 0 {
        it := heap.Pop(h).(item)
        d, v := it.d, it.v
        if d > dist[v] {
            continue
        }
        for _, e := range g[v] {
            nd := d + e.cost
            if nd < dist[e.to] {
                dist[e.to] = nd
                heap.Push(h, item{nd, e.to})
            }
        }
    }
    return dist
}
```

**霊夢**: 負の辺があるときは？

**魔理沙**: ダイクストラは使えない。0-1 BFS（辺コスト 0 or 1）やベルマン・フォードは [04.md](04.md) 以降。緑では **非負コスト + ダイクストラ** だけ覚えろ。

**霊夢**: 同じ頂点がヒープに何度も入るのは無駄じゃない？

**魔理沙**: 実装では `if d > dist[v]: continue` で **古いエントリを捨てる**（遅延削除）。コードは少し冗長に見えるが、定数倍で速くて定番だ。
