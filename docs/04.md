## 4.1 Union-Find（DSU）

**霊夢**: グループの合体・同じグループか判定って、毎回 DFS するの？

**魔理沙**: 毎回 DFS だと辺を M 本処理するたびに **O(N)** かかって全体 **O(NM)** になりがちだ。**Union-Find（DSU: Disjoint Set Union）** なら、ほぼ **逆アッカーマン** で `find` と `unite` が高速だ。

**霊夢**: 逆アッカーマンって、実質定数？

**魔理沙**: 競プロの制約（N ≤ 10^6 程度）では **定数扱いで十分** だと思え。大事なのは **経路圧縮** と **サイズでマージ** の 2 つだ。

### DSU のイメージ

各頂点が **親ポインタ** で木を作る。`find(x)` は根まで辿り、**同じ根なら同じグループ** だ。

1. 初期: 各 `parent[i] = i`  
2. `unite(a, b)`: それぞれの根を見て、別グループなら **小さい木を大きい木にぶら下げる**  
3. `same(a, b)`: `find(a) == find(b)`  

| 操作 | 意味 |
|------|------|
| `find(x)` | x の代表元（根） |
| `unite(a, b)` | a と b のグループを合体（成功したら `True`） |
| `same(a, b)` | 同じグループか |

### 問題文で DSU を疑うキーワード

| キーワード | 候補 |
|------------|------|
| 連結、同じグループ、友達関係の合体 | DSU |
| 辺を足していき閉路を作らない | クラスカル（[5.1](05.md)） |
| クエリで合体・同グループの個数 | DSU + `size` |
| グリッドの連結成分（一回きり） | DFS/BFS（[03.md](03.md)）でも可 |

### 計算量

| 操作 | 目安 |
|------|------|
| `find` / `unite` | ほぼ O(α(N))（実質定数級） |
| M 本の辺を処理 | O(M α(N)) |

### つまずき

- **ルートの取り違え**: `parent[x] = x` のときが根。`find` の戻り値を `unite` の引数に使う。  
- **サイズ忘れ**: 深い木になると遅くなる。**小さい方を大きい方にマージ** する。  
- **0-indexed / 1-indexed**: 頂点番号が 1 始まりなら DSU のサイズを `N+1` にするか、入力で `-1` する。

[03.md](03.md) の連結成分 DFS と違い、DSU は **動的にグループが合体していく** ときに強い。[02.md](02.md) のグリッド連結は「一度見るだけ」なら DFS でも足りるが、クエリ合体が来たら DSU 一択に近い。

#### DSU（Python）

→ [solutions/python/04/dsu/](../solutions/python/04/dsu/) / [solutions/go/04/dsu/](../solutions/go/04/dsu/)

```python
class DSU:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def unite(self, a: int, b: int) -> bool:
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True
```

```go
type DSU struct {
    parent []int
    size   []int
}

func (d *DSU) Find(x int) int {
    for d.parent[x] != x {
        d.parent[x] = d.parent[d.parent[x]]
        x = d.parent[x]
    }
    return x
}

func (d *DSU) Unite(a, b int) bool {
    a, b = d.Find(a), d.Find(b)
    if a == b {
        return false
    }
    if d.size[a] < d.size[b] {
        a, b = b, a
    }
    d.parent[b] = a
    d.size[a] += d.size[b]
    return true
}
```

#### クラスカル（最小全域木の準備）

→ [solutions/python/04/kruskal/](../solutions/python/04/kruskal/) / [solutions/go/04/kruskal/](../solutions/go/04/kruskal/)

**霊夢**: DSU、木の話とセットで出てくるよね？

**魔理沙**: **クラスカル法** は「辺を軽い順に見て、閉路を作らなければ採用」だ。採用できるかは **`unite` が成功するか** だけで判定する。本番の MST は [05.md](05.md) の 5.1 で仕上げるが、水色ではここまで押さえておけ。

```python
edges.sort(key=lambda e: e[2])
dsu = DSU(n)
total = 0
for u, v, w in edges:
    if dsu.unite(u, v):
        total += w
```

**霊夢**: `size` 配列、何に使うの？

**魔理沙**: 根の `size[root]` が **そのグループの頂点数** だ。同じグループのペア数は `size * (size - 1) / 2`（ABC177 D 系）。合体時に `size` を足し合わせるのを忘れると WA になる。

## 4.2 最短経路

**霊夢**: [03.md](03.md) でダイクストラはやった。他に何があるの？

**魔理沙**: 水色では **3 種類** を使い分ける。共通の考え方は「距離配列 `dist` を更新し、まだ確定していない頂点から広げる」だ。

| 手法 | 条件 | 計算量 |
|------|------|--------|
| ダイクストラ | 非負辺 | O((V+E) log V) |
| 0-1 BFS | 辺コスト 0 または 1 | O(V+E) |
| ワーシャル | V ≤ 400 程度 | O(V^3) |

### 使い分けの目安

| 問題の様子 | 候補 |
|------------|------|
| 重み 0/1 のみ、テレポート 0・移動 1 など | 0-1 BFS |
| 全点対の最短、V が小さい | ワーシャル |
| 非負で 1 源点 | ダイクストラ（[03.md](03.md)） |
| 負辺あり | ベルマン・フォード（黄色以降） |

**霊夢**: 0-1 BFS、ダイクストラと何が違うの？

**魔理沙**: コスト 0 の辺は **deque の先頭**、コスト 1 は **末尾** に入れる。ヒープが要らず **O(V+E)** だ。ダイクストラは一般の非負重み向け。

### つまずき

- **0-1 BFS**: コスト 0 を `appendleft`、1 を `append` と取り違えると WA。  
- **ワーシャル**: `dist[i][i]=0` の初期化、中間点 `k` のループが **外側** であること。  
- **オーバーフロー**: `INF = 10**18`（Python）/ `1<<60`（Go）を使う。

#### 0-1 BFS（deque）

→ [solutions/python/04/bfs01/](../solutions/python/04/bfs01/) / [solutions/go/04/bfs01/](../solutions/go/04/bfs01/)

```python
from collections import deque

def bfs01(g, start, n):
    INF = 10**18
    dist = [INF] * n
    dist[start] = 0
    dq = deque([start])
    while dq:
        v = dq.popleft()
        for to, cost in g[v]:
            nd = dist[v] + cost
            if nd < dist[to]:
                dist[to] = nd
                if cost == 0:
                    dq.appendleft(to)
                else:
                    dq.append(to)
    return dist
```

```go
func bfs01(g [][]struct{ to, cost int }, start, n int) []int {
    const INF = 1 << 60
    dist := make([]int, n)
    for i := range dist {
        dist[i] = INF
    }
    dist[start] = 0
    dq := []int{start}
    for head := 0; head < len(dq); head++ {
        v := dq[head]
        for _, e := range g[v] {
            nd := dist[v] + e.cost
            if nd < dist[e.to] {
                dist[e.to] = nd
                if e.cost == 0 {
                    dq = append([]int{e.to}, dq...)
                } else {
                    dq = append(dq, e.to)
                }
            }
        }
    }
    return dist
}
```

#### ワーシャル（全点対）

→ [solutions/python/04/floyd_warshall/](../solutions/python/04/floyd_warshall/) / [solutions/go/04/floyd_warshall/](../solutions/go/04/floyd_warshall/)

```python
def floyd(dist):
    n = len(dist)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
    return dist
```

**霊夢**: 三重ループ、k が一番外？

**魔理沙**: `k` を経由する最短を更新する順序だ。`dist[i][j]` の初期値は「辺があればその重み、なければ INF、自分自身は 0」だ。V=300 なら 27M 程度で、Python でも通ることが多い。

### 🖐️ abc184_e 相当（グリッド + テレポート = 0-1）

[abc184_e](https://atcoder.jp/contests/abc184/tasks/abc184_e) は **隣接移動コスト 0・同じ文字へテレポートコスト 1** の 0-1 BFS 定番。実装は [bfs01/](../solutions/python/04/bfs01/) の拡張で挑戦する。

## 4.3 累積和・二次元累積和

**霊夢**: 矩形の和、毎回四重ループは無理でしょ？

**魔理沙**: [02.md](02.md) の 1 次元累積和の拡張だ。**2 次元累積和** を前計算すれば、矩形 `[h1,w1]`〜`[h2,w2]`（含む）の和が **O(1)** で出せる。

### イメージ

```
s[i][j] = マス (1..i, 1..j) の矩形和（1-indexed）
```

構築は「上 + 左 − 左上 + 自分」の包含排除。クエリは大きい矩形から小さい矩形を引く。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 部分矩形の和、黒マスの個数、ヒストグラム | 2D 累積和 |
| 固定高さの横棒、最大面積 | 累積和 + 単調スタック（黄色） |
| 点だけ更新が多い | Fenwick / セグ木（4.5） |

### 計算量

| 処理 | 目安 |
|------|------|
| 構築 | O(HW) |
| 矩形 1 クエリ | O(1) |
| Q クエリ | O(HW + Q) |

#### 構築（1-indexed）

→ [solutions/python/04/prefix_sum_2d/](../solutions/python/04/prefix_sum_2d/) / [solutions/go/04/prefix_sum_2d/](../solutions/go/04/prefix_sum_2d/)

```python
def build_2d(a):
    h, w = len(a), len(a[0])
    s = [[0] * (w + 1) for _ in range(h + 1)]
    for i in range(1, h + 1):
        for j in range(1, w + 1):
            s[i][j] = s[i - 1][j] + s[i][j - 1] - s[i - 1][j - 1] + a[i - 1][j - 1]
    return s

def rect_sum(s, h1, w1, h2, w2):
    return s[h2][w2] - s[h1 - 1][w2] - s[h2][w1 - 1] + s[h1 - 1][w1 - 1]
```

```go
func build2D(a [][]int) [][]int {
    h, w := len(a), len(a[0])
    s := make([][]int, h+1)
    for i := range s {
        s[i] = make([]int, w+1)
    }
    for i := 1; i <= h; i++ {
        for j := 1; j <= w; j++ {
            s[i][j] = s[i-1][j] + s[i][j-1] - s[i-1][j-1] + a[i-1][j-1]
        }
    }
    return s
}

func rectSum(s [][]int, h1, w1, h2, w2 int) int {
    return s[h2][w2] - s[h1-1][w2] - s[h2][w1-1] + s[h1-1][w1-1]
}
```

**霊夢**: 1-indexed なのが、毎回つまずく……

**魔理沙**: `s[0][*]=s[*][0]=0` のガード行を足すと式がきれいになる。座標が 0-indexed なら **入力の (i,j) を +1 してから** `rect_sum` に渡す。紙に小さい例を書いてからコードにする癖をつけろ。

**霊夢**:  inclusive / exclusive の取り違えが怖い。

**魔理沙**: 本書の `rect_sum` は **両端含む（inclusive）** だ。`[h1,w1]` から `[h2,w2]` まで全部足すイメージで、`h1-1` 行・`w1-1` 列の外側を引く。

## 4.4 DP の応用

**霊夢**: ナップサックの次は何？

**魔理沙**: [03.md](03.md) のナップサック・LCS 入門の先だ。水色では **区間 DP・木 DP・bitmask DP** の 3 つが頻出だ。どれも「状態の持ち方」が問題ごとに違うので、**骨格をテンプレ化** しておく。

| 種類 | 状態の例 | 典型キーワード |
|------|----------|----------------|
| 区間 DP | `dp[l][r]` | 連続区間をまとめる、合体コスト |
| 木 DP | `dp[v]`（部分木） | 木、根からの値、部分木のサイズ |
| bitmask DP | `dp[mask][i]` | 訪問済み集合、順序付き巡回 |

### 計算量の目安

| 種類 | 目安 |
|------|------|
| 区間 DP | O(N^3)（長さ × 分割位置） |
| 木 DP | O(N)（各辺 1 回） |
| bitmask DP | O(N^2 · 2^N)（N ≤ 20 程度） |

### つまずき

- **区間 DP**: ループは **区間の長さ** の外側、`l` の内側、`k` で分割。`r = l + length - 1` の off-by-one。  
- **木 DP**: `parent` を渡し忘れると逆流する。再帰深度 → `setrecursionlimit`（[00.md](00.md)）。  
- **bitmask DP**: スタートを `dp[1][0]=0`（頂点 0 から）など、初期マスクを問題に合わせる。

### 区間 DP（例: 石の合体）

`dp[l][r]` = 区間 `[l,r]` の最適値。長さで増やす。

→ [solutions/python/04/dp_interval/](../solutions/python/04/dp_interval/) / [solutions/go/04/dp_interval/](../solutions/go/04/dp_interval/)

```python
def merge_stones(a):
    n = len(a)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            dp[l][r] = min(
                dp[l][k] + dp[k + 1][r] for k in range(l, r)
            ) + sum(a[l : r + 1])
    return dp[0][n - 1]
```

**霊夢**: `length` で回すの、なんか気持ち悪い……

**魔理沙**: 短い区間から埋めないと長い区間の値が未定義になる。**長さ 2 → 3 → … → n** の順が正しい。内側の `k` は「最後に合体する境界」だと思え。

### 木 DP（部分木の値）

→ [solutions/python/04/dp_tree/](../solutions/python/04/dp_tree/) / [solutions/go/04/dp_tree/](../solutions/go/04/dp_tree/)

```python
import sys

sys.setrecursionlimit(10**7)

def dfs(v, parent, g, dp):
    dp[v] = 1  # 例: 部分木のサイズ
    for to in g[v]:
        if to == parent:
            continue
        dfs(to, v, g, dp)
        dp[v] += dp[to]
```

**霊夢**: 木 DP、DFS と同じ感じ？

**魔理沙**: 根から DFS し、子の結果を使って親を更新する。**部分木の情報だけ** が子から親に渡ればよい（サイズ、和、白黒の可否など）。Euler Tour + セグ木に発展する問題もある（黄色以降）。

### bitmask DP（小さな N）

`dp[mask][i]` = 訪問済み `mask`、現在 `i`。TSP 入門。

→ [solutions/python/04/dp_bitmask/](../solutions/python/04/dp_bitmask/) / [solutions/go/04/dp_bitmask/](../solutions/go/04/dp_bitmask/)

```python
def tsp(dist, n):
    INF = 10**18
    dp = [[INF] * n for _ in range(1 << n)]
    dp[1][0] = 0
    for mask in range(1 << n):
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            for j in range(n):
                if mask >> j & 1:
                    continue
                nmask = mask | (1 << j)
                dp[nmask][j] = min(dp[nmask][j], dp[mask][i] + dist[i][j])
    full = (1 << n) - 1
    return min(dp[full][i] for i in range(n))
```

**霊夢**: TSP、N=20 くらいまで？

**魔理沙**: `2^N · N^2` が限界目安だ。N が 12 なら余裕、18 ならギリギリ、20 超は別手法（Held-Karp の定数倍や枝刈り）を探す。水色 E 問題の **「N が小さい」** は bitmask を疑うサインだ。

## 4.5 セグメントツリー・Fenwick（入門）

**霊夢**: 区間和を更新し続ける問題って、累積和じゃ足りないの？

**魔理沙**: [02.md](02.md) の累積和は **配列が固定** のとき最強だ。要素が **何度も変わる** と、区間和クエリのたびに作り直すのは遅い。**点更新 + 区間和** が繰り返されるときは **Fenwick（BIT）** か **セグメントツリー** を使う。

| 構造 | できること（入門） | 実装のしやすさ |
|------|-------------------|----------------|
| Fenwick | 点更新・区間和 | ◎ 短い |
| セグメントツリー | 点更新・区間和（拡張しやすい） | △ やや長い |

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 点を更新、区間の和・最大 | Fenwick / セグ木 |
| 区間に +v、区間の和 | lazy セグ木（[05.md](05.md) 5.3） |
| 逆順に見る、自分より小さい個数 | Fenwick + 座標圧縮 |

### 計算量

| 操作 | Fenwick / セグ木（入門） |
|------|--------------------------|
| 点更新 | O(log N) |
| 区間和 | O(log N) |

**霊夢**: Fenwick、`i & -i` が魔法みたい……

**魔理沙**: 最下位の 1 ビットで「担当範囲の幅」が決まる。暗記でよいが、**1-indexed** とセットで覚えろ。0-indexed の配列 `a[i]` を更新するときは `add(i+1, delta)` だ。

#### Fenwick（Python）

→ [solutions/python/04/fenwick/](../solutions/python/04/fenwick/) / [solutions/go/04/fenwick/](../solutions/go/04/fenwick/)

```python
class Fenwick:
    def __init__(self, n: int) -> None:
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i: int, x: int) -> None:
        while i <= self.n:
            self.bit[i] += x
            i += i & -i

    def sum(self, i: int) -> int:
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l: int, r: int) -> int:
        return self.sum(r) - self.sum(l - 1)
```

```go
type Fenwick struct {
    n   int
    bit []int
}

func (f *Fenwick) Add(i, x int) {
    for i <= f.n {
        f.bit[i] += x
        i += i & -i
    }
}

func (f *Fenwick) Sum(i int) int {
    s := 0
    for i > 0 {
        s += f.bit[i]
        i -= i & -i
    }
    return s
}

func (f *Fenwick) RangeSum(l, r int) int {
    return f.Sum(r) - f.Sum(l-1)
}
```

#### セグメントツリー（区間和・一点更新）

→ [solutions/python/04/segtree/](../solutions/python/04/segtree/) / [solutions/go/04/segtree/](../solutions/go/04/segtree/)

```python
class SegTree:
    def __init__(self, data):
        n = 1
        while n < len(data):
            n <<= 1
        self.n = n
        self.seg = [0] * (2 * n)
        for i, v in enumerate(data):
            self.seg[n + i] = v
        for i in range(n - 1, 0, -1):
            self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]

    def update(self, i, x):
        i += self.n
        self.seg[i] = x
        while i > 1:
            i >>= 1
            self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]

    def query(self, l, r):
        l += self.n
        r += self.n
        res = 0
        while l < r:
            if l & 1:
                res += self.seg[l]
                l += 1
            if r & 1:
                r -= 1
                res += self.seg[r]
            l >>= 1
            r >>= 1
        return res
```

**霊夢**: lazy propagation は？

**魔理沙**: 区間更新が必要になったら [05.md](05.md) で扱う。水色では **一点更新・区間和** までで十分だ。

## 4.6 スライディングウィンドウ・尺取り

**霊夢**: 部分列で条件を満たす longest / shortest、どう探すの？

**魔理沙**: **尺取り法（two pointers）** だ。右端 `right` を進め、条件を破したら左端 `left` を進める。**各要素が left に入るのは高々 1 回** なので全体 O(N) になる。

### 手順（「合計 ≤ K」の個数）

1. `right` を 0 から n-1 まで進める  
2. `sum` に `a[right]` を足す  
3. `sum > K` の間、`left` を進めて `sum` から引く  
4. この時点で `[left, right]` を終端とする部分列はすべて条件 OK → `right - left + 1` を答えに加算  

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 部分列、連続、合計・個数の条件 | 尺取り |
| 最短の長さ（条件を満たす最小） | 尺取り（満たしたら left を進める） |
| ソート済み配列のペア | 尺取り or 二分 |

[03.md](03.md) の deque ウィンドウと似ているが、尺取りは **可変長** の連続部分列が多い。

→ [solutions/python/04/two_pointers/](../solutions/python/04/two_pointers/) / [solutions/go/04/two_pointers/](../solutions/go/04/two_pointers/)

「**合計が K 以下** の部分列の個数」を数える例。

```python
def count_subarray_le_k(xs, k):
    n = len(xs)
    ans = 0
    left = 0
    s = 0
    for right in range(n):
        s += xs[right]
        while s > k and left <= right:
            s -= xs[left]
            left += 1
        ans += right - left + 1
    return ans
```

```go
ans, left, sum := 0, 0, 0
for right := 0; right < n; right++ {
    sum += xs[right]
    for sum > k && left <= right {
        sum -= xs[left]
        left++
    }
    ans += right - left + 1
}
```

**魔理沙**: 「最短の長さ」を求める問題では、条件を満たしたら左を進めるパターンも多い。文面で **最大化か最小化か** を確認しろ。

## 4.7 数学：逆元・フェルマ

**霊夢**: nCr mod、割り算ってどうするの？

**魔理沙**: mod 世界では **割り算 = 逆元を掛ける** だ。mod が素数 `p` のとき、**逆元** `a^{-1}` は `a^{p-2} mod p`（フェルマの小定理）。[03.md](03.md) のパスカル三角より、**大量の nCr** が欲しいときは **階乗 + 逆元テーブル** が定番だ。

### 手順（nCr 高速）

1. `fac[i] = i! mod p` を前計算  
2. `inv[n] = fac[n]^{p-2} mod p`（フェルマ）  
3. `inv[i-1] = inv[i] * i mod p` で逆順に逆階乗  
4. `nCr = fac[n] * inv[r] * inv[n-r] mod p`  

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 組み合わせ、nCr、mod 998244353 | 階乗 + 逆元 |
| 割り算、期待値 mod | 逆元 |
| mod が素数でない | 拡張ユークリッド |

### つまずき

- **0! = 1** を忘れる  
- **`r > n` は 0** を返す  
- **フェルマは p が素数** のときだけ（998244353 は OK）

→ [solutions/python/04/modinv/](../solutions/python/04/modinv/) / [solutions/go/04/modinv/](../solutions/go/04/modinv/)

```python
MOD = 998244353

def mod_pow(a, e, mod=MOD):
    res = 1
    while e:
        if e & 1:
            res = res * a % mod
        a = a * a % mod
        e >>= 1
    return res

def prepare_fac(n, mod=MOD):
    fac = [1] * (n + 1)
    inv = [1] * (n + 1)
    for i in range(1, n + 1):
        fac[i] = fac[i - 1] * i % mod
    inv[n] = mod_pow(fac[n], mod - 2, mod)
    for i in range(n, 0, -1):
        inv[i - 1] = inv[i] * i % mod
    return fac, inv

def ncr(n, r, fac, inv, mod=MOD):
    if r < 0 or r > n:
        return 0
    return fac[n] * inv[r] % mod * inv[n - r] % mod
```

```go
const MOD = 998244353

func modPow(a, e int) int {
    res := 1
    for e > 0 {
        if e&1 == 1 {
            res = res * a % MOD
        }
        a = a * a % MOD
        e >>= 1
    }
    return res
}

func ncr(n, r int, fac, inv []int) int {
    if r < 0 || r > n {
        return 0
    }
    return fac[n] * inv[r] % MOD * inv[n-r] % MOD
}
```

**霊夢**: mod が素数じゃないときは？

**魔理沙**: 拡張ユークリッドで逆元を求める。水色では **998244353** 前提で十分なことが多い。

## 4.8 二分グラフ・マッチング入門

**霊夢**: 2 色に分けられるか、ってグラフの問題？

**魔理沙**: **二分グラフ** は頂点を 2 つの集合に分け、**すべての辺が集合をまたぐ** グラフだ。判定は BFS/DFS で「色 0/1 を交互に塗る」。隣が同じ色になったら **矛盾 → No**。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 2 色塗り、隣が異なる、偶数長サイクル | 二分グラフ判定 |
| マッチング、割当、ペアリング | 貪欲 / 増路 DFS / フロー（[05.md](05.md)） |
| 奇数サイクル | 二分グラフではない |

### 計算量

| 処理 | 目安 |
|------|------|
| 判定 | O(V+E) |

[03.md](03.md) の BFS と同じキューだが、状態に **色** が増えるだけだ。

→ [solutions/python/04/bipartite/](../solutions/python/04/bipartite/) / [solutions/go/04/bipartite/](../solutions/go/04/bipartite/)

```python
from collections import deque

def is_bipartite(g, n):
    color = [-1] * n
    for s in range(n):
        if color[s] != -1:
            continue
        color[s] = 0
        q = deque([s])
        while q:
            v = q.popleft()
            for to in g[v]:
                if color[to] == -1:
                    color[to] = color[v] ^ 1
                    q.append(to)
                elif color[to] == color[v]:
                    return False
    return True
```

```go
func isBipartite(g [][]int, n int) bool {
    color := make([]int, n)
    for i := range color {
        color[i] = -1
    }
    for s := 0; s < n; s++ {
        if color[s] != -1 {
            continue
        }
        color[s] = 0
        q := []int{s}
        for head := 0; head < len(q); head++ {
            v := q[head]
            for _, to := range g[v] {
                if color[to] == -1 {
                    color[to] = color[v] ^ 1
                    q = append(q, to)
                } else if color[to] == color[v] {
                    return false
                }
            }
        }
    }
    return true
}
```

**霊夢**: 非連結グラフは？

**魔理沙**: 未着色の頂点をスタートに BFS を **繰り返す**（上の `for s` ループ）。1 成分だけ見て終わると WA だ。

**マッチング入門**: 水色 ARC B では **貪欲** や **DFS で増路** の簡単版が出る。本格の容量・最小カットは [05.md](05.md) のフロー（5.4）へ。
