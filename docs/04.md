## 4.1 最短経路

**霊夢**: [03.md](03.md) でダイクストラはやった。他に何があるの？

**魔理沙**: 水色では **3 種類** を使い分ける。共通の考え方は「距離配列 `dist` を更新し、まだ確定していない頂点から広げる」だ。

| 手法 | 条件 | 計算量 |
|------|------|--------|
| ダイクストラ | 非負辺 | O((V+E) log V) |
| 0-1 BFS | 辺コスト 0 または 1 | O(V+E) |
| ワーシャル | V ≤ 400 程度 | O(V^3) |

### 使い分けの目安

| 問題の様子 | 候補 |
|------------|------|
| 重み 0/1 のみ、テレポート 0・移動 1 など | 0-1 BFS |
| 全点対の最短、V が小さい | ワーシャル |
| 非負で 1 源点 | ダイクストラ（[03.md](03.md)） |
| 負辺あり | ベルマン・フォード（黄色以降） |

**霊夢**: 0-1 BFS、ダイクストラと何が違うの？

**魔理沙**: コスト 0 の辺は **deque の先頭**、コスト 1 は **末尾** に入れる。ヒープが要らず **O(V+E)** だ。ダイクストラは一般の非負重み向け。

### つまずき

- **0-1 BFS**: コスト 0 を `appendleft`、1 を `append` と取り違えると WA。  
- **ワーシャル**: `dist[i][i]=0` の初期化、中間点 `k` のループが **外側** であること。  
- **オーバーフロー**: `INF = 10**18`（Python）/ `1<<60`（Go）を使う。

#### 0-1 BFS（deque）

→ [solutions/python/04/bfs01/](../solutions/python/04/bfs01/) / [solutions/go/04/bfs01/](../solutions/go/04/bfs01/)

```python
from collections import deque

def bfs01(g, start, n):
    INF = 10**18
    dist = [INF] * n
    dist[start] = 0
    dq = deque([start])
    while dq:
        v = dq.popleft()
        for to, cost in g[v]:
            nd = dist[v] + cost
            if nd < dist[to]:
                dist[to] = nd
                if cost == 0:
                    dq.appendleft(to)
                else:
                    dq.append(to)
    return dist
```

```go
func bfs01(g [][]struct{ to, cost int }, start, n int) []int {
    const INF = 1 << 60
    dist := make([]int, n)
    for i := range dist {
        dist[i] = INF
    }
    dist[start] = 0
    // deque を 2 本のスライスで表す: front は末尾が先頭（コスト 0 を積む）、back は普通のキュー（コスト 1）
    front := []int{start}
    back := []int{}
    for len(front) > 0 || len(back) > 0 {
        var v int
        if len(front) > 0 {
            v = front[len(front)-1]
            front = front[:len(front)-1]
        } else {
            v = back[0]
            back = back[1:]
        }
        for _, e := range g[v] {
            nd := dist[v] + e.cost
            if nd < dist[e.to] {
                dist[e.to] = nd
                if e.cost == 0 {
                    front = append(front, e.to)
                } else {
                    back = append(back, e.to)
                }
            }
        }
    }
    return dist
}
```

#### ワーシャル（全点対）

→ [solutions/python/04/floyd_warshall/](../solutions/python/04/floyd_warshall/) / [solutions/go/04/floyd_warshall/](../solutions/go/04/floyd_warshall/)

```python
def floyd(dist):
    n = len(dist)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
    return dist
```

**霊夢**: 三重ループ、k が一番外？

**魔理沙**: `k` を経由する最短を更新する順序だ。`dist[i][j]` の初期値は「辺があればその重み、なければ INF、自分自身は 0」だ。V=300 なら 27M 程度で、Python でも通ることが多い。

### 🖐️ abc184_e（グリッド + テレポート）

[abc184_e](https://atcoder.jp/contests/abc184/tasks/abc184_e) は、隣のマスへの移動も、同じ文字のマスへのテレポートも **どちらも 1 秒**。コストが全部 1 なので **普通の BFS** で解ける。

**霊夢**: 同じ文字のマスが何万個もあったら、テレポート先を毎回全部見るのは遅くない？

**魔理沙**: そこが要点だ。ある文字のテレポートを **一度使ったら、その文字の行き先リストを空にする**。BFS では最初に使ったときが一番早いので、2 回目以降は調べても距離が縮まらないからな。これで各マスを見るのが O(1) 回になり、全体 O(HW) で済む。グリッド BFS は [solutions/python/03/grid_bfs/](../solutions/python/03/grid_bfs/) を土台にしろ。

## 4.2 二次元累積和・いもす法

**霊夢**: 矩形の和、毎回四重ループは無理でしょ？

**魔理沙**: [02.md](02.md) の 2.5 でやった 1 次元累積和の拡張だ（1 次元の復習はそちらで）。**2 次元累積和** を前計算すれば、矩形 `[h1,w1]`〜`[h2,w2]`（含む）の和が **O(1)** で出せる。

### イメージ

```
s[i][j] = マス (1..i, 1..j) の矩形和（1-indexed）
```

構築は「上 + 左 − 左上 + 自分」の包含排除。クエリは大きい矩形から小さい矩形を引く。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 部分矩形の和、黒マスの個数、ヒストグラム | 2D 累積和 |
| 固定高さの横棒、最大面積 | 累積和 + 単調スタック（黄色） |
| 点だけ更新が多い | Fenwick / セグ木（4.5） |

### 計算量

| 処理 | 目安 |
|------|------|
| 構築 | O(HW) |
| 矩形 1 クエリ | O(1) |
| Q クエリ | O(HW + Q) |

#### 構築（1-indexed）

→ [solutions/python/04/prefix_sum_2d/](../solutions/python/04/prefix_sum_2d/) / [solutions/go/04/prefix_sum_2d/](../solutions/go/04/prefix_sum_2d/)

```python
def build_2d(a):
    h, w = len(a), len(a[0])
    s = [[0] * (w + 1) for _ in range(h + 1)]
    for i in range(1, h + 1):
        for j in range(1, w + 1):
            s[i][j] = s[i - 1][j] + s[i][j - 1] - s[i - 1][j - 1] + a[i - 1][j - 1]
    return s

def rect_sum(s, h1, w1, h2, w2):
    return s[h2][w2] - s[h1 - 1][w2] - s[h2][w1 - 1] + s[h1 - 1][w1 - 1]
```

```go
func build2D(a [][]int) [][]int {
    h, w := len(a), len(a[0])
    s := make([][]int, h+1)
    for i := range s {
        s[i] = make([]int, w+1)
    }
    for i := 1; i <= h; i++ {
        for j := 1; j <= w; j++ {
            s[i][j] = s[i-1][j] + s[i][j-1] - s[i-1][j-1] + a[i-1][j-1]
        }
    }
    return s
}

func rectSum(s [][]int, h1, w1, h2, w2 int) int {
    return s[h2][w2] - s[h1-1][w2] - s[h2][w1-1] + s[h1-1][w1-1]
}
```

**霊夢**: 1-indexed なのが、毎回つまずく……

**魔理沙**: `s[0][*]=s[*][0]=0` のガード行を足すと式がきれいになる。座標が 0-indexed なら **入力の (i,j) を +1 してから** `rect_sum` に渡す。紙に小さい例を書いてからコードにする癖をつけろ。

**霊夢**:  inclusive / exclusive の取り違えが怖い。

**魔理沙**: 本書の `rect_sum` は **両端含む（inclusive）** だ。`[h1,w1]` から `[h2,w2]` まで全部足すイメージで、`h1-1` 行・`w1-1` 列の外側を引く。

### 二次元いもす法（矩形にまとめて足す）

**霊夢**: 逆に「矩形の範囲に +1 を何回も足して、最後に各マスの値が知りたい」ときは？

**魔理沙**: それは **二次元いもす法** だ。[02.md](02.md) の 2.5 でやった 1 次元の差分配列（いもす法）を 2 方向に広げる。矩形 `[r1, r2) × [c1, c2)` に +1 するとき、**四隅に ±1 を置く** だけにして、最後に **横に累積 → 縦に累積** するとすべてのマスの値が出る。

| 置く場所 | 値 |
|----------|-----|
| 左上 `(r1, c1)` | +1 |
| 右上の外 `(r1, c2)` | −1 |
| 左下の外 `(r2, c1)` | −1 |
| 右下の外 `(r2, c2)` | +1 |

**霊夢**: 右下が +1 なのはなぜ？

**魔理沙**: 右上と左下の −1 が、右下の外側の領域で **2 回引かれる** からだ。1 回足し戻して打ち消す。2D 累積和の「左上を足し戻す」と同じ包含排除だ。

| 処理 | 計算量 |
|------|--------|
| 矩形 N 個の登録 | O(N)（四隅に書くだけ） |
| 最後の累積 | O(HW) |
| 全体 | O(N + HW)（素朴に塗ると O(N × HW)） |

→ [solutions/python/04/imos_2d/](../solutions/python/04/imos_2d/) / [solutions/go/04/imos_2d/](../solutions/go/04/imos_2d/)

```python
import sys

def main() -> None:
    input = sys.stdin.readline
    h, w, n = map(int, input().split())
    # 差分は 1 マス大きく取る（右端・下端の +1 が溢れないように）
    d = [[0] * (w + 1) for _ in range(h + 1)]
    for _ in range(n):
        # 矩形 [r1, r2) × [c1, c2) に +1（0-indexed、右端・下端は含まない）
        r1, c1, r2, c2 = map(int, input().split())
        d[r1][c1] += 1
        d[r1][c2] -= 1
        d[r2][c1] -= 1
        d[r2][c2] += 1
    # 横方向に累積 → 縦方向に累積
    for i in range(h + 1):
        for j in range(1, w + 1):
            d[i][j] += d[i][j - 1]
    for i in range(1, h + 1):
        for j in range(w + 1):
            d[i][j] += d[i - 1][j]
    for i in range(h):
        print(*d[i][:w])

if __name__ == "__main__":
    main()
```

```go
// 横方向に累積 → 縦方向に累積
for i := 0; i <= h; i++ {
	for j := 1; j <= w; j++ {
		d[i][j] += d[i][j-1]

}
for i := 1; i <= h; i++ {
	for j := 0; j <= w; j++ {
```

## 4.3 DP の応用

**霊夢**: ナップサックの次は何？

**魔理沙**: [03.md](03.md) のナップサック・LCS 入門の先だ。水色では **区間 DP・木 DP・bitmask DP** の 3 つが頻出だ。どれも「状態の持ち方」が問題ごとに違うので、**骨格をテンプレ化** しておく。

| 種類 | 状態の例 | 典型キーワード |
|------|----------|----------------|
| 区間 DP | `dp[l][r]` | 連続区間をまとめる、合体コスト |
| 木 DP | `dp[v]`（部分木） | 木、根からの値、部分木のサイズ |
| bitmask DP | `dp[mask][i]` | 訪問済み集合、順序付き巡回 |

### 計算量の目安

| 種類 | 目安 |
|------|------|
| 区間 DP | O(N^3)（長さ × 分割位置） |
| 木 DP | O(N)（各辺 1 回） |
| bitmask DP | O(N^2 · 2^N)（N ≤ 20 程度） |

### つまずき

- **区間 DP**: ループは **区間の長さ** の外側、`l` の内側、`k` で分割。`r = l + length - 1` の off-by-one。  
- **木 DP**: `parent` を渡し忘れると逆流する。再帰深度 → `setrecursionlimit`（[00.md](00.md)）。  
- **bitmask DP**: スタートを `dp[1][0]=0`（頂点 0 から）など、初期マスクを問題に合わせる。

### 区間 DP（例: 石の合体）

`dp[l][r]` = 区間 `[l,r]` の最適値。長さで増やす。

→ [solutions/python/04/dp_interval/](../solutions/python/04/dp_interval/) / [solutions/go/04/dp_interval/](../solutions/go/04/dp_interval/)

```python
def merge_stones(a):
    n = len(a)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            dp[l][r] = min(
                dp[l][k] + dp[k + 1][r] for k in range(l, r)
            ) + sum(a[l : r + 1])
    return dp[0][n - 1]
```

**霊夢**: `length` で回すの、なんか気持ち悪い……

**魔理沙**: 短い区間から埋めないと長い区間の値が未定義になる。**長さ 2 → 3 → … → n** の順が正しい。内側の `k` は「最後に合体する境界」だと思え。

### 木 DP（部分木の値）

→ [solutions/python/04/dp_tree/](../solutions/python/04/dp_tree/) / [solutions/go/04/dp_tree/](../solutions/go/04/dp_tree/)

```python
import sys

sys.setrecursionlimit(10**7)

def dfs(v, parent, g, dp):
    dp[v] = 1  # 例: 部分木のサイズ
    for to in g[v]:
        if to == parent:
            continue
        dfs(to, v, g, dp)
        dp[v] += dp[to]
```

**霊夢**: 木 DP、DFS と同じ感じ？

**魔理沙**: 根から DFS し、子の結果を使って親を更新する。**部分木の情報だけ** が子から親に渡ればよい（サイズ、和、白黒の可否など）。Euler Tour + セグ木に発展する問題もある（黄色以降）。

### bitmask DP（小さな N）

`dp[mask][i]` = 訪問済み `mask`、現在 `i`。TSP 入門。

→ [solutions/python/04/dp_bitmask/](../solutions/python/04/dp_bitmask/) / [solutions/go/04/dp_bitmask/](../solutions/go/04/dp_bitmask/)

```python
def tsp(dist, n):
    INF = 10**18
    dp = [[INF] * n for _ in range(1 << n)]
    dp[1][0] = 0
    for mask in range(1 << n):
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            for j in range(n):
                if mask >> j & 1:
                    continue
                nmask = mask | (1 << j)
                dp[nmask][j] = min(dp[nmask][j], dp[mask][i] + dist[i][j])
    full = (1 << n) - 1
    return min(dp[full][i] for i in range(n))
```

**霊夢**: TSP、N=20 くらいまで？

**魔理沙**: `2^N · N^2` が限界目安だ。N が 12 なら余裕、18 ならギリギリ、20 超は別手法（Held-Karp の定数倍や枝刈り）を探す。水色 E 問題の **「N が小さい」** は bitmask を疑うサインだ。

## 4.4 桁 DP

**霊夢**: 「1 以上 K 以下の整数のうち、条件を満たすものはいくつ？」で K が 10^18 とか 10^10000 だと、全部調べられないよね。

**魔理沙**: そこで **桁 DP** だ。数を 1 個ずつ見るのではなく、**上の桁から 1 桁ずつ数字を決めていく** 過程を DP にする。状態に「ここまでの桁で K と同じか、もう小さいか」を持つのがポイントだ。

**霊夢**: 「K と同じか、もう小さいか」？

**魔理沙**: K = 352 で考えろ。百の位に 3 を置いたら、十の位は **5 以下** しか置けない（352 を超えるかもしれないから）。でも百の位に 2 を置いたら、その時点で 352 より小さいことが確定するので、残りの桁は **0〜9 を自由に** 置ける。この「まだ K に張り付いているか」を **tight フラグ**（smaller フラグとも呼ぶ）で持つ。

### 状態と遷移

| 状態 | 意味 |
|------|------|
| 何桁目まで決めたか | 上から i 桁 |
| tight | 1: ここまで K と完全一致 / 0: すでに K より小さい |
| 問題ごとの値 | 例: 桁和 mod D、0 以外の数字の個数 |

1. `dp[tight=1][初期値] = 1` から始める（まだ何も置いていない）  
2. 各桁で、置ける数字の上限は **tight なら K のその桁、そうでなければ 9**  
3. tight で、置いた数字が上限と等しいときだけ、次も tight のまま  
4. 最後の桁まで進んだら、tight=0 と tight=1 の両方を合計する（K 自身も含めるため）  
5. **0 を数えていないか** 確認する（「1 以上」の問題なら必要に応じて引く）

### いつ使うか

| 問題文のヒント | 方針 |
|----------------|------|
| 「K 以下の整数で〜を満たすもの」、K ≤ 10^18 や桁数で与えられる | 桁 DP |
| 「各桁の和」「0 でない桁の個数」「特定の数字を含む」 | 桁 DP の状態に入れる |
| 「L 以上 R 以下」 | f(R) − f(L−1) の 2 回に分ける |
| K が小さい（≤ 10^6） | 全探索で十分 |

### 計算量

- O(桁数 × 2 × 状態数 × 10)。K が 10^10000 で状態数 100 でも 10^7 程度  

### つまずき

| 症状 | 原因の例 |
|------|----------|
| 1 ずれる | 0 を数えている、または K 自身（最後の tight=1）を足し忘れ |
| 答えが大きすぎる | tight=1 のときも 0〜9 を全部置いている |
| K を整数で読んで桁が取れない | K は **文字列** として読み、1 文字ずつ処理する |

#### 桁和が D の倍数になる数を数える

→ [solutions/python/04/digit_dp/](../solutions/python/04/digit_dp/) / [solutions/go/04/digit_dp/](../solutions/go/04/digit_dp/)

```python
MOD = 10**9 + 7

def count_digit_sum_multiple(k: str, d: int) -> int:
    """1 以上 K 以下で、各桁の和が D の倍数になる整数の個数（mod 1e9+7）"""
    # dp[tight][r]: 上の桁から決めてきて、桁和 mod D が r の個数
    #   tight=1: ここまで K と完全に一致（次の桁は K の桁以下しか置けない）
    #   tight=0: すでに K より小さい（次の桁は 0〜9 を自由に置ける）
    dp = [[0] * d for _ in range(2)]
    dp[1][0] = 1
    for ch in k:
        x = int(ch)
        ndp = [[0] * d for _ in range(2)]
        for tight in range(2):
            for r in range(d):
                cur = dp[tight][r]
                if cur == 0:
                    continue
                limit = x if tight else 9
                for digit in range(limit + 1):
                    nt = 1 if (tight and digit == limit) else 0
                    nr = (r + digit) % d
                    ndp[nt][nr] = (ndp[nt][nr] + cur) % MOD
        dp = ndp
    # 0 も「桁和 0」で数えてしまっているので 1 引く
    return (dp[0][0] + dp[1][0] - 1) % MOD
```

```go
const mod = 1_000_000_007

// countDigitSumMultiple は 1 以上 K 以下で、各桁の和が D の倍数になる整数の個数を返す。
func countDigitSumMultiple(k string, d int) int {
	// dp[tight][r]: 上の桁から決めてきて、桁和 mod D が r の個数
	//   tight=1: ここまで K と完全に一致 / tight=0: すでに K より小さい
	newTable := func() [2][]int { return [2][]int{make([]int, d), make([]int, d)} }
	dp := newTable()
	dp[1][0] = 1
	for _, ch := range k {
		x := int(ch - '0')
		ndp := newTable()
		for tight := 0; tight < 2; tight++ {
			for r := 0; r < d; r++ {
				cur := dp[tight][r]
				if cur == 0 {
					continue
				}
				limit := 9
				if tight == 1 {
					limit = x
				}
				for digit := 0; digit <= limit; digit++ {
					nt := 0
					if tight == 1 && digit == limit {
						nt = 1
					}
					nr := (r + digit) % d
					ndp[nt][nr] = (ndp[nt][nr] + cur) % mod
				}
			}
		}
		dp = ndp
	}
	// 0 も「桁和 0」で数えてしまっているので 1 引く
	return (dp[0][0] + dp[1][0] - 1 + mod) % mod
}
```

**魔理沙**: そうだ。「何を状態に持てば、残りの桁の数え方が決まるか」を考えるのは [03.md](03.md) の DP と同じだ。桁和なら mod、0 でない桁の個数ならその個数を状態に足す。

## 4.5 セグメントツリー・Fenwick（入門）

**霊夢**: 区間和を更新し続ける問題って、累積和じゃ足りないの？

**魔理沙**: [02.md](02.md) の累積和は **配列が固定** のとき最強だ。要素が **何度も変わる** と、区間和クエリのたびに作り直すのは遅い。**点更新 + 区間和** が繰り返されるときは **Fenwick（BIT）** か **セグメントツリー** を使う。

| 構造 | できること（入門） | 実装のしやすさ |
|------|-------------------|----------------|
| Fenwick | 点更新・区間和 | ◎ 短い |
| セグメントツリー | 点更新・区間和（拡張しやすい） | △ やや長い |

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 点を更新、区間の和・最大 | Fenwick / セグ木 |
| 区間に +v、区間の和 | lazy セグ木（[05.md](05.md) 5.3） |
| 逆順に見る、自分より小さい個数 | Fenwick + 座標圧縮 |

### 計算量

| 操作 | Fenwick / セグ木（入門） |
|------|--------------------------|
| 点更新 | O(log N) |
| 区間和 | O(log N) |

**霊夢**: Fenwick、`i & -i` が魔法みたい……

**魔理沙**: 最下位の 1 ビットで「担当範囲の幅」が決まる。暗記でよいが、**1-indexed** とセットで覚えろ。0-indexed の配列 `a[i]` を更新するときは `add(i+1, delta)` だ。

```python
class Fenwick:
    def __init__(self, n: int) -> None:
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i: int, x: int) -> None:
        while i <= self.n:
            self.bit[i] += x
            i += i & -i

    def sum(self, i: int) -> int:
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l: int, r: int) -> int:
        return self.sum(r) - self.sum(l - 1)
```

```python
class SegTree:
    def __init__(self, data):
        n = 1
        while n < len(data):
            n <<= 1
        self.n = n
        self.seg = [0] * (2 * n)
        for i, v in enumerate(data):
            self.seg[n + i] = v
        for i in range(n - 1, 0, -1):
            self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]

    def update(self, i, x):
        i += self.n
        self.seg[i] = x
        while i > 1:
            i >>= 1
            self.seg[i] = self.seg[2 * i] + self.seg[2 * i + 1]

    def query(self, l, r):
        l += self.n
        r += self.n
        res = 0
        while l < r:
            if l & 1:
                res += self.seg[l]
                l += 1
            if r & 1:
                r -= 1
                res += self.seg[r]
            l >>= 1
            r >>= 1
        return res
```

## 4.6 スライディングウィンドウ・尺取り

**霊夢**: 部分列で条件を満たす longest / shortest、どう探すの？

**魔理沙**: **尺取り法（two pointers）** だ。右端 `right` を進め、条件を破したら左端 `left` を進める。**各要素が left に入るのは高々 1 回** なので全体 O(N) になる。

### 手順（「合計 ≤ K」の個数）

1. `right` を 0 から n-1 まで進める  
2. `sum` に `a[right]` を足す  
3. `sum > K` の間、`left` を進めて `sum` から引く  
4. この時点で `[left, right]` を終端とする部分列はすべて条件 OK → `right - left + 1` を答えに加算  

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 部分列、連続、合計・個数の条件 | 尺取り |
| 最短の長さ（条件を満たす最小） | 尺取り（満たしたら left を進める） |
| ソート済み配列のペア | 尺取り or 二分 |

[03.md](03.md) の deque ウィンドウと似ているが、尺取りは **可変長** の連続部分列が多い。

→ [solutions/python/04/two_pointers/](../solutions/python/04/two_pointers/) / [solutions/go/04/two_pointers/](../solutions/go/04/two_pointers/)

## 4.7 数学：逆元・フェルマ

**霊夢**: nCr mod、割り算ってどうするの？

**魔理沙**: mod 世界では **割り算 = 逆元を掛ける** だ。mod が素数 `p` のとき、**逆元** `a^{-1}` は `a^{p-2} mod p`（フェルマの小定理）。[03.md](03.md) のパスカル三角より、**大量の nCr** が欲しいときは **階乗 + 逆元テーブル** が定番だ。

### 手順（nCr 高速）

1. `fac[i] = i! mod p` を前計算  
2. `inv[n] = fac[n]^{p-2} mod p`（フェルマ）  
3. `inv[i-1] = inv[i] * i mod p` で逆順に逆階乗  
4. `nCr = fac[n] * inv[r] * inv[n-r] mod p`  

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 組み合わせ、nCr、mod 998244353 | 階乗 + 逆元 |
| 割り算、期待値 mod | 逆元 |
| mod が素数でない | 拡張ユークリッド |

### つまずき

- **0! = 1** を忘れる  
- **`r > n` は 0** を返す  
- **フェルマは p が素数** のときだけ（998244353 は OK）

→ [solutions/python/04/modinv/](../solutions/python/04/modinv/) / [solutions/go/04/modinv/](../solutions/go/04/modinv/)

```python
MOD = 998244353

def mod_pow(a, e, mod=MOD):
    res = 1
    while e:
        if e & 1:
            res = res * a % mod
        a = a * a % mod
        e >>= 1
    return res

def prepare_fac(n, mod=MOD):
    fac = [1] * (n + 1)
    inv = [1] * (n + 1)
    for i in range(1, n + 1):
        fac[i] = fac[i - 1] * i % mod
    inv[n] = mod_pow(fac[n], mod - 2, mod)
    for i in range(n, 0, -1):
        inv[i - 1] = inv[i] * i % mod
    return fac, inv

def ncr(n, r, fac, inv, mod=MOD):
    if r < 0 or r > n:
        return 0
    return fac[n] * inv[r] % mod * inv[n - r] % mod
```

## 4.8 二分グラフ判定

**霊夢**: 2 色に分けられるか、ってグラフの問題？

**魔理沙**: **二分グラフ** は頂点を 2 つの集合に分け、**すべての辺が集合をまたぐ** グラフだ。判定は BFS/DFS で「色 0/1 を交互に塗る」。隣が同じ色になったら **矛盾 → No**。

### 問題文のキーワード

| キーワード | 候補 |
|------------|------|
| 2 色塗り、隣が異なる、偶数長サイクル | 二分グラフ判定 |
| マッチング、割当、ペアリング | 二部マッチング（[05.md](05.md) 5.4） |
| 奇数サイクル | 二分グラフではない |

### 計算量

| 処理 | 目安 |
|------|------|
| 判定 | O(V+E) |

[03.md](03.md) の BFS と同じキューだが、状態に **色** が増えるだけだ。

→ [solutions/python/04/bipartite/](../solutions/python/04/bipartite/) / [solutions/go/04/bipartite/](../solutions/go/04/bipartite/)

```python
from collections import deque

def is_bipartite(g, n):
    color = [-1] * n
    for s in range(n):
        if color[s] != -1:
            continue
        color[s] = 0
        q = deque([s])
        while q:
            v = q.popleft()
            for to in g[v]:
                if color[to] == -1:
                    color[to] = color[v] ^ 1
                    q.append(to)
                elif color[to] == color[v]:
                    return False
    return True
```

```go
func isBipartite(g [][]int, n int) bool {
    color := make([]int, n)
    for i := range color {
        color[i] = -1
    }
    for s := 0; s < n; s++ {
        if color[s] != -1 {
            continue
        }
        color[s] = 0
        q := []int{s}
        for head := 0; head < len(q); head++ {
            v := q[head]
            for _, to := range g[v] {
                if color[to] == -1 {
                    color[to] = color[v] ^ 1
                    q = append(q, to)
                } else if color[to] == color[v] {
                    return false
                }
            }
        }
    }
    return true
}
```

**魔理沙**: 未着色の頂点をスタートに BFS を **繰り返す**（上の `for s` ループ）。1 成分だけ見て終わると WA だ。

**霊夢**: 2 色に分けた後、「左右でペアを作る」問題もあるよね？

**魔理沙**: それは **二部マッチング** だ。最大流で解くのが基本なので、[05.md](05.md) の 5.4（フロー）でまとめて扱う。水色では「2 色に塗れるか」を確実に判定できれば十分だ。

### 🖐️ abc199_d（3 色塗りの数え上げ）

[abc199_d](https://atcoder.jp/contests/abc199/tasks/abc199_d) は、N ≤ 20 頂点のグラフを **3 色** で塗り分ける方法の数を求める。2 色なら二分グラフ判定で一意に決まるが、3 色は決まらないので **全探索** する。

## 4.9 期待値の線形性・主客転倒

**霊夢**: 「すべての区間について和を求めて、その合計を出せ」って、区間は N² 個あるから無理じゃない？

**魔理沙**: 見方を逆にする。「区間ごとに和を計算する」のではなく、**「要素 a[i] は何個の区間に含まれるか」** を数えて、`a[i] × 個数` を足す。これを **主客転倒**（寄与で数える、とも言う）と呼ぶ。

**霊夢**: a[i] を含む区間の数？

**魔理沙**: 左端は 0〜i の **i+1 通り**、右端は i〜N−1 の **N−i 通り** だから、`(i+1) × (N−i)` 個だ。全体は O(N) で済む。

### 主客転倒の手順

1. 素朴な「全部の組み合わせ（区間・ペア・部分集合）について〇〇を足す」式を書く  
2. 足し算の順番を入れ替えて、**「各要素について、それが寄与する回数」** の和に書き直す  
3. 寄与する回数を **数式やソート・累積和** で O(1)〜O(log N) で出す  

**霊夢**: ペアの差の絶対値の合計も同じ？

**魔理沙**: そうだ。**ソートすれば** 絶対値が外れる。小さい順に並べたとき、`b[i]` は左の i 個との差では「大きい方」として +b[i]、右の N−1−i 個との差では「小さい方」として −b[i] で数えられる。

### 期待値の線形性

**霊夢**: 期待値の問題も似てるって聞いたよ。

**魔理沙**: **期待値の線形性**: 「X = X₁ + X₂ + … + Xₙ なら E[X] = E[X₁] + E[X₂] + … + E[Xₙ]」。しかも **X₁ たちが独立でなくても成り立つ**。だから複雑な量の期待値も、「各要素が条件を満たせば 1、そうでなければ 0」という指示変数に分けると、**各確率を足すだけ** になる。

**霊夢**: 例えば？

**魔理沙**: 1〜N をランダムに並べたとき、「それまでの最大値を更新する位置」は何個あると期待できるか。位置 i が更新になるのは「先頭 i 個の最大値が i 番目にある」ときで、確率は **1/i**。だから期待値は 1 + 1/2 + … + 1/N だ。全順列を考える必要はない。

### いつ使うか

| 問題文のヒント | 方針 |
|----------------|------|
| 「すべての区間 / ペア / 部分集合について〜の総和」 | 主客転倒（各要素の寄与） |
| 「|a_i − a_j| の総和」 | ソート + 寄与 |
| 「xor の総和」 | ビットごとに 0 と 1 の個数で寄与を数える |
| 「〜の個数の期待値」 | 指示変数に分けて期待値の線形性 |
| 期待値で状態が遷移する（何回で終わるか） | 期待値 DP（[05.md](05.md) 5.8） |

### 計算量

- 区間の和の総和: O(N)（素朴は O(N²)〜O(N³)）  
- ペアの差の総和: O(N log N)（ソート）  

### つまずき

- 寄与の個数を **1 ずらす**（左端 i+1 通り・右端 N−i 通りを小さい例で確かめる）  
- 総和が大きくなりすぎる（Go は int64 の範囲、mod 指定があれば都度 mod）  
- 期待値を「確率の積」で計算しようとする（線形性は **和** で使う）  

→ [solutions/python/04/contribution/](../solutions/python/04/contribution/) / [solutions/go/04/contribution/](../solutions/go/04/contribution/)

```python
def sum_of_all_subarray_sums(a: list) -> int:
    """すべての連続部分列の和の総和。a[i] が何個の区間に含まれるかで数える"""
    n = len(a)
    total = 0
    for i, x in enumerate(a):
        left = i + 1  # 区間の左端の選び方: 0..i
        right = n - i  # 区間の右端の選び方: i..n-1
        total += x * left * right
    return total

def sum_of_pair_diffs(a: list) -> int:
    """i < j のすべてのペアの |a_i - a_j| の総和。ソートして寄与で数える"""
    b = sorted(a)
    total = 0
    for i, x in enumerate(b):
        # x は自分より左の i 個に対して「大きい方」として +x、
        # 右の n-1-i 個に対して「小さい方」として -x される
        total += x * i - x * (len(b) - 1 - i)
    return total

    位置 i（1-indexed）が更新になる確率は 1/i なので、期待値の線形性で和を取る"""
    return sum(1 / i for i in range(1, n + 1))
```

**初 ARC A の心構え**

- ABC と違い、**典型アルゴリズムを当てはめるだけ** では解けないことが多い。まずは **手で小さい例** を試して規則を探す。  
- 実装は短いことが多い。考察に時間を使ってよい。
